# 命名規則

この教材([scratchpad-ibmi-learning-from-zero](https://github.com/bluemoonjp/scratchpad-ibmi-learning-from-zero)の[付録E](https://github.com/bluemoonjp/scratchpad-ibmi-learning-from-zero/blob/main/docs/appendix/e-naming.md))から引き継いだ、汎用的な部分だけを抜き出した短縮版です。自分のプロジェクトに合わせて書き換えてください。

## オブジェクト名(6文字)

演習・学習用の教材とは違い、実プロジェクトでは「部・レッスン番号」ではなく、プロジェクト固有の業務領域コードを使うのが一般的です。次のような形を土台にできます。

`<種別1文字><業務領域コード2〜3文字><連番>`

- 種別: `C`=CL、`R`=RPG III(固定形式)、`V`=固定形式 RPG IV、`F`=`**FREE`、`Q`=SQLRPGLE、`M`=モジュール、`D`=DSPF、`P`=PRTF、`K`=コマンド、`B`=バインダー・ソース
- 業務領域コード: プロジェクトごとに決める(例: 得意先=`TK`、受注=`JU`、在庫=`ZA`)
- 対になる画面・CL・プログラムは、同じ番号を共有して種別だけを変える(例: `TK0100`(RPG)と `TK0100D`(DSPF)は対)

RPG III(固定形式)を使う場合、フィールド名・変数名・DS名・ラベル名は**6文字以内**という制約があることを忘れないでください。

## ライブラリー・ソース物理ファイルの役割分担

自分の環境の権限に応じて決めてください。開発・本番・バックアップを分けるかどうか、分ける場合の名前をどうするかは、この教材の `<USER>1`/`<USER>2`/`<USER>B` の3分割を出発点にしても、1つのライブラリーで完結させてもかまいません。

## 共通で使うツール・道具

複数の場面で繰り返し使うツール(バッチの雛形、環境切り替えコマンド等)は、番号ではなく役割を表す名前を付けます。プロジェクト全体で使う道具に共通の接頭辞(例: 社名やシステム名の略称)を決めておくと、他のオブジェクトと見分けやすくなります。
