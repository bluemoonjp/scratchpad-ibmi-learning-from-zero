# 第7部 ILE とモジュール化

## この部の目標

第6部で身につけた RPG IV `**FREE` を土台に、**ILE(統合言語環境)のモジュール化の考え方**を身につけます。モジュール(`*MODULE`)→プログラム(`*PGM`)/サービス・プログラム(`*SRVPGM`)という2段階ビルド、バインディング・ディレクトリーによる `*LIBL` 経由の参照解決、バインダー・ソースによる署名(シグネチャー)管理、活性化グループ、ILE CL からのサービス・プログラム呼び出しまでを、実際にロジックを共有オブジェクトへ括り出しながら学びます。

## 前提となる状態

第6部までの内容(06-15 のチェックポイントまで)が済んでいること。

## 道具

5250(コンパイル・実行・確認)。SSH(`CPYFRMSTMF` でのソース取り込み)、SQL(`STRSQL`、`DSPSRVPGM` の裏付けや `TXCKM` 登録)も使います。

## この部で自分たちが作る道具

新規の道具はありません。`TXCHECK`(`*CMD` 形)を、この部のチェックポイント(07-05)で実行します。

## 観測方法

`DSPJOBLOG`(ジョブ・ログへのメッセージ)、`DSPPGM DETAIL(*MODULE)`・`DSPSRVPGM`(モジュール構成・エクスポート一覧の確認)、`WRKSPLF`(07-05 の印字結果)。

## この部で扱わないこと

- RPG IV の新しい文法そのもの(第6部で習得済みの前提)。
- 現代的な開発環境(VS Code でのデバッグ等、第8部)。

## 同時接続数

基本は5250×1です。SSHでのソース取り込みは都度接続し直す形で行います(02-04・05-01と同じやり方、各レッスンの案内文を参照)。

## 容量の予算

この部で作るオブジェクトはいずれも小さなモジュール・サービス・プログラムで、容量を気にする場面はありません。

## 出力が違うとき

- **印刷結果が `WRKSPLF` に出てこない**: 07-05 の印字結果も、第6部と同じ理由(検証ハーネスの非対話SSHジョブでは印刷装置ファイルが実スプール・ファイルにならない)で、学習者自身の5250対話セッションでは通常どおり `WRKSPLF` で確認できます。
- **`MCH4431`(Program signature violation)が出た**: 07-03 が教える核心の現象です。`EXPORT(*ALL)` のサービス・プログラムでエクスポートする手続きの数を変えたのに、既存のクライアントを再コンパイルしていないと起こります。バインダー・ソースへ切り替えるか、影響を受けるクライアントを再コンパイルしてください。
- **07-05を実施した場合の注意**: 07-05の演習は共有テーブル `ZAIKOM` の中身を書き換えます。演習後は必ず `TXRESET` を実行してください。
