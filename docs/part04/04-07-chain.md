# 04-07 キーで読む

> 所要時間: 60分 / 前提レッスン: 04-06 / 目標番号: 3 / 観測方法: `WRKSPLF` / 道具: 5250(SEU)/ 同時接続数: 5250×1 / 作る・変えるオブジェクト: `<USER>1/R0407A` / DBVER: 1 / 依存するプローブ: なし / PTF 依存: なし / 容量の目安: わずか

## ゴール

- `CHAIN` で、キー(`TOKCD` など)を指定して1件だけ読める。
- `CHAIN` が「見つからなかった」ことを、結果標識で判定できる。
- 外部記述・キー付きファイルを、CHAIN で使うための F 仕様書の書き方が分かる。

## なぜ学ぶか

04-06 の `READ` は、ファイルの先頭から順番に読むしかありませんでした。**「得意先コード `C00001` の得意先だけが欲しい」というときに、先頭から1件ずつ `READ` して比較するのは非効率です。** `CHAIN` を使えば、キーを指定して**1件だけ**を直接読めます。CL の `RCVF` にはこの機能がなく(03-09)、これが RPG ならではの強みです。

## 新出

- `CHAIN`(キーを指定して1件読む)
- F 仕様書の**レコード・アドレス型**(31桁目。`CHAIN` でキー・アクセスするなら `K` を指定する)
- 「見つからなかった」の判定(結果標識は `HI` の位置)

## 説明

### F 仕様書: レコード・アドレス型に K を指定する

```text
FTOKUIM  IF  E           K        DISK
```

04-06 の F 仕様書との違いは、**31桁目に `K`** が入っている点だけです。**これがないと、`CHAIN` の Factor 1(キー値)が「相対レコード番号」として解釈されようとしてエラーになります。** `TOKUIM` は DDS で `K TOKCD` とキーが定義された外部記述ファイルなので、`K` を指定することで「そのキーで検索する」という意味になります。

### CHAIN

```text
C           'C00001'  CHAINTOKUIM               99
```

Factor 1 に**探したいキーの値**(ここでは得意先コード `'C00001'`)、Factor 2 に**ファイル名**を書きます。**結果標識は `HI` の位置(54〜55桁目)** に書き、**見つからなかったときに ON** になります(`READ` の `EQ` とは違う位置なので注意してください)。

### 見つからなかったときの処理

```text
C   99                MOVEL'NOTFOUND'TOKNM
```

**`CHAIN` が失敗した場合、レコードのフィールド(`TOKNM` など)は書き換わりません**(04-03 で学んだ「古いデータが残る」のと同じ理屈です)。そのため、**結果標識(この例では `99`)を必ず確認し、失敗した場合の処理を自分で書く**必要があります。このコードでは、見つからなかったときだけ `TOKNM` に `'NOTFOUND'` を入れています。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0407A`(`RPG`)を作る。
2. 次を、桁位置に注意しながら入力する(`src/qrpgsrc/r0407s.rpg` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0407A - CHAIN: look up one customer by key (TOKCD).
        H
        FTOKUIM  IF  E           K        DISK
        FQSYSPRT O   F     132            PRINTER
        C           'C00001'  CHAINTOKUIM               99
        C   99                MOVEL'NOTFOUND'TOKNM
        C                     EXCPT
        C                     SETON                     LR
        OQSYSPRT E
        O                         TOKCD      6
        O                                    8 '  '
        O                         TOKNM     38
   ```

3. コンパイルして `CALL PGM(R0407A)` を実行し、`WRKSPLF` で `C00001  ACME TRADING CO` と印刷されることを確認する。

## 演習

1. `'C00001'` を、存在しない得意先コード `'C99999'` に変えて再コンパイル・実行し、**`TOKCD` が空白のまま、`TOKNM` に `NOTFOUND` とだけ印刷される**ことを確認してください(`CHAIN` が失敗すると `TOKCD` も書き換わらないため空白のままである点に注目してください)。
2. `'C00001'` を `'C00003'` に変えて、`BLUE OCEAN INC` が印刷されることを確認してください。
3. 04-05 で学んだ `IFxx` を使って、`99` を条件標識として使う代わりに `IF *IN99 = *ON`(あるいは同等の書き方)で分岐できないか、`F4` プロンプトで確認しながら試してみてください(できなくても構いません。次の部で改めて扱います)。

## 実機メモ

- 確認日: 2026-09-25。**`R0407A` を `<USER>2` で実際に `CRTRPGPGM` でコンパイル(Highest Severity 00)し、実行して `C00001  ACME TRADING CO` が正しく印刷されることを確認した。** 存在しないキー(`C99999`)で試したところ、`TOKNM` に `NOTFOUND` とだけ印刷され(`TOKCD` は空白のまま)、`CHAIN` 失敗時の結果標識(`HI`)とフィールドの挙動も確認できた。
  - F仕様書の31桁目(レコード・アドレス型)に `K` が必要なことは、当初 `KEYLEN`(29〜30桁目)を試して `QRG2008` になり、次に `K` なしで `CHAIN` すると `QRG7055`(Factor 1 が相対レコード番号として不正)になったことから特定した。
  - `CHAIN` の結果標識は `HI`(54〜55桁目)で、`READ` の `EQ` とは異なる位置であることも実機で確認した(`EQ` を指定すると `QRG5127`/`QRG5130` になった)。
