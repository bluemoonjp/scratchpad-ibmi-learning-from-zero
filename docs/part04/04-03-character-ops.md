## なぜ学ぶか

RPG III には `EVAL` がないため、文字列の組み立てや初期化も、決まった命令で行います。中でも `MOVE`・`MOVEL` は、**代入のようでいて代入ではありません。** 「結果フィールドの、書き換えなかった部分に古いデータが残る」という、初心者がまずハマる罠を、ここで実際に体験して身につけます。

## 新出

- `MOVE`(右詰めで転記)・`MOVEL`(左詰めで転記)
- `CLEAR`(フィールドを既定値に戻す。文字は空白、数値はゼロ)
- 図形定数: `*BLANKS`(空白)・`*ZEROS`(ゼロ)・`*HIVAL`(その型で表現できる最大値)・`*LOVAL`(最小値)
- `CAT`(連結)・`SUBST`(部分文字列の取り出し)・`SCAN`(検索)

## 説明

### MOVE と MOVEL は「詰め方」が違う

どちらも Factor 2 の内容を結果フィールドへ転記する命令ですが、**詰める向きが逆**です。

- `MOVEL`(MOVE Left): 結果フィールドの**左(高位、先頭)**から詰めます。Factor 2 が短ければ、**右側の余った部分は変わりません。**
- `MOVE`: 結果フィールドの**右(低位、末尾)**から詰めます。Factor 2 が短ければ、**左側の余った部分は変わりません。**

「変わりません」は「空白になる」ではなく、**その場所に前から入っていた値がそのまま残る**という意味です。これが、このレッスンの中心となる罠です。

### 罠: 古いデータが残る

結果フィールドを**初めて**使うときは、フィールドの中身はプログラム開始時からの空白(文字)またはゼロ(数値)なので、この罠には気づきません。危険なのは、**同じフィールドに、前より短い値を2回目以降に転記したとき**です。

```text
NAME2 に MOVEL 'JOHNSON'  → NAME2 = 'JOHNSON   '(10桁、右側3つは初期値の空白)
NAME2 に MOVEL 'AL'       → NAME2 = 'ALHNSON   '(左2桁だけ書き換わり、'HNSON' が残る!)
```

**対策は簡単です。転記の前に `CLEAR` でフィールドを空にしておけば、古いデータは残りません。**

### CLEAR

```text
C                     CLEARNAME3
```

**`CLEAR` の対象フィールドは、結果フィールド(43〜48桁目)ではなく Factor 2(33〜42桁目)に書きます。** `CLEAR` という命令コードはちょうど5文字(28〜32桁目)なので、続く `NAME3`(Factor 2)との間に空白が入らず、見た目には1つの単語のようにつながります(これは誤植ではなく、固定桁のRPG IIIでは普通のことです)。`NAME3` が文字フィールドなら空白に、数値フィールドならゼロになります。**`CLEAR` の対象は、すでにどこかで定義済みのフィールドでなければなりません**(`CLEAR` 自体には長さを指定する桁がありません)。

### 図形定数(figurative constant)

リテラル(`'ABC'` や `123` のような具体的な値)の代わりに使える、特別な予約語です。引用符を付けずに書きます。

| 図形定数 | 意味 |
|---|---|
| `*BLANKS` | 空白(文字フィールド用) |
| `*ZEROS` | ゼロ(数値フィールド用。文字フィールドに使うと `'0'` の並びになります) |
| `*HIVAL` | その型で表現できる最大の値(ソート時に「必ず一番後ろに来る」番兵値として使われます) |
| `*LOVAL` | その型で表現できる最小の値(「必ず一番前に来る」番兵値) |

`*BLANKS`/`*ZEROS` は `MOVE`/`MOVEL` の Factor 2 として使え、`CLEAR` の簡易な代わりになります。`*HIVAL`/`*LOVAL` は主に `COMP`(比較。04-04 で扱います)で、「最大値/最小値との比較」に使います。

### CAT・SUBST・SCAN(概要)

この3つは、複数のフィールド(Factor 1・Factor 2・結果フィールド)の桁位置の組み合わせがやや複雑です。**SEU で命令コードの欄に `CAT`・`SUBST`・`SCAN` と入力してから `F4` を押すと、その命令専用の入力プロンプト画面が出ます。** これを使えば、桁を数えて手で合わせる必要はありません(第4部の道具として、5250/PDM/SEU を選んだ理由の一つです)。

- **`CAT`**(連結): Factor 1 の文字列と Factor 2 の文字列をつなげ、結果フィールドに入れます。間に空白を何文字入れるかを指定できます。
- **`SUBST`**(部分文字列): Factor 2 の文字列から、指定した位置・長さの一部分を取り出し、結果フィールドに入れます。
- **`SCAN`**: Factor 1 の文字列が、Factor 2 の文字列の中に含まれるかを検索し、見つかった位置(見つからなければ `0`)を結果フィールドに入れます。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0403A`(`RPG`)を作る。
2. 次を、桁位置に注意しながら入力する(`src/qrpgsrc/r0403s.rpg` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0403A - MOVE/MOVEL leave old data behind; CLEAR first to avoid it.
        H
        FQSYSPRT O   F     132            PRINTER
        C                     MOVEL'JOHNSON' NAME1  10
        C                     MOVEL'JOHNSON' NAME2  10
        C                     MOVEL'AL'      NAME2
        C                     MOVE '123456'  CODE1   6
        C                     MOVE '123456'  CODE2   6
        C                     MOVE 'AB'      CODE2
        C                     MOVEL'XX'      NAME3  10
        C                     CLEARNAME3
        C                     MOVEL'BOB'     NAME3
        C                     EXCPT
        C                     SETON                     LR
        OQSYSPRT E
        O                                    2 'A='
        O                         NAME1     12
        O                                   16 '  B='
        O                         NAME2     26
        O                                   30 '  C='
        O                         CODE1     36
        O                                   40 '  D='
        O                         CODE2     46
        O                                   50 '  E='
        O                         NAME3     60
   ```

   **O 仕様書の1行目(`OQSYSPRT E`)には、ファイル名と出力タイプだけを書き、実際に出力するフィールドや定数は書きません。** フィールド・定数は、次の行以降(ファイル名の欄が空白の行)に1つずつ書きます(04-01・04-02 と同じ形です)。

   `A`=`NAME1`(`MOVEL` で初めて定義)、`B`=`NAME2`(`MOVEL` を2回。罠が起きる)、`C`=`CODE1`(`MOVE` で初めて定義)、`D`=`CODE2`(`MOVE` を2回。罠が起きる)、`E`=`NAME3`(`CLEAR` してから `MOVEL`。罠が起きない)です。

3. コンパイルして `CALL PGM(R0403A)` を実行し、`WRKSPLF` で次のように印刷されることを確認する(実機で確認済みの出力です)。

   ```text
   A=JOHNSON     B=ALHNSON     C=123456  D=1234AB  E=BOB
   ```

   **`B` が `ALHNSON` になっている**(`MOVEL 'AL'` で先頭2桁だけ書き換わり、`JOHNSON` の3〜7桁目 `HNSON` が残った)、**`D` が `1234AB` になっている**(`MOVE 'AB'` で末尾2桁だけ書き換わり、`123456` の1〜4桁目 `1234` が残った)、これが「古いデータが残る罠」です。**`E` は `BOB` だけで正しく埋まっています**(`CLEAR` してから `MOVEL` したため)。

## 演習

1. `NAME2`・`CODE2` への2回目の `MOVEL`/`MOVE` の**前**に `CLEAR` を1行ずつ追加し、再コンパイル・実行して、罠が起きなくなることを確認してください。
2. `CAT` を使って、`NAME1` に空白1個を挟んで文字列 `'SAN'` を連結した結果を、新しいフィールド `NAME5`(15桁)に入れて印刷してください。`F4` プロンプトを使って桁を確認しながら入力してください。
3. `SCAN` を使って、`NAME1` の中に `'SON'` という文字列が含まれるか検索し、見つかった位置を印刷してください。
