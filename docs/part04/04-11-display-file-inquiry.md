# 04-11 表示装置ファイルを手書きして照会画面を作る

## ゴール

- 表示装置ファイル(DSPF)を DDS で手書きできる。
- `EXFMT` で「書いてから読む」画面のやり取りを実装できる。
- `CHAIN` の結果を画面に表示し、見つからないときのメッセージも出せる。

## なぜ学ぶか

**ここまでのレッスンは、印刷(`PRINTER`)への出力だけでした。** 実際の業務では、画面で得意先コードを入力し、その場で名前を確認する「照会画面」が最も基本的なやり取りです。RPG III では、画面も DDS(`PRINTER`/`DISK` と同じ書き方の一種)で定義し、`EXFMT`(書いてから読む)という専用の命令でやり取りします。

## 新出

- DDS(表示装置ファイル)の桁位置(38桁目=使用法、39-44桁目=画面上の行・桁)
- ファンクション・キー(`CF03(03)`)
- F 仕様書16桁目 `F` + 15桁目 `C`(WORKSTN + `EXFMT` の必須の組み合わせ)
- `EXFMT`(書いてから読む)
- `*IN03`(標識を直接 Factor 1/Factor 2 に書く)

## 説明

### 画面の DDS を書く

```text
     A                                      DSPSIZ(24 80 *DS3)
     A          R INQFMT
     A                                      CF03(03)
     A                                  1  2'Customer code:'
     A            TOKCD          6A  I  1 17
     A                                  3  2'Name:'
     A            TOKNM         30A  O  3  8
     A                                  5  2'F3=Exit'
```

38桁目が使用法です。`I`(入力)は学習者が入力する欄、`O`(出力)はプログラムが表示するだけの欄です。39-41桁目が画面の行、42-44桁目が桁(横位置)です。`CF03(03)` は、`F3` キーが押されたときに標識03を ON にする、という宣言です(レコード様式の `R` 行の直後に単独行で書きます)。

**出力フィールドの長さは、参照元のフィールドと完全に一致させる必要があります。** `TOKUIM.TOKNM` は30文字なので、画面側も30文字にします(38文字にすると `QRG6033` でコンパイルが失敗します)。

### F 仕様書: WORKSTN + EXFMT には F 指定が必須

```text
FR0411A  CF  E                    WORKSTN
```

15桁目が `C`(組み合わせ、入力も出力もする)、**16桁目が `F`(完全手続き型)** です。**`EXFMT` を使う WORKSTN ファイルは、この `F` 指定が必須**です(空欄のままだと `QRG2096` でコンパイルが失敗します)。04-06〜04-10 で「順に読む DISK ファイル」に使ってきた `F` と同じ文字ですが、ここでは「`EXFMT` を使う組み合わせファイルの決まりごと」という別の理由によるものです。

### EXFMT で書いてから読む

```text
C           *IN03     DOWEQ*OFF
C                     EXFMTINQFMT
C  N03      TOKCD     CHAINTOKUIM               50
C  N03 50             MOVEL'NOTFOUND'TOKNM
C                     ENDDO
```

`EXFMT`(Factor2にレコード様式名)は、画面を表示してから、学習者が `Enter` を押すまで待ち、入力された内容を読み込みます。`CF03(03)` があるので、`*IN03` という標識が自動的に使えます(DDS 側で宣言した名前がそのまま RPG のフィールド・標識になります)。`DOWEQ` で `*IN03` が `*OFF` の間はループを繰り返し、`F3` が押されたら(`*IN03` が `*ON` になったら)ループを抜けます。

`CHAIN` で取得した `TOKUIM.TOKNM` は、**画面の `TOKNM`(同じ名前)に自動的に表示されます**。見つからなかったとき(標識50)は、`MOVEL` で `TOKNM` の中身を `'NOTFOUND'` に書き換えます(04-03 で学んだ技法の応用です)。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QDDSSRC)` で `R0411A`(`DSPF`)を作る。次を入力する(`src/qddssrc/r0411s.dspf` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
        A                                      DSPSIZ(24 80 *DS3)
        A          R INQFMT
        A                                      CF03(03)
        A                                  1  2'Customer code:'
        A            TOKCD          6A  I  1 17
        A                                  3  2'Name:'
        A            TOKNM         30A  O  3  8
        A                                  5  2'F3=Exit'
   ```

2. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0411A`(`RPG`)を作る。次を入力する(`src/qrpgsrc/r0411s.rpg` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0411A - TOKUIM inquiry screen (WORKSTN, EXFMT, F3=exit).
        H
        FR0411A  CF  E                    WORKSTN
        FTOKUIM  IF  E           K        DISK
        C           *IN03     DOWEQ*OFF
        C                     EXFMTINQFMT
        C  N03      TOKCD     CHAINTOKUIM               50
        C  N03 50             MOVEL'NOTFOUND'TOKNM
        C                     ENDDO
        C                     SETON                         LR
   ```

3. 両方をコンパイルする(`CRTDSPF`・`CRTRPGPGM`、いずれも Highest Severity 00 を確認)。
4. `CALL PGM(R0411A)` を実行し、実際の画面が出ることを確認する。`T00001` など `TOKUIM` に実在する得意先コードを入力して `Enter` を押し、名前が表示されることを確認する。存在しないコードで `NOTFOUND` が出ることも確認する。`F3` で終了することを確認する。

## 演習

1. 存在する得意先コードと存在しないコードを、それぞれ試してください。
2. 画面の見出し(`'Customer code:'` など)の位置や文言を変えて、再コンパイル・実行してみてください。

## 実機メモ

- 確認日: 2026-09-25。**DDS(表示装置ファイル)の桁位置(38桁目=使用法、39-41桁目=行、42-44桁目=桁)と、レコード様式レベルのファンクション・キー・キーワード(`CF03(03)`)を、実機で `CRTDSPF`(Highest Severity 00)により確認した。**
- **新知見: WORKSTN の組み合わせ(C)ファイルで `EXFMT` を使うには、F仕様書16桁目を `F`(完全手続き型)にする必要がある。** 空欄だと `QRG2096` でコンパイル失敗することを実機で確認した。RPG/400 Reference の `EXFMT` の説明とも一致する。
- **新知見: DDS の出力フィールドの長さは、外部記述ファイル側の同名フィールドと完全に一致させる必要がある。** `TOKUIM.TOKNM` の実際の長さ(30文字)と異なる長さ(38文字)で書いたところ `QRG6033` で失敗し、30文字に修正して解決した。
- `CHAIN` で取得したフィールドが、同じ名前の画面出力フィールドに自動的に表示されることを、実機コンパイルのクロス・リファレンス(`TOKNM` が入力側・出力側の両方で同じフィールドとして扱われていること)で確認した。
- **試して失敗したこと(未解決)**: DDS のフィールド・定数行を標識の ON/OFF で出し分ける「条件標識」の桁位置は、7桁目に標識番号を置く形を試したが `CPD7410`/`CPD7606`/`CPD5238` で失敗し、正しい桁位置を特定できなかった。今回は代わりに、RPG 側の `MOVEL`(04-03 で確認済みの技法)で出力フィールドの内容を直接書き換える方式で「見つからない」を表現し、この問題を回避した(優先度低として保留)。
- **検証範囲の限界**: `R0411A` は `CRTDSPF`・`CRTRPGPGM` のコンパイル確認(Highest Severity 00)までを、このセッションの SSH 経由の非対話バッチで実機確認した。**`EXFMT` を含む対話的な実行そのものは、実際の5250デバイスを必要とするため、この経路では検証できない**(`CALL` すると応答なくハングする)。実演・演習は、学習者自身が実際の5250セッションで実行して確認してください。
