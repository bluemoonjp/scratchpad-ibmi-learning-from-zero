# 04-06 外部記述ファイルを順に読む

> 所要時間: 75分(長め)/ 前提レッスン: 04-05 / 目標番号: 3 / 観測方法: `WRKSPLF` / 道具: 5250(SEU)/ 同時接続数: 5250×1 / 作る・変えるオブジェクト: `<USER>1/R0406A` / DBVER: 1 / 依存するプローブ: なし / PTF 依存: なし / 容量の目安: わずか

## ゴール

- 外部記述ファイル(DDS で定義済みのファイル)を、F 仕様書で入力用に宣言できる。
- `READ` でレコードを1件ずつ読み、EOF(ファイルの終わり)を検知できる。
- `GOTO`・`TAG` で、EOF まで読み続けるループを書ける。

## なぜ学ぶか

ここまでは、プログラムの中に値を直接書いてきました。**いよいよ、02-05 で作ったサンプル・データベース(`TOKUIM` など)を、RPG III から実際に読みます。** CL の `DCLF`/`RCVF`(03-09)と似た働きですが、RPG III では `READ` を使い、より細かく制御できます。

## 新出

- F 仕様書の入力ファイル宣言(全手続き方式・外部記述)
- `READ`(レコードを1件読む。EOF は結果標識で分かる)
- `GOTO`・`TAG`(指定した場所へ処理を移す。ループを書くのに使う)

## 説明

### F 仕様書: 入力ファイルの宣言

```text
FTOKUIM  IF  E                    DISK
```

15桁目の `I` はファイル・タイプ(入力)、16桁目の `F` は「全手続き方式」(Full procedural。`READ` を自分で書いて読む方式。04-10 で扱う「プライマリー・ファイル」との違いです)、19桁目の `E` は「外部記述」(DDS で定義済みのファイルという意味。フィールドの桁位置・型は DDS 側から自動的に取り込まれます)、装置は `DISK` です。

### READ と EOF

```text
C                     READ TOKUIM                   99
```

Factor 2 にファイル名、**結果標識は EQ の位置(58〜59桁目)** に書きます(`COMP` の EQ と同じ場所ですが、意味は「ファイルの終わりに達した」です)。**`READ` が成功している間は標識 `99` は OFF のまま、読むレコードがなくなると `99` が ON になります。**

### GOTO と TAG でループする

RPG III には(04-05 で学んだ `DOWxx` のような)ファイル読み込み専用のループ命令はありません。**`GOTO`(Factor 2 に行き先のラベル名)と `TAG`(Factor 1 にラベル名。行き先の印)を組み合わせて、自分でループを作ります。**

```text
C           LOOP      TAG
C                     READ TOKUIM                   99
C   99                GOTO ENDLP
C                     EXCPT
C                     GOTO LOOP
C           ENDLP     TAG
C                     SETON                     LR
```

1. `LOOP:` から始める。
2. `READ` で1件読む。
3. 標識 `99`(EOF)が ON なら(条件標識、04-04 で学んだ書き方)、`ENDLP` へ飛ぶ。
4. まだ続くなら、`EXCPT` で印刷し、`LOOP` に戻る。
5. `ENDLP:` で `SETON LR` して終了する。

**`GOTO`/`TAG` は、04-05 の構造化命令より前からある、古い書き方です。** ファイルの読み込みループでは今でもよく使われますが、それ以外の条件分岐には、できるだけ `IFxx`/`DOWxx` を使うようにしてください。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0406A`(`RPG`)を作る。
2. 次を、桁位置に注意しながら入力する(`src/qrpgsrc/r0406s.rpg` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0406A - read TOKUIM sequentially and print each customer.
        H
        FTOKUIM  IF  E                    DISK
        FQSYSPRT O   F     132            PRINTER
        C           LOOP      TAG
        C                     READ TOKUIM                   99
        C   99                GOTO ENDLP
        C                     EXCPT
        C                     GOTO LOOP
        C           ENDLP     TAG
        C                     SETON                     LR
        OQSYSPRT E
        O                         TOKCD      6
        O                                    8 '  '
        O                         TOKNM     38
   ```

3. コンパイルして `CALL PGM(R0406A)` を実行し、`WRKSPLF` で `TOKUIM` の6件が1件ずつ印刷されることを確認する(`C00001  ACME TRADING CO` のように、顧客コードと顧客名が並びます)。

## 出力が違うとき

- **`CPF4101`(`File TOKUIM in library *LIBL not found`)のようなメッセージが出た場合、または実行が固まったように見える(応答が返ってこない)場合**、`TOKUIM` があなたの実行環境の `*LIBL`(ライブラリー・リスト)に入っていない可能性があります。**この種のファイル・オープンの失敗は、RPG が自動的に照会メッセージ(応答待ちのメッセージ)を出す仕様になっており、5250 の対話画面では `C`(取り消し)で応答できますが、応答できない環境では止まったままになります。** `WRKLIBL` でライブラリー・リストを確認し、`ADDLIBLE <自分のユーザー名>1` を実行してから、もう一度 `CALL` してください。

## 実機メモ

- 確認日: 2026-09-25。**`R0406A` を `<USER>2` で実際に `CRTRPGPGM` でコンパイル(Highest Severity 00)し、実行して `TOKUIM` の6件すべて(`C00001 ACME TRADING CO` 〜 `C00006 RIVER SIDE SHOP`)が正しく印刷されることを確認した。** F 仕様書の入力ファイル宣言、`READ` の結果標識(EQ)、`GOTO`/`TAG` の Factor 配置(`TAG` は Factor 1、`GOTO` は Factor 2。`BEGSR`/`EXSR` と同じ使い分け)、すべて実機で確認済み。
- **検証の過程で、実行時に長時間応答がなくなる現象に遭遇した。** 原因は `CPF4101`(`TOKUIM` が `*LIBL` に見つからない)で、**RPG は暗黙のファイル・オープンが失敗すると、`MONMSG` や `*PSSR`(RPG のエラー処理サブルーチン)でも捕まえられない、専用の照会メッセージ(`RPG1216`)を出す**ことが分かった(`DSPJOB OPTION(*PGMSTK)`・`DSPJOBLOG` で該当ジョブを直接調べて特定した)。この照会に応答できない非対話ジョブでは、無期限に停止する。**検証は、コンパイルしたジョブとは別のジョブから `CALL` していたために `*LIBL` に `<USER>2` が入っておらず、この問題を踏んだ。** `ADDLIBLE` してから `CALL` する診断用のラッパーを使ったところ、正常に完走した。**学習者が5250の対話的セッションで、コンパイルと同じセッション内で `CALL` する分には(自分のライブラリーが通常 `*LIBL`/`*CURLIB` に含まれているため)、この問題は起きないと考えられるが、5250での確認はまだできていない。**
