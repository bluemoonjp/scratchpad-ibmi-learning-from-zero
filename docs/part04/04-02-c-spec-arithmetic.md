## なぜ学ぶか

RPG III には `EVAL` のような自由な代入式がありません。**計算は、決まった桁位置に決まった要素を置く「演算命令」で行います。** ここで C 仕様書の桁の意味と、基本的な算術命令を身につけます。

## 新出

- C 仕様書の桁割り当て(7〜59桁)
- `Z-ADD`(ゼロ加算。実質的な代入)
- `ADD`・`SUB`・`MULT`・`DIV`・`MVR`(剰余)
- 桁あふれ(結果フィールドの桁数を超えた部分は、警告なく消える)

## 説明

### C 仕様書の桁割り当て

| 桁 | 内容 |
|---|---|
| 7〜8 | 制御レベル(空白、`L1`〜`L9` など。第4部後半で使います) |
| 9〜17 | 条件標識(条件付きで実行する場合) |
| 18〜27 | Factor 1(1つ目の項) |
| 28〜32 | 命令コード(最大5文字) |
| 33〜42 | Factor 2(2つ目の項) |
| 43〜48 | 結果フィールド(6文字以内の名前) |
| 49〜51 | フィールドの長さ |
| 52 | 小数桁数 |
| 54〜59 | 結果標識(HI/LO/EQ) |

### Z-ADD と、フィールドの「その場宣言」

RPG III には D 仕様書(変数を先に宣言する仕組み)がありません。**結果フィールドに初めて長さ・小数桁数を指定した行が、そのフィールドの定義を兼ねます。** `Z-ADD`(ゼロ加算)は、「結果フィールドを一度ゼロにしてから、Factor 2 の値を加える」という命令で、実質的には代入として使います。

### 桁あふれは警告なく消える

計算結果が、結果フィールドの桁数に収まらない場合、**超えた桁は警告なく切り捨てられます。** これは、現代の言語の「オーバーフロー例外」とは大きく違う挙動です。桁数の見積もりを誤ると、静かに間違った値が生まれます。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0402A`(`RPG`)を作る。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0402A - C-spec columns and arithmetic (tax-inclusive price).
        H
        FQSYSPRT O   F     132            PRINTER
        C                     Z-ADD1580      PRICE   72
        C                     Z-ADD1.10      RATE    32
        C           PRICE     MULT RATE      TOTAL   92
        C                     EXCPT
        C                     SETON                     LR
        OQSYSPRT E
        O                         TOTAL 1   20
   ```

   `PRICE`(単価1580、小数2桁)に `RATE`(税率1.10)を掛けて `TOTAL`(9桁、小数2桁)に入れ、印刷します。`O` 仕様書の `1`(編集コード)は、カンマ区切りなどの見やすい表示形式を指定するものです(詳しくは04-08で扱います)。

2. コンパイルして `CALL PGM(R0402A)` を実行し、`WRKSPLF` で税込み金額(`1,738.00`。編集コード `1` によりカンマ区切りで印刷されます)が印刷されていることを確認する。

## 演習: 桁あふれを予想する

次のそれぞれについて、結果がどうなるか予想してから、実際に試してください(`TOTAL` の長さを変えて実験してください)。

1. `TOTAL` の長さを `4`(小数2桁のまま、整数部2桁)に縮めて、`1738.00` を計算するとどうなるか。
2. `PRICE` の値を `99999`(5桁)に変え、`TOTAL` の長さを `5`(小数0桁)にするとどうなるか。
3. `DIV` で割り算をした後、`MVR`(剰余)で余りを求める2行を追加し、`10 ÷ 3` の商と余りを確認する。
