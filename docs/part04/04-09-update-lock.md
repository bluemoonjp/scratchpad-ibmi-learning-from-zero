## なぜ学ぶか

**ここまでは読むだけでした。ここで初めて、データベースの中身を書き換えます。** 商品の在庫を、注文の数量だけ減らす「在庫引当」を題材にします。**複数の人が同時に同じ商品を注文するかもしれない**ので、読んでから書き込むまでの間に、他の処理が割り込まないようにする「ロック」の考え方も扱います。

## 新出

- `UPDAT`(`CHAIN`・`READ` で読んだレコードを書き換える。命令コードは5文字までなので `UPDATE` ではなく `UPDAT` と書く)
- F 仕様書15桁目のファイル・タイプ `U`(更新用)
- レコード・ロック(`CHAIN` で読むと、そのレコードは他からの更新を待たされる)

## 説明

### 更新用ファイルの宣言

```text
FZAIKOM  UF  E           K        DISK
```

15桁目が `U`(更新)になっている点が、これまでの `I`(入力専用)との違いです。**`U` で宣言したファイルを `CHAIN` すると、そのレコードは「ロック」されます**(他のジョブがそのレコードを同時に更新できないよう、読み取った側が優先権を持つ状態になります)。`UPDAT` で書き込むと、ロックは自動的に解放されます。

### UPDAT で書き換える

```text
C                     SUB  QTY       ZASU
C                     UPDATZAIKOR
```

`SUB`(04-05 の `ADD` と同じ書き方で、Factor 1 を省略すると「結果 = 結果 − Factor 2」になります)で `ZASU`(在庫数量)を減らしたあと、**`UPDAT`**(Factor 2 にレコード形式名 `ZAIKOR`)で、書き換えた内容をデータベースに反映します。`UPDAT` は、直前に `CHAIN` または `READ` で読んだレコードを対象にします。**`UPDAT` の前に必ず `CHAIN`(または `READ`)でそのレコードをロックしておく必要があります。**

### 在庫不足を先にチェックする

```text
C           ZASU      COMP QTY                    98
C   98                GOTO SHORT
```

**在庫数量が注文数量より少ない場合、そのまま引き算すると在庫がマイナスになってしまいます。** `COMP` の `LO`(56〜57桁目。Factor 1 が Factor 2 より小さいとき ON)を使い、**更新する前に**在庫が足りているかを確認します。足りなければ `SHORT` へ分岐し、`UPDAT` を実行しません。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QRPGSRC)` で `R0409A`(`RPG`)を作る。
2. 次を、桁位置に注意しながら入力する(`src/qrpgsrc/r0409s.rpg` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * R0409A - ZAHIK3: allocate stock for one product (UPDATE + lock).
        H
        FZAIKOM  UF  E           K        DISK
        FQSYSPRT O   F     132            PRINTER
        C                     MOVEL'P00001'  PROD    6
        C                     Z-ADD2         QTY     50
        C           PROD      CHAINZAIKOM               99
        C   99                GOTO NOTFND
        C           ZASU      COMP QTY                    98
        C   98                GOTO SHORT
        C                     SUB  QTY       ZASU
        C                     UPDATZAIKOR
        C                     MOVEL'OK'      MSG    10
        C                     GOTO ENDPGM
        C           SHORT     TAG
        C                     MOVEL'SHORT'   MSG
        C                     GOTO ENDPGM
        C           NOTFND    TAG
        C                     MOVEL'NOTFOUND'MSG
        C           ENDPGM    TAG
        C                     EXCPT
        C                     SETON                     LR
        OQSYSPRT E
        O                         PROD       6
        O                                    8 '  '
        O                         ZASU      15
        O                                   17 '  '
        O                         MSG       27
   ```

   商品 `P00001`(在庫45)から2個引き当てます。`CHAIN` で見つからなければ `NOTFOUND`、在庫が足りなければ `SHORT`、それ以外は `SUB`+`UPDAT` してから `OK` を表示します。

3. コンパイルして `CALL PGM(R0409A)` を実行し、`WRKSPLF` で `P00001  0000043  OK` と印刷されることを確認する(45−2=43)。`STRSQL` で `SELECT ZASU FROM ZAIKOM WHERE ZASHO='P00001'` を実行し、実際に43になっていることも確認してください。

## 演習

1. `Z-ADD2` を `Z-ADD999`(在庫より多い数)に変えて再コンパイル・実行し、`P00001  0000043  SHORT` と印刷される(**在庫は書き換わらない**)ことを確認してください。
2. `'P00001'` を存在しない商品コード `'P99999'` に変え、`NOTFOUND` になることを確認してください。
3. 演習の後、必ず `<自分のユーザー名>1/TXRESET` を実行し、在庫を元の45に戻してください(次のレッスン・他の演習に影響しないようにするためです)。

## 実機メモ

- 確認日: 2026-09-25。**`R0409A` を `<USER>2` で実際に `CRTRPGPGM` でコンパイル(Highest Severity 00)し、実行して次の両方のケースを確認した**: (1) 在庫が足りる場合(`QTY=2`)→ `P00001  0000043  OK`(45→43に正しく更新)。(2) 在庫が足りない場合(`QTY=999`)→ `P00001  0000043  SHORT`(**在庫は更新されない**、43のまま)。
- `UPDATE` という命令コードは、C仕様書の命令コード欄(28〜32桁目、5桁)に収まらないため、実際には **`UPDAT`**(5文字)と書く。これは実機コンパイルの過程で、桁がずれた状態でもたまたま正しく解釈された結果から気づき、明示的に `UPDAT` と書き直して再確認した。
- `COMP` の `LO` 標識(04-04 で桁位置を確認済み)を、更新前の在庫チェックに使えることも実機で確認した。
- 検証後は `TXRESET` でデータを在庫45の状態に戻し、以降のレッスン・演習に影響が出ないことを確認済み。
