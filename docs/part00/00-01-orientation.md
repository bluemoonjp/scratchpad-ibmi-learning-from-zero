## 完成形を先に見る

この教科書を最後まで進めると、次のようなことができるようになります。

架空の商社(得意先・商品・受注・受注明細・在庫を扱う小さな業務)を題材に、「得意先ごとの受注を調べる」という同じ用件を、道具を変えながら何度も実装します。

| 段階 | 形 | 使う技術 | 学ぶ部 |
|---|---|---|---|
| 1 | SQL で問い合わせる | STRSQL(対話式 SQL) | 第2部 |
| 2 | CL プログラムで表示する | CL の DCLF/RCVF | 第3部 |
| 3 | 帳票に印刷する | RPG III(固定形式) | 第4部 |
| 4 | 対話画面で照会する | RPG III + DDS 表示装置ファイル | 第4部 |
| 5 | RPG IV(固定形式)に変換する | CVTRPGSRC | 第6部 |
| 6 | 完全自由形式で書き直す | RPG IV `**FREE` | 第6部 |
| 7 | サブファイルで一覧表示する | RPG IV + DDS サブファイル | 第6部 |
| 8 | サービス・プログラムに分ける | ILE(モジュール分割) | 第7部 |
| 9 | JSON を返す API にする | SQL 外部プロシージャ | 第9部 |

最後のレッスン(09-04)では、次のような JSON が SQL 1 本で返ってくるところまで到達します。

```json
{
  "customer": "ACME TRADING CO",
  "orders": [
    { "orderNo": "J00001", "date": "2026-09-01", "total": 5560.00 },
    { "orderNo": "J00003", "date": "2026-09-05", "total": 9170.00 }
  ]

```

同じ業務を、道具を変えながら何度も実装する。これがこの教科書の一貫した進め方です。1回で完璧に理解する必要はありません。何度も同じ景色を、違う角度から見ることで身につきます。

## IBM i の全体像(Windows / Linux との比較)

IBM i を初めて触る人がまず戸惑うのは、「見慣れた道具がない」ことです。ここでは、比較先の仕組みも含めて説明します。

**すべてがオブジェクトである。** Windows や Linux では「ファイル」と「プログラム」は別の世界の話です(実行ファイルもファイルの一種ではありますが、OS がプログラムとして特別扱いするのはロード時です)。IBM i では、プログラム・ファイル・ライブラリー・メッセージ待ち行列など、扱うものすべてに「名前」「型」「置き場所(ライブラリー)」があり、統一的に「オブジェクト」と呼ばれます。`DSPOBJD`(オブジェクトの記述を表示する)という1つのコマンドで、プログラムもファイルもデータ域も同じように調べられるのはこのためです。

**データベースが OS に統合されている。** Windows や Linux では、データベース(MySQL や PostgreSQL など)は別途インストールするソフトウェアです。IBM i では Db2 for i が OS に統合されており、特別なインストール作業なしに、最初からテーブル(IBM i の用語では物理ファイル)を作って使えます。

**文字コードが違う。** Windows や Linux で標準的な文字コードは ASCII 系(UTF-8 等)ですが、IBM i は歴史的に EBCDIC という別系統の文字コードを使います。今回の学習環境である PUB400 は CCSID 273(ドイツ語圏向けの EBCDIC)を使っており、これが原因で特定の記号が化けることがあります(01-01 と 02-03 で詳しく扱います)。

**「ジョブ」という単位で動く。** Linux の「プロセス」に近い概念ですが、IBM i では対話式(画面を持つ)かバッチ(画面を持たない)かで扱いが変わり、ジョブごとにジョブ・ログ(実行記録)や、ライブラリー・リスト(探索対象のライブラリーの並び。`PATH` に近い概念)を持ちます(01-08 で扱います)。

**5250 という画面方式。** Windows や Linux の CUI ツールは、多くが「1行ずつ送って、1行ずつ返る」対話です(SSH のシェルなど)。5250 は「画面全体を一度に送って、Enter で画面全体を送り返す」方式です。慣れるまでは操作感が独特に感じられます(01-01 で扱います)。

## 学び方の型

各レッスンは、**説明 → 実演 → 同じ手順を対象を変えて繰り返す**、という順で進みます。「自分で探してみましょう」という課題は出しません。分からないことがあれば、そのレッスンの中で説明します。

新しく登場する概念やコマンドは、1レッスンにつき中核概念3つ・コマンド等6つまでに絞っています。「新出」として明記されているものが、そのレッスンで覚えるべきものです。それ以外は「読めればよい」もの(読解用)として区別されます。

## 確認IDと習熟度トラッカー

各レッスンには確認ID(例: `03-07-1`)が付いています。[`docs/progress-template.md`](../progress-template.md) をコピーして、自分の学習記録を作ってください。各確認IDについて、次の3段階で自己評価します。

1. 手順書を見ればできる
2. 見ずにできる
3. 別の対象に応用でき、日を空けてもできる

各部の最後にはチェックポイントがあり、そこで習熟度をまとめて確認します。
