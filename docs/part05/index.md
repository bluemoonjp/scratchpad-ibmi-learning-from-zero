# 第5部 RPG III を読む・直す(保守)

## この部の目標

自分で新しく書くのではなく、**他人が書いた(それも、標識だらけの古い)RPG III を読み、安全に手を入れられる**ようになります。第4部までで身につけた文法の知識を、実際の保守の現場でそのまま使います。

## 前提となる状態

`TXSTATUS` で確認してください。第2部の TXSETUP でサンプル・データベース(TOKUIM/JUCHUM/JUCHUD/ZAIKOM/TANTOM/JUCHUL1/TOKUIL1)が入っていること。05-01 で `TXLEGACY` を実行すると、この部の旧システム一式(`src/legacy/`)が投入されます。

## 道具

5250(PDM/SEU/STRDBG)。05-07 以降は SQL(ACS の「実行 SQL スクリプト」または `RUNSQL`)も使います。

## この部で自分たちが作る道具

`TXLEGACY`(旧システムの投入)。TXSNAP・TXMIGR は第2〜3部で作った道具の延長として、この部の改修レッスン(05-08・05-09)で使います。`TXCHECK`(オブジェクトの存在・型を機械的に確認する道具)は、この部のチェックポイント(05-13)で初めてコンパイル・使用します。

## 観測方法

`STRDBG` によるステップ実行、`DSPJOBLOG`、`WRKSPLF`。画面は画面そのものを見ます。

## この部で扱わないこと

- 自由形式で新しく書くこと(第6部)。
- サブファイル・配列・データ構造を**自分で設計して書く**こと(第4部同様、読むだけ)。
- ILE(モジュール・サービス・プログラム、第7部)。

## 同時接続数

基本は5250×1。05-13(チェックポイント)の一部演習では、移送元・移送先を確認するために5250×2を使うことがあります。

## 容量の予算

旧システムのソース・オブジェクトはわずかです(`src/legacy/` 全体で数十KB)。05-09・05-12 で SAVF を作りますが、いずれも小さなサンプル・データベースの複製です。

## 出力が違うとき

- **画面が期待と違う**: `src/legacy/qddssrc/` の DDS ソースと見比べてください。標識(indicator)の状態を `STRDBG` で確認するのが最短です。
- **コンパイルが通らない**: この部のソースの大半は`docs/probes.md`の第5部関連プローブで実機コンパイル確認済みです(`TXSNAP`は対話操作専用のため未確認、`RESTOBJ`等の一部コマンドの実パラメーターも未確認——各レッスンの「実機メモ」節参照)。自分の環境で再現しない場合は、まず各レッスンの「実機メモ」節と`docs/probes.md`を見比べてください。それでも解決しなければ Issue で教えてください。
- **`CPF4131`(様式レベル ID 不一致)が消えない**: 05-09 の「再作成の順序」を確認してください。PF → LF → DSPF → RPG → CL の順を飛ばすと再発します。
