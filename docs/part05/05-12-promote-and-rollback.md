## なぜ学ぶか

**05-10 まで、あなたはずっと `<USER>1`(開発用)の中だけで直してきました。** どんなに正しく直せていても、それが実際に使われる場所(本番役)に届かなければ意味がありません。逆に、届け方を間違えると、開発用では起きなかった問題(本番役に必要なファイルが無い、`*LIBL` の並び順のせいで古いプログラムが動き続ける、など)が起きます。ここでは、01-04・03-11 で予告だけしていた `<USER>2`(本番役)を、この教材で初めて実際に使います。**「まず戻れる状態を作ってから変更する」という安全第一の順序**を、実際に手を動かして身につけます。

## 説明

### `SETENV` で本番役に切り替える

03-11 で作った `SETENV`(`src/qclsrc/setenv.clp`)は、`*DEV`/`*PRD` を切り替えるツールでした。`*PRD` を渡すと、現行ライブラリーを `<USER>2` に変え、**`<USER>1` はライブラリー・リストの最後に残します**(`ADDLIBLE LIB(&LIB1) POSITION(*LAST)`)。

```text
CALL PGM(<自分のユーザー名>1/SETENV) PARM('*PRD')
```

**ここが今回の一番のわなです。** `<USER>1` が `*LIBL` に残ったままなので、もし `<USER>2` への移送が実は失敗していても、`CALL PGM(TK0100)` のようにライブラリー名を省略して呼び出すと、`*LIBL` を上から探して結局 `<USER>1` の(移送前と同じ)コピーが実行されてしまいます。**「動いた」ように見えても、それが本当に `<USER>2` のコピーで動いたのかどうかは、ライブラリー名を省略しない限り確認できません。**

### 本番の SAVF を先に取る

**何かを上書きする前に、必ず今の状態を保存します。** 02-10・03-14 で学んだ命名規則(`BKyymmdd`)と同じ発想で、今回は移送(Promote)用に別の接頭辞を使います。03-14 の模範解答(`solutions/03-14/backup.clp`)と同じパターンです。

```text
DCL VAR(&LIBB) TYPE(*CHAR) LEN(10)     /* %TRIM(&USRPRF) *TCAT 'B' */
DCL VAR(&DATE) TYPE(*CHAR) LEN(6)      /* RTVSYSVAL SYSVAL(QDATE) */
DCL VAR(&SAVF) TYPE(*CHAR) LEN(10)     /* 'PR' *TCAT &DATE        */
```

`BKyymmdd`(週次バックアップ)と同じ日に作業すると名前が衝突するため、接頭辞を `PR`(Promote)に変え、`PRyymmdd` とします。**QDATE の書式が `QDATFMT` に依存する点は 03-14 で既に指摘したとおりです**(実機での実際の桁数・区切りは未確認)。

```text
CRTSAVF FILE(<自分のユーザー名>B/PR<今日の日付6桁>)
SAVOBJ OBJ(TK0100 TK0100D) LIB(<自分のユーザー名>2) DEV(*SAVF) SAVF(<自分のユーザー名>B/PR<今日の日付6桁>) OBJTYPE(*ALL)
```

これで、**`<USER>2` に今すでにあるバージョン**(まだ05-10の変更が入っていない、`TXLEGACY` が入れたそのままのバージョン)が退避されます。これがあるおかげで、あとで問題が起きても元に戻せます。

### 再コンパイルと `CRTDUPOBJ` の違い

移送そのものには、大きく2つのやり方があります。

| やり方 | 内容 | 長所 | 短所 |
|---|---|---|---|
| `CRTDUPOBJ` | 開発用ですでにコンパイル済みのオブジェクトを、そのまま複製する | 速い。開発用で確認したのと**全く同じオブジェクト**が届く | 複製先(`<USER>2`)にソースは残らない(`ALWRTVSRC` が有効でない限り)。開発用が将来変わっても複製先は自動的には追従しない |
| 再コンパイル | 移送先のソース(コピーしたメンバー)から、移送先で改めて `CRTDSPF`/`CRTRPGPGM` する | 移送先が持っている**今のファイルの形**に対して確実にコンパイルし直せる。移送先が自分自身のソースを持つので独立している | 時間がかかる。ソース・メンバー自体を先に移送先へコピーしておく必要がある |

`TK0100D`(DSPF)は `TANTOM`・`TOKUIM` のようなファイルの形(様式)には依存しないので、**今回は `CRTDUPOBJ` で問題ありません**(移送先の `<USER>2` にも、`TXSETUP`/`TXLEGACY` で同じ `db/v1`/`db/v2` の DDS から作った同じ形のファイルが入っている前提です)。**もし移送先のファイルの形が開発用と違っていたら**(例えば05-09のような様式変更が移送先にまだ反映されていない場合)、`CRTDUPOBJ` は「その場のコンパイル済みオブジェクトをそのまま置くだけ」なので、様式レベル ID の不一致(`CPF4131`)にはその場では気づけません。そういう場合こそ、移送先で改めて再コンパイルする価値があります。

`DSPOBJD` の詳細(`DETAIL(*FULL)`)には、**そのオブジェクトが「どのソース・ファイル/メンバー/ライブラリー、いつの変更日時からコンパイルされたか」という作成元の情報**が出ます(`P44`)。`CRTDUPOBJ` で複製した直後は、この情報は**元のコンパイル場所(`<USER>1` 側)を指したまま**のはずです。もし `<USER>2` で改めて `CRTRPGPGM` していれば、この情報は `<USER>2/QRPGSRC` を指すはずです。**どちらの値が実際にどう表示されるかは、この教材群ではまだ実機確認できていません**(下の実機メモ参照)。

### `RTVCLSRC`/`ALWRTVSRC`: ソースが無くなったときの安全網

`CRTCLPGM` の `ALWRTVSRC(*YES)`(既定値)は、**コンパイル済みのプログラム・オブジェクトの中に、元の CL ソースをそのまま保持しておく**という設定です。ソース・メンバーを誤って消してしまった(あるいは、`<USER>2` のようにソースを持たせていない移送先だった)場合でも、`RTVCLSRC` コマンドで、動いているオブジェクトからソースを取り出し、ソース物理ファイルへ書き戻せます。**これは CL プログラムだけの機能です**(RPG III には同等の一般的な機能はありません)。`JU0900C` で試してみます。

```text
RTVCLSRC PGM(<自分のユーザー名>2/JU0900C) SRCFILE(<自分のユーザー名>2/QCLSRC) SRCMBR(JU0900C)
```

**`TK0100`/`TK0100D`(このレッスンの本題)は RPG と DSPF なので、この安全網は使えません。** だからこそ「ソース自体もきちんと移送先に置いておく」(上の再コンパイルの説明)ことに意味があります。ILE(第7部)では `DSPPGM` で似た情報が見られますが、ここでは扱いません。

## 実演

**ここから先は未検証です。** `<USER>2` を実際に使う移送・切り戻しの通しは、このセッションでは実機確認できていません(実機メモ参照)。

### 0. 事前準備・事前確認

1. `<USER>1/TK0100D` に `TANNM` フィールドが実際にあることを確認します(念のための確認です。05-10 は `<USER>1` で作業する前提で書かれています)。

   ```text
   DSPFFD FILE(<自分のユーザー名>1/TK0100D)
   ```

2. `TXSTATUS LIB(<自分のユーザー名>2)` を実行します。「not initialized」であれば、`<USER>2` を本番役として初めて使う準備をします(この教材で初めて `<USER>2` にオブジェクトが入ります)。

   ```text
   TXSETUP LIB(<自分のユーザー名>2)
   TXLEGACY LIB(<自分のユーザー名>2)
   ```

3. `TXLEGACY` は `LASTCD`(`TK0100` が実行時に必要とするデータ域)を作りません(05-01 で確認済み)。`<USER>2` でも手動で作ります。

   ```text
   CRTDTAARA DTAARA(<自分のユーザー名>2/LASTCD) TYPE(*CHAR) LEN(6)
   ```

### 1. 本番の SAVF を先に取る

4. 「説明」の手順どおり、`<USER>2` の今の `TK0100`・`TK0100D` を `<USER>B` の SAVF に退避します。

   ```text
   CRTSAVF FILE(<自分のユーザー名>B/PR<今日の日付6桁>)
   SAVOBJ OBJ(TK0100 TK0100D) LIB(<自分のユーザー名>2) DEV(*SAVF) SAVF(<自分のユーザー名>B/PR<今日の日付6桁>) OBJTYPE(*ALL)
   ```

5. `DSPSAVF FILE(<自分のユーザー名>B/PR<今日の日付6桁>)` で、退避された内容を確認します。

### 2. 移送する

6. `SETENV` で本番役に切り替えます。

   ```text
   CALL PGM(<自分のユーザー名>1/SETENV) PARM('*PRD')
   ```

   `DSPLIBL` で、現行ライブラリーが `<USER>2` になり、かつ `<USER>1` がリストの最後に残っていることを確認します。

7. `<USER>2` に既存の `TK0100D`・`TK0100` があれば削除します(`CRTDUPOBJ` は置き換えではなく新規作成のため。01-04 で学んだとおり、コマンド行では `CHKOBJ` ではなく `DSPOBJD` で存在を確認します)。

   ```text
   DSPOBJD OBJ(<自分のユーザー名>2/TK0100D) OBJTYPE(*FILE)
   DLTF FILE(<自分のユーザー名>2/TK0100D)
   DSPOBJD OBJ(<自分のユーザー名>2/TK0100) OBJTYPE(*PGM)
   DLTPGM PGM(<自分のユーザー名>2/TK0100)
   ```

8. `CRTDUPOBJ` で移送します。**DSPF を先に、RPG をあとに**(05-10 で確認した再作成順序と同じ理由です)。

   ```text
   CRTDUPOBJ OBJ(TK0100D) FROMLIB(<自分のユーザー名>1) OBJTYPE(*FILE) TOLIB(<自分のユーザー名>2)
   CRTDUPOBJ OBJ(TK0100) FROMLIB(<自分のユーザー名>1) OBJTYPE(*PGM) TOLIB(<自分のユーザー名>2)
   ```

### 3. 確認する

9. **ライブラリー名を省略せず**、`<USER>2` のコピーで実際に動くことを確認します。

   ```text
   CALL PGM(<自分のユーザー名>2/TK0100)
   ```

   得意先を1件照会し、8行目に担当者名(`TANNM`)が表示されることを確認します。

10. `DSPOBJD OBJ(<自分のユーザー名>2/TK0100) OBJTYPE(*PGM) DETAIL(*FULL)` で、作成元の情報(ソース・ファイル/メンバー/ライブラリー、変更日時)を確認します。`CRTDUPOBJ` で複製したので、この情報が `<USER>1` 側の元のコンパイル場所を指しているかどうかを記録してください。

11. **(余力があれば、5250 をもう1セッション開いて)** 1つ目のセッションで `CALL PGM(<自分のユーザー名>2/TK0100)` を実行したまま、2つ目のセッションから `WRKACTJOB` でそのジョブを探し、`DSPJOB OPTION(*OPNF)` で `TK0100D` が実際にどのライブラリーから開かれたかを確認します。`*LIBL` 経由で呼び出した場合、ここで初めて「本当に `<USER>2` から開かれているか、実は `<USER>1` のままか」が分かります。

12. 開発用ライブラリーへの参照が残っていないかも確認します(02-05 で触れた注意点です)。`TK0100`/`TK0100D` は `*CMD` ではないのでこの問題自体は起きませんが、もし `*CMD` を移送する場面があれば、`CRTCMD` の `PGM()` に `<USER>1` が決め打ちで残っていないか(`*LIBL` になっているか)を確認する習慣を、ここで併せて確認しておいてください。

13. **`<USER>1` への参照が本当に残っていないかを、動的に確認します(B2-1、Issue #9 の 08-08 側と同じ考え方の確認です)。** 手順9・10は `<USER>2` を明示的に修飾して呼んでいるだけなので、実は `<USER>1` 側の何かにこっそり依存していても、この確認では見抜けません。**`<USER>1` を `*LIBL` から完全に外した状態で動くかどうか**を確かめて初めて、「`<USER>2` だけで独立して動く」ことが証明できます。

    ```text
    DSPLIBL
    RMVLIBLE LIB(<自分のユーザー名>1)
    DSPLIBL
    CALL PGM(<自分のユーザー名>2/TK0100)
    ```

    2回目の `DSPLIBL` で `<USER>1` がライブラリー・リストから消えていることを確認してから `CALL` してください。得意先を1件照会し、手順9と同じ結果(`TANNM` が表示される)になれば、`<USER>2` は `<USER>1` に一切依存せずに動いていると確認できたことになります。**確認できたら、`ADDLIBLE LIB(<自分のユーザー名>1) POSITION(*LAST)` で `<USER>1` を元どおり `*LIBL` の最後に戻してください**(手順6の `SETENV *PRD` が作った状態に戻すため。以降の手順はこの状態を前提とします)。

### 4. 切り戻す

14. 「本番役で画面が崩れている」「担当者名が正しく出ない」など、**切り戻しが必要な状況**を想定します。まず `<USER>2` の今のコピーを削除します。

    ```text
    DLTF FILE(<自分のユーザー名>2/TK0100D)
    DLTPGM PGM(<自分のユーザー名>2/TK0100)
    ```

15. `RESTOBJ` を `F4` で開き、手順4で取った SAVF(`<USER>B/PR<日付>`)から復元します。02-10 で確認したとおり、PUB400 の `RESTOBJ` は `TMPxxxxxx` という一時ライブラリーに復元します。

16. `DSPOBJD OBJ(QSYS/TMP*) OBJTYPE(*LIB)` で、できた一時ライブラリーの名前を確認し、`CRTDUPOBJ` で `<USER>2` へ戻します(DSPF を先に)。

    ```text
    CRTDUPOBJ OBJ(TK0100D) FROMLIB(一時ライブラリー名) OBJTYPE(*FILE) TOLIB(<自分のユーザー名>2)
    CRTDUPOBJ OBJ(TK0100) FROMLIB(一時ライブラリー名) OBJTYPE(*PGM) TOLIB(<自分のユーザー名>2)
    DLTLIB LIB(一時ライブラリー名)
    ```

17. `CALL PGM(<自分のユーザー名>2/TK0100)` で、切り戻し後の状態(手順4の時点、担当者名の行が無い状態)に戻っていることを確認します。

18. `SETENV` で開発用に戻します。

    ```text
    CALL PGM(<自分のユーザー名>1/SETENV) PARM('*DEV')
    ```
