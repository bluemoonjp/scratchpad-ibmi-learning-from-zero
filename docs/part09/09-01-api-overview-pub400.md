第7部までで、受注・在庫の業務ロジックを[`JUCSRV`](../../src/qrpglesrc/jucsrv.rpgle)・[`ZAISRV`](../../solutions/07-05/zaisrv.rpgle)というサービス・プログラムに切り出しました。第8部では、それをgit・ビルド・テストで育てる道具立てを整えました。第9部では、この部品を**「外から呼べる形」にする**方法を扱います。画面(5250)ではなく、別のプログラムやWebのシステムが、決まった入力を渡して決まった形式(JSON)の結果を受け取る入口です。現場ではこれを一括して「API化」と呼びます。

## 説明

### APIとは何か(読解用)

**API**(Application Programming Interface)は、あるプログラムを別のプログラムから呼び出すための「入口の約束事」です。Windowsで言えば、他のアプリから呼ばれるDLLの関数や、WebサービスのURLがそれにあたります。5250の画面プログラムは人間が画面越しに使う入口であり、プログラムから呼ぶ入口としては使いにくいので、業務ロジックをそれと切り離した形で公開し直す、というのがAPI化です。

現場で「APIを作る」と言うとき、ほとんどは次の組み合わせを指しています。

- **REST**: HTTPでURLにリクエストを送り、結果を受け取るスタイル。
- **JSON**: 結果を表す文字列の書式。`{"ok":1}`のように、名前と値の組を波かっこで囲みます。

IBM iの中でどの入口を選ぶかで、必要な権限・作る手間が大きく違います。それを整理したのが次の4層です。

### 権限の壁

`*PGMR`は、ユーザー・クラス(ユーザー・プロファイルの種別)の1つで「プログラマー」を意味します。プログラムを作ってコンパイルし、自分のライブラリーの中のオブジェクトを作る・変える、という開発作業は`*PGMR`の範囲で足ります。第1部から第8部までの演習は、この範囲で進められる想定で書いてありますが、あなたのアカウントが実際に`*PGMR`かどうかは確認していません(未検証(2026-09-29時点))。

一方、サーバーを立ち上げる操作は、システム全体の構成にかかわるため、`*ALLOBJ`(すべてのオブジェクトに対する権限)や`*IOSYSCFG`(入出力・通信の構成を変える権限)といった**特別権限**を必要とします。この教材の設計は、IWSサーバーやHTTPサーバーの作成、ポートの開放をこちら側に分類し、PUB400では扱わないか、読んで設計する対象にとどめています。

ここで、確認できていることと、できていないことを分けておきます。

- **設計上の前提**(この教材の設計資料の記述): サーバーを作るには`*ALLOBJ`と`*IOSYSCFG`が要る。PUB400では受信ポートの開放は運営との調整次第で、`RSTLIB`も使えない。
- **実機では確認していないこと(未検証(2026-09-29時点))**: あなたのPUB400アカウントのユーザー・クラスが実際に`*PGMR`であること、サーバーを作ろうとして実際に権限エラーになること。この教材の実機記録には、どちらも残っていません。「壁がある」というのは設計上の整理であり、実機で測った事実ではありません。
- **実機で確認したこと(V2、2026-09-29)**: PUB400自身の`127.0.0.1`に対して、ACSのデータベース接続に使うとされる8471番・446番、P14の定義に含まれる8470番、Mapepireの8076番へ、`curl`で`telnet://`の形式(`-m 3`、3秒間)の接続を試したところ、4つとも`curl`の終了コードは28(タイムアウト)でした。ポートが閉じているのか、開いているが応答がないのかを区別できなかったため、**これはポートが開いているという証拠にも、閉じているという証拠にもなりません**(結論が出ていないので、P14・P40はV3のままです)。

つまり、第9部の「実機でやる」層は、**この壁の手前だけで完結するように選んである**、というのがこの教材の設計です。壁の向こう側は、設計書を書き、コードを読むところまでを目標にします。

### `VALUES`文

`VALUES`は、表を読まずに**式を1つだけ評価する**SQL文です。関数の動きを確かめたいときに、`SELECT ... FROM SYSIBM.SYSDUMMY1`と書く代わりに使えます。第9部で使う`JSON_OBJECT`・`HTTP_GET`といった関数を確かめる練習にちょうどよい題材です(IBMのドキュメントには`HTTP_GET`を`VALUES`で呼ぶ例があります。`JSON_OBJECT`の例の出典は未確認で、実機の確認対象外です)。

```sql
VALUES CURRENT_TIMESTAMP
VALUES JSON_OBJECT(KEY 'ok' VALUE 1)
```

2つ目は09-02の先取りです。ここでは**結果を見るだけで、組み立て方はまだ説明しません**。

### SSHの中でSQLを実行する: `db2`

第2部(02-04)で、SSH接続の中では`qsh`という、UNIXに近いシェルが使えると説明しました。その中の`db2`コマンドに、SQL文を**引用符で囲んで**渡すと、結果が表の形で返ってきます。

```text
db2 "SQL文"
```

この教材の検証(自動化ハーネス)は、SQLの結果の多くをこの形(`collect`ステップ)で集めています。5250の`STRSQL`([02-06](../part02/02-06-sql-inquiry.md))と違い、コマンドを貼り付けて結果をそのまま読める、ACSが使えなくても動く、という点がこのレッスンでの利点です。

## 実演

**手順1〜4は、実機(`part09-inventory`・`part09-01-02-json`、2026-09-29)で、qshの`db2`経由で実行し、結果まで確認済みです(V2)。** ただし手順4のSQLは、読みやすさとSQL0104対策のためコンマの後に空白を足してあり、ハーネスが実行した綴り(空白なし)とは空白の有無だけが違います。この綴りのままの実行は行っていません(結果の8行はルーチンの一覧と一致しています)。また著者の検証用ライブラリーで、自動化ハーネスがqshへ順に流し込む形で実行したものです。あなたが対話的にqshへ手で打ち込む操作そのものは、この教材では実行していません(同じ`db2`コマンドなので同様に動くと考えられますが、断定はしません)。ACSの手順は、後ろの囲みにまとめてあります(未検証)。

1. SSHでPUB400に接続し(02-04の作法のとおり。認証に2回失敗したらやめます)、`qsh`を起動します。

   ```text
   qsh
   ```

   これで`db2`コマンドを実行できる状態になるはずです。

2. 現在の時刻を、`VALUES`文で取得します。

   ```text
   db2 "VALUES CURRENT_TIMESTAMP"
   ```

   結果は、列見出し(名前のない列なので`00001`のような数字の見出し)と、1行の値、行数の表示です。**値は実行した時刻のものになります。** 著者の検証では、次の形式でした。

   ```text
   00001
   --
   2026-09-29-15.46.14.182526
    1 RECORD(S) SELECTED.
   ```

   `年-月-日-時.分.秒.マイクロ秒`の並びです(空白の数などの細かい見た目は環境で少し違うことがあります)。

3. 09-02の先取りとして、JSONを1つ作ってみます。

   ```text
   db2 "VALUES JSON_OBJECT(KEY 'ok' VALUE 1)"
   ```

   結果は次のとおりです。

   ```text
   00001
   --
   {"ok":1}
    1 RECORD(S) SELECTED.
   ```

   `{"ok":1}`は「`ok`という名前に、数値の1が対応する」という意味のJSONです。`JSON_OBJECT`の引数の書き方(`KEY '名前' VALUE 値`)は、09-02で説明します。

4. PUB400のうえに、このあとの部品(HTTP通信・ファイル書き出し・データ待ち行列のSQLルーチン)が実在することを、カタログから確かめます。

   ```text
   db2 "SELECT ROUTINE_SCHEMA, ROUTINE_NAME, ROUTINE_TYPE FROM QSYS2.SYSROUTINES WHERE ROUTINE_SCHEMA IN ('QSYS2', 'SYSTOOLS') AND ROUTINE_NAME IN ('HTTP_GET', 'HTTP_POST', 'IFS_WRITE_UTF8', 'IFS_WRITE', 'SEND_DATA_QUEUE', 'RECEIVE_DATA_QUEUE', 'SEND_DATA_QUEUE_UTF8', 'SPOOLED_FILE_DATA', 'JSON_TABLE') ORDER BY 1, 2, 3"
   ```

   著者の検証では、次の8行が返りました。

   ```text
   ROUTINE_SCHEMA ROUTINE_NAME ROUTINE_TYPE
   -- -- --
   QSYS2 HTTP_GET FUNCTION
   QSYS2 HTTP_POST FUNCTION
   QSYS2 IFS_WRITE PROCEDURE
   QSYS2 IFS_WRITE_UTF8 PROCEDURE
   QSYS2 RECEIVE_DATA_QUEUE FUNCTION
   QSYS2 SEND_DATA_QUEUE PROCEDURE
   QSYS2 SEND_DATA_QUEUE_UTF8 PROCEDURE
   SYSTOOLS SPOOLED_FILE_DATA FUNCTION
    8 RECORD(S) SELECTED.
   ```

   `JSON_TABLE`は指定していますが、行として返りません(実機で確認した事実です)。行として返らなかったのは、`FROM`句に書く構文で、ルーチンとして登録されていないためと考えられます(理由は未検証(2026-09-29時点))。使えるかどうかは、09-02で実際にJSONを読むときに確かめます(著者の検証では動作しました)。

5. 終わったら、`exit`でqshを抜けます。

   ```text
   exit
   ```
