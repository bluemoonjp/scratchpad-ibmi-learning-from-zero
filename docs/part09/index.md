## この部の目標

第8部までで、あなたは業務ロジックを`JUCSRV`・`ZAISRV`にまとめ、git・ビルド・テストで守るところまで来ました。現場では次に「そのロジックを別のシステムやWebの画面から呼べる形にしてほしい」と頼まれます。これがAPI化です。

PUB400は共有の練習機で、サーバーを立てる権限(`*ALLOBJ`・`*IOSYSCFG`)も、外から入ってくるポートの開放もない、と設計上は想定しています(PUB400の権限・規約は、この教材の実機確認では確かめていません。未検証(2026-09-29時点))。そこでこの部は、できないことを最初に線引きし、できる範囲(自分のライブラリーの中で、SQLとサービス・プログラムだけで、JSONを返す入口を作る)で手を動かします。総まとめの09-07は、第10部の総合演習E(API)の下地になります。

## 前提となる状態

第8部の内容(08-08のチェックポイントまで)が済んでいること。サンプル・データベースが入っていて、`DBVER`が、RPG III を通らないルートでは1、一本道(05-09を実施した人)では2になっていることは、`TXSTATUS LIB(<自分のユーザー名>1)`で確かめてください(`<自分のユーザー名>`は、各自のユーザー名に読み替えます)。08-08を実施した場合は、両方のライブラリーに`TXRESET`を実行した後の状態から始めてください(08-08が`ZAIKOM`の中身を書き換えるため)。

09-04でSQLルーチンとして登録する`JUCSRV`・`ZAISRV`は、第8部で作り直した後の`<自分のユーザー名>1`のものを使います。SQLルーチンの登録は、実体の`*SRVPGM`に登録情報を書き込む可能性があり(IBM Docsの記載。SQL7909)、途中で`JUCSRV`・`ZAISRV`を作り直した場合は`CREATE`文の再実行が要るかもしれません(未検証(2026-09-29時点))。RPGLEの外部関数の登録は、実体のオブジェクトを作らず、カタログ(`QSYS2.SYSROUTINES`)に載るだけでした(09-04で確認済み。ただし著者の検証では、本物ではなく複製を指していました)。

この部でデータを書き換えるのは、次の2か所だけです。09-04だけが、自分のコピーの`JUCHUM`・`JUCHUD`に`J09901`〜`J09903`を書き込みます。09-07は、`TXCKM`に3行入れます。`ZAIKOM`はこの部では書き換えません。

**解答ファイルの取得(この部の最初に1回)**: 02-04のクローンは`git sparse-checkout set src db tools`で作っているため、`solutions/`は手元にありません。09-03・09-04・09-05・09-07の手順は`solutions/`配下のファイルをIFSから読むので、SSHで次を実行して`solutions/`を追加してください。

```sh
cd $HOME/ibmi-kyozai && git sparse-checkout add solutions && git pull
```

(著者は実機では実行していません。未検証(2026-09-29時点)。第6〜8部で`solutions/`を使う手順も同じ状況です。)

## 4つの層

| 観察のみ | PUB400のMapepireデーモン(8076番。存在は未検証)へのVS Codeからの接続(P40)/実通信の`HTTP_GET`を手で1回ずつ(P33) | デーモンの設定は運営側の領域。実通信は、共有IPから大量に通信しない作法として、手で1回ずつ任意で試すだけにする(ループやバッチからは呼ばない) |
| 読んで設計する | IWSのRESTとPCMLからの公開/Apache+RPG CGI/Mapepireサーバーの導入/OpenAPI・認証・TLS・版の管理/HTTPAPI・YAJL・`DATA-INTO`/GitHub ActionsからSSHでPUB400に入るCI | サーバーを作るには`*ALLOBJ`と`*IOSYSCFG`が要る(想定。未検証)。現場では出会うので、設計書を書けて、コードを読めるところまでを目標にする |
| 扱わない | Node・Python・Java・PHPの実装/IWSサーバーやHTTPサーバーの作成/DCMと`QYKMIMPK`による証明書の管理/常駐リスナー/SOAPとAXIS/YAJLとRPGUnitの導入/PUB400を相手にする自動CI | 目標の範囲外、権限不足、共有機の規約のいずれか |

## 道具

- 5250: `TXSTATUS`・`SBMJOB`・`DSPJOBLOG`・`CRTDTAQ`などのCLコマンド。この部の`SBMJOB`には、必ず`INQMSGRPY(*DFT)`と`LOG(4 00 *SECLVL)`を付け([スタイル・ガイド](../style-guide.md)のPUB400での作法)、さらに`JOBQ(QGPL/QBATCH)`を明示します(既定のジョブ・キューに投入した検証では、ワーカーが2分以上動きませんでした。09-06)。
- SSH: SQLスクリプトを実行する経路です。(SSH)の手順は、SSH接続後に`qsh`を入力して、qshの中で実行します(`db2`はqshのコマンドです。SSHの既定シェルはPASEのbshで、`qsh`への切り替えの詳細は[09-01](09-01-api-overview-pub400.md)の未検証の注記のとおりです)。`RUNSQLSTM SRCSTMF('...') COMMIT(*NONE)`でIFS上の`.sql`ファイルを直接実行します。実行コマンドの形と注意点(`NAMING(*SQL)`・`ERRLVL(40)`、文字コードのタグ、`SQL0084`など)は09-02にあります。
- ACSの「実行SQLスクリプト」またはVS CodeのDb2 for i拡張(V3): 結果を表として見る、結果セットを返すプロシージャーを確かめる(09-07)、`HTTP_GET`のエラー情報を見る(09-05の任意節)ために使います。`HTTP_GET`のエラー情報については、IBM Docsに「ACSの実行SQLスクリプトで実行しないと有用なエラー情報が得られない。`STRSQL`では得られない」という記載があります(実機では未確認。IBM Docsの記載は、ACSの実行SQLスクリプトを使うべきで、`STRSQL`では有用な問題情報が得られない、という趣旨です)。
- PC側のブラウザー・テキストエディター(設計書を書くため)。

**この部のGUI(V3)について**: ACSやVS Codeの画面操作は、この教材の検証ハーネス(非対話のSSHだけで実機に接続する)では確認できません。GUIが前提のレッスン・節は、V3として次のように扱います。

- 09-01のACS接続設定の節と09-07のACS/VS Codeから呼ぶ節は、V3です。GUIを使えなくても、それ以外の本編(`VALUES`文の実行、紙上演習、SQLルーチンの作成と呼び出し)は成立するように書きます。
- **09-02bは、日本語の文字を実際に画面で見るGUI中心のレッスンです。V3のまま、00-02(PUB400登録)・06-02(VS Code)と同じ例外として公開します。** 著者が確認できたのは、後述の「日本語の文字コードの往復(16進数での確認)」の部分だけです。

## 観測方法

- SQLの結果(JSON文字列や表)。SSHでは`RUNSQLSTM`の実行リストを見ます。`RUNSQLSTM`は`SELECT`単独文を実行できない(`SQL0084`)ので、結果を見るには`INSERT ... SELECT`で表に入れるか、ACSを使います。
- `DSPJOBLOG`・メッセージ・キュー(09-06のワーカーの通知)。
- IFSに書き出したJSONファイル(`IFS_READ_UTF8`で読み返す)。
- 日本語の確認(09-02b)は`HEX()`による16進表示。

## 同時接続数

レッスンの案内文の「同時接続数」欄が正です。おおまかには次のとおりです。

- 09-01: SSH×1(ACSを試す場合だけ、さらにACS×1)。
- 09-02: ACS×1(またはSSH×1)。09-03〜09-06: 5250×1+SSHの形が中心です。
- 09-02b: ACS×1(GUI中心)。09-07: 案内文の欄を確認してください(ACS・VS Codeから呼ぶ節はV3)。

SSHは、連続失敗でIPが一時遮断されるため、認証に2回失敗したらやめてください([スタイル・ガイド](../style-guide.md)の「PUB400での作法」)。
