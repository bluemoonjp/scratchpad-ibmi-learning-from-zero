## なぜ学ぶか

第8部までで、あなたは「業務ロジックを`JUCSRV`・`ZAISRV`にまとめ、git・ビルド・テストで守る」ところまで来ました。現場では次に「そのロジックを**別のシステムやWebの画面から呼べる形**にしてほしい」と頼まれます。これがAPI化です。

ただし、PUB400は共有の練習機で、サーバーを立てる権限(`*ALLOBJ`・`*IOSYSCFG`)も、外から入ってくるポートの開放もない、と設計上は想定しています(PUB400の権限・規約は、この教材の実機確認では確かめていません。未検証(2026-09-29時点))。そこでこの部は、**できないことを最初に線引きし、できる範囲(自分のライブラリーの中で、SQLとサービス・プログラムだけで、JSONを返す入口を作る)で実際に手を動かす**という進め方を取ります。これは現場でも同じで、「何を自分で作り、何を基盤チームに頼み、何は設計書に書くだけにするか」を切り分ける力が、API化の最初の仕事になります。この部の総まとめ(09-07)は、そのまま第10部の総合演習E(API)の下地になります。

## 前提となる状態

第8部の内容(08-08のチェックポイントまで)が済んでいること。ただし、**09-04でSQLルーチンとして登録する`JUCSRV`・`ZAISRV`は、第8部(08-01のSRCSTMFビルド・08-02のmakeiビルド)で作り直した後の`<自分のユーザー名>1`のものを使います**。SQLルーチンの登録は、実体の`*SRVPGM`に登録情報を書き込む可能性があります(IBM Docsの記載による。SQL7909というメッセージが、作成・変更・削除のときに`*PGM`・`*SRVPGM`を変更できなかった場合に出るとされています)。そのため、この部の途中で`JUCSRV`・`ZAISRV`を作り直した場合は、SQLの`CREATE`文を再実行する必要があるかもしれません(未検証(2026-09-29時点))。

`TXSTATUS`で確認してください(実演のステップ1)。サンプル・データベースが`DBVER=1`の状態で入っていること。第8部の08-08を実施した場合は、`<自分のユーザー名>1`・`<自分のユーザー名>2`の両方に`TXRESET`を実行した後の状態から始めてください(08-08が`ZAIKOM`の中身を書き換えるため)。形は`<自分のユーザー名>1/TXRESET LIB(<自分のユーザー名>1)`のように、ライブラリーを指定します。

なお、09-04と09-07は、あなた自身のコピーの`JUCHUM`・`JUCHUD`・`ZAIKOM`を書き換えます(受注登録など)。`TXRESET`で元に戻せる想定ですが、第9部での戻し方は未検証(2026-09-29時点)です。

## 実演

1. 5250で`TXSTATUS`を実行し、サンプル・データベースの版を確かめます。

   ```text
   TXSTATUS LIB(<自分のユーザー名>1)
   ```

   `TXSTATUS: DBVER=1 in library ...`という形のメッセージが出ればよい状態です(メッセージの形は`tools/qclsrc/txstatus.clp`のソースから読み取ったもので、実行して確かめてはいません。未検証(2026-09-29時点)。`DBVER`が1になることは02-05で確認済みの内容です)。`TXSTATUS: not initialized in this library. Run TXSETUP first.`と出たら、第2部の`TXSETUP`が済んでいません(02-05へ戻ってください)。

2. 5250で`DSPLIBL`を実行し、現行ライブラリー(`CUR`の印が付く行)が`<自分のユーザー名>1`であることを確かめます。この部のSQLは、ライブラリー名を書かずに書きます。**`RUNSQLSTM`では、ライブラリー名を省略した`CREATE`の作成先は、`DFTRDBCOL`で指定したライブラリーです**(実機確認済み。ステップ4と実機メモを参照)。`DFTRDBCOL`を付けない場合や、ACS・`STRSQL`での作成先は、未検証(2026-09-29時点)です。`DSPLIBL`の`CUR`の行が作成先を決めるとは確認できていないので、ここでは自分の環境の確認として見るだけにします。第8部の08-08で`SETENV *PRD`を使った場合(08-08でも実機では実行していないV3の手順です)は、`SETENV *DEV`で戻してから始めてください。

3. SQLで、式を1つ評価してみます(`VALUES`文)。ACSの実行SQLスクリプト、または5250の`STRSQL`で次を実行します(どちらも使えないSSHだけの環境では、この実演は読むだけにして、結果を見る場面では、09-02から`INSERT ... SELECT`で表に入れて中身を確かめる形で進めます)。

   ```sql
   VALUES JSON_OBJECT(KEY 'ok' VALUE 1)
   ```

   結果は`{"ok":1}`という文字列になります。この式と`VALUES CURRENT_TIMESTAMP`は、2026-09-29に非対話のSSH経路(検証ハーネス)で実行し、どちらも動くことを確認済みです(`part09-01-02-json`)。**ACSや`STRSQL`の画面でどう表示されるかは対話操作のため未確認(V3、2026-09-29時点)** です。`JSON_OBJECT`の組み立て方は、ここではまだ説明しません。09-02で扱います。

4. SQLスクリプトをSSHで実行する道筋を、名前だけ確かめておきます(実際の実行は09-02から)。IFS上の`.sql`ファイルを、次の形で実行します。

   ```text
   RUNSQLSTM SRCSTMF('<IFS上のsqlファイル>') COMMIT(*NONE) DFTRDBCOL(<自分のユーザー名>1)
   ```

   実機では、`$`・`[`・`]`・`{`・`}`を含む`JSON_TABLE`のパス式(例: `'lax $.a[*]'`)が、この経路(qshのヒアドキュメントで書いたCCSID 273タグの`.sql`を`RUNSQLSTM SRCSTMF`で実行する)では壊れずに実行できました。逆に、`iconv`でUTF-8(CCSID 1208タグ)に変換した`.sql`を渡すと、`SQL0330`(文字変換不可)で失敗しました。**したがって、変換せずに実行できると確認できたのは、qshのヒアドキュメントでIFSに書いた場合(CCSID 273のタグが付く)だけです。** scp・git clone・`CPYFRMSTMF`などで`.sql`をIFSに置いた場合のCCSIDのタグと実行結果は、未検証(2026-09-29時点)です(09-02以降で、確認済みの置き方を示します)。 また、表がジャーナルされていないという`SQL7905`(重大度20)が出ても、後続の文は実行されました(警告扱い)。なお、`DFTRDBCOL`は未修飾名の作成先を決めますが、`CURRENT SCHEMA`はユーザー名のままです。これは著者の検証用ライブラリーでの結果で、あなたの`<自分のユーザー名>1`での再現は未確認です。

| `SQL0084` | `RUNSQLSTM`で`SELECT`単独文を実行した(SQL文が許可されていない) | 結果を表に入れる(`INSERT ... SELECT`)か、ACSの実行SQLスクリプトで実行する(`VALUES`単独文でも同じかは未検証(2026-09-29時点)) |
| `SQL7905`(重大度20) | 表を作ったが、ジャーナルされていない | この教材の範囲では警告として扱ってよい。後続の文は実行された(実機確認済み) |
| `SQL0330` | UTF-8(CCSID 1208タグ)に変換した`.sql`を`RUNSQLSTM`に渡した(文字変換不可) | 変換せず、確認済みの置き方(qshのヒアドキュメント)で書いた形のまま実行する |
| `SQL0104` | `SUBSTR(x,1,200)`のようにコンマの直後に数字を続けた。PUB400は小数点がコンマ(スタイル・ガイドの「SQLの数値の並び」。2026-09-26に実機で発生・修正した) | コンマの直後に空白を1つ置く: `SUBSTR(x, 1, 200)` |
| `SQL0110`系(SQLSTATE 42606) | `GX'0E30420F'`のようなグラフィック定数の書き方が不正(09-02bの実験で発生) | 日本語の確認は`UX'3042'`+`CAST(... AS VARCHAR(n) CCSID 1208)`の形を使う(09-02b) |
| SQLSTATE 42611 | `CAST(UX'3042' AS GRAPHIC(1) CCSID 1200)`を含む文で発生(どの部分が原因かは未切り分け) | 09-02bで扱う範囲では、この形を使わない |
| `CPF2104` | 現行ライブラリーを`RMVLIBLE`で外そうとした(05-12で確認) | 先に`CHGCURLIB`で現行ライブラリーを変える |
| `SQL7909` | 外部ルーチンの作成・変更・削除のとき、`*PGM`・`*SRVPGM`を変更できなかった(IBM Docsの記載。実機では未確認(2026-09-29時点)) | `JUCSRV`・`ZAISRV`にロックが掛かっていないか(他のジョブが使っていないか)確認する。詳しくは09-04 |

## 出力が違うとき

- **作ったはずのSQLルーチン・表が自分のライブラリーに見当たらない**: `RUNSQLSTM`では、未修飾の名前は`DFTRDBCOL`のライブラリーに作られます(実機確認済み)。`CURRENT SCHEMA`(ユーザー名のまま)とは別物です。`RUNSQLSTM`の実行リストの`Default collection`の行を確かめてください。`DFTRDBCOL`なしの場合やACS・`STRSQL`での作成先は、未検証(2026-09-29時点)です。
- **JSONの中の入れ子の配列が`"lines":"[{\"line\":1},...]"`のように、二重にエスケープされた文字列になる**: 外側の`JSON_OBJECT`に、内側の`JSON_ARRAYAGG`の結果を入れるときに`FORMAT JSON`を付けていません。付けると`"lines":[{"line":1,...}]`のように入れ子になります(実機確認済み、09-02)。
- **SSHで`SELECT`を実行しても結果が見えない**: `RUNSQLSTM`は`SELECT`単独文を実行できません(`SQL0084`。実機確認済み)。`VALUES`単独文でも同じかは未検証(2026-09-29時点)です(`VALUES`は検証ハーネスの別の経路で実行しました)。ACSで実行するか、結果を表に入れてください。
- **日本語が期待どおりに出ない**: 文字コード(CCSID)を疑ってください。検証したジョブのCCSIDは273でした。09-02bで、`UX'3042'`(ひらがなの あ)を`CCSID 1208`にキャストすると16進で`E38182`(UTF-8)、`CCSID 1399`・`939`・`930`にすると`0E44810F`(SO+4481+SI)になることを確かめます(実機確認済み)。ACSなどの画面での見え方はV3です。付録Jも参照してください。
- **`curl`が見つからない(09-05の任意節)**: PASE側の`curl`は`/QOpenSys/pkgs/bin/curl`にありますが、`PATH`には入っていません。フルパスで呼びます。なお、この教材の既定はモックで、実通信は任意です。実通信は、手で1回ずつだけ試し、ループや`SBMJOB`からは呼ばないでください。
- **ACSやVS Codeからつながらない**: PUB400へのACS(8471/446番)・Mapepire(8076番)の接続は、この教材では確認できていません(V3、未検証(2026-09-29時点))。つながらなくても本編は成立します。無理に設定を変えず、SSH経由の`RUNSQLSTM`で進めてください。
- **SSHで認証に失敗する**: 2回失敗したらやめてください(IPが一時遮断されます)。
