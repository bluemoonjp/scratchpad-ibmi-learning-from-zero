## 説明

### インストールするもの

VS CodeのMarketplaceで「IBM i Development Pack」(`HalcyonTechLtd.ibm-i-development-pack`)という拡張機能パックを検索してインストールします。これは単体の拡張機能ではなく、**Code for IBM i本体・IBM iの言語サポート(RPGLE/COBOL/CL/SQL)・Db2 for IBM i・IBM i Rendererをまとめて導入する「拡張機能パック」**です。個別に探して入れる必要はありません。

### 接続

Code for IBM iの接続設定画面に、02-04で使ったのと同じ情報(ホスト`pub400.com`、ポート**2222**番、ユーザー名、パスワードまたは秘密鍵)を入力します。

**秘密鍵を使う場合の注意**: Code for IBM iはOpenSSH形式の秘密鍵を前提にしています。PuTTYgenで作った鍵をそのまま指定すると`.ppk`形式のままで接続に失敗するため、PuTTYgenの「Conversions → Export OpenSSH key」で書き出し直す必要があります。また、秘密鍵ファイルは改行コードLFの単純なテキストとして扱われる形式のため、Windows上のテキスト・エディターで開いて保存し直すと改行コードがCRLFに変わり、鍵として壊れることがあります——編集せずそのまま使ってください。

### 一時ライブラリーの設定(重要、事故の芽)

Code for IBM iは、自分の作業用に「一時ライブラリー」(`tempLibrary`設定)を1つ使います。既定値は`ILEDITOR`という固定の名前で、**QTEMPは指定できません**。style-guide.mdのライブラリー構成(第0部)に合わせ、ここでは`<自分のユーザー名>B`を設定してください。

拡張機能には`autoClearTempData`という設定(既定でオン)があり、**接続のたびに一時ライブラリーの中の`O_`で始まる`*FILE`オブジェクトを自動的に削除します**(内部的には`DLTOBJ OBJ(一時ライブラリー/O_*) OBJTYPE(*FILE)`に相当)。これ自体は一時ライブラリーの中だけで完結する分には無害です。

**しかし、一時ライブラリーの作成・アクセスに失敗すると、拡張機能は警告メッセージを出したうえで、「現在のライブラリー」(名前が`Q`で始まらない限り)へ静かにフォールバックします。** つまり、`<USER>B`の設定を誤ったまま使い続けると、次回接続時の自動クリアが`<USER>1`(自分の主ライブラリー)に対して行われる可能性があります。もし`<USER>1`に偶然`O_`で始まる名前の`*FILE`オブジェクト(自分の開発物)があれば、気づかないまま消えることになります。**このレッスンの実演では、一時ライブラリーの設定値が実際に`<USER>B`になっていることを、初回接続のたびに確認する手順を必ず踏んでください。**

### コンパイル・アクションとProblemsパネル

VS Code上でメンバーを右クリック(またはショートカット)すると、あらかじめ用意された「アクション」(コンパイル・コマンドのひな型)を実行できます。RPGLEメンバー向けの既定アクションには最初から`OPTION(*EVENTF)`が含まれているため、追加の設定なしでコンパイル時の診断メッセージがProblemsパネルに反映されます。独自のアクションを`.vscode/actions.json`に書き足すこともできますが、このレッスンでは既定のアクションのまま使います。

### Db2 for IBM i拡張

同じ拡張機能パックに含まれる「Db2 for IBM i」拡張を使うと、VS Code上でSQL文を直接実行できます。バックエンドには`Mapepire`という、SSH経由(またはWebSocket経由)でSQLジョブを開く仕組みが使われています。

## 実演

**このレッスンの内容は、VS Code + Code for IBM iという、この教材の実機検証ハーネス(非対話SSHジョブ)では操作できないGUIツールが前提のため、著者自身によるSSH実機検証は行っていません(00-02のPUB400登録と同じ扱いです)。** 以下は拡張機能自身の公開ドキュメント・ソースに基づく手順で、実際の画面の細部は拡張機能のバージョンによって変わる可能性があります。

1. VS Codeに「IBM i Development Pack」をインストールする。
2. Code for IBM iの接続パネルから、02-04と同じ接続情報(ホスト・ポート2222・ユーザー名・パスワードまたはOpenSSH形式の秘密鍵)を使って接続する。
3. 接続設定の一時ライブラリーを`<自分のユーザー名>B`に設定し、実際にその値になっていることを設定画面で確認する。
4. `<自分のユーザー名>1/QRPGLESRC`に新しいメンバー(例: `V0602A`)を作り、06-01bで読んだ`V0601B`のごく一部を書き写したうえで、わざと1箇所だけ構文を崩す(例: `dcl-s`の型名を綴り間違える)。
5. 既定のコンパイル・アクション(RPGLE用)を実行し、Problemsパネルにエラーが表示されることを確認する。
6. 誤りを直して再コンパイルし、Problemsパネルが空になることを確認する。
7. Db2 for IBM i拡張から、`SELECT * FROM <自分のユーザー名>1.TOKUIM`のような簡単なSELECT文を実行し、結果がパネルに表示されることを確認する。

## 実機メモ

- **このレッスン自体は実機(SSH非対話ジョブ)で検証できないGUIツールが前提のため、V3(学習者自身の環境での確認が前提)として扱います。** 00-02(PUB400登録)と同じ位置づけです。依存するプローブ(P03・P14・P27・P37)は、この教材ではいずれも未実施のままです。
- **`tempLibrary`の既定値(`ILEDITOR`、QTEMP不可)・`autoClearTempData`が一時ライブラリー内の`O_*`(`*FILE`)を削除すること・一時ライブラリーの作成/アクセスに失敗した場合は警告を出したうえで現在のライブラリーへフォールバックすること**は、拡張機能(`codefori/vscode-ibmi`)自身の公開ソース(`src/api/IBMi.ts`)を2026-09時点の`master`ブランチで直接確認して書いている。
- **秘密鍵がOpenSSH形式である必要があること**は、拡張機能の既知の制約として複数のコミュニティー記事([Seiden Group](https://www.seidengroup.com/2023/09/11/using-ssh-keys-with-vs-code-for-ibm-i/)等)・GitHub Issueで報告されている内容に基づく。
- **RPGLE用の既定アクションに`OPTION(*EVENTF)`が最初から含まれていること**も、拡張機能自身の公開ソース(`src/filesystems/local/LocalLanguageActions.ts`)で確認した。設計段階のメモ(`work/design/part06-design-v1.md`)には「既定アクションにREPLACE(*NO)の罠がある」という想定があったが、実際のソースにはREPLACEパラメーター自体が明示されておらず(コマンド自身の既定値に委ねられる)、確認できなかったためこの想定は採用していない。
- 「IBM Bob」というAI製品と「TOBi」という呼称の区別(設計段階のメモにあった項目)は、一次資料で裏付けを取れなかったため、本文には含めていない。
