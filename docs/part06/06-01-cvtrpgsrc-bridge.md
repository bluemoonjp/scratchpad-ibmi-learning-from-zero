# 06-01 橋渡し: CVTRPGSRC と固定形式 RPG IV

> 所要時間: 75分(長め)/ 前提レッスン: 05-13 / 目標番号: 5・15 / 観測方法: `WRKSPLF`(変換レポート・コンパイル・リスト)・`DSPJOBLOG`(変換完了メッセージ)/ 道具: 5250(PDM/SEU)/ 同時接続数: 5250×1 / 作る・変えるオブジェクト: `<USER>1/QRPGLE112`(新規ソース物理ファイル)・`<USER>1/QRPGLE112(V0601A)`(変換後メンバー)・`<USER>1/V0601A`(プログラム)/ DBVER: 1 / 依存するプローブ: P04・P10(いずれも未実施)・P21(本レッスンで実機確認済み、ただし変換レポートのみ。`LOGFILE(*NONE)` としたため監査ログ側は未確認)/ PTF 依存: なし / 容量の目安: わずか

## ゴール

- `CVTRPGSRC` で、既に動いている RPG III プログラムを固定形式 RPG IV に変換できる。
- 変換レポートとコンパイル・リストを読み分け、「何を変換したか」と「変換後にコンパイラが何を指摘したか」を区別できる。
- RPG IV のソースが「固定形式」→「固定形式+`/FREE`埋め込み」→「`**FREE`完全自由形式」という3段階の系譜を持つことを説明できる。

## なぜ学ぶか

第5部までで、`R0408A`(`JUCINQ3`、受注照会の帳票版)のような RPG III プログラムを読み・直す力がつきました。第6部からは RPG IV の完全自由形式(`**FREE`)を主力言語にしていきますが、**いきなり全部を書き直すのではなく、まず「今動いているものを、最小限の手間で RPG IV のコンパイラーに通す」経路を知っておくことが、現場での引き継ぎ・段階的な近代化でも定石です。** その道具が `CVTRPGSRC`(RPG 変換支援ツール)です。このレッスンでは、04-08 で実機確認済みの `R0408A` をそのまま `CVTRPGSRC` にかけ、出てきたものが何であり、何でないかを実際に確かめます。ここで作る `V0601A`(固定形式 RPG IV)は、06-01b(固定形式+`/FREE`混在を読む)・06-03(`**FREE` で書き直す)の土台になります。

## 新出

### 中核概念(3つ)

1. `CVTRPGSRC` は**桁位置ベースの命令コードを、RPG IV コンパイラーが読める桁位置に機械的に並べ替えるだけの道具**であり、`DOW`/`EVAL` のような現代的な書き方に自動的に書き換えてくれるわけではない(命令コードは、綴りの変更(`EXCPT`→`EXCEPT`)を除けばそのままである)。
2. RPG IV のソースには「固定形式」→「固定形式+`/FREE`...`/END-FREE`埋め込みブロック」→「`**FREE`完全自由形式」という3段階の系譜があり、このレッスンで作る `V0601A` は**その1段階目(純粋な固定形式)**にあたる。
3. SEU(第1〜5部で使ってきたソース編集ツール)は、そもそも `**FREE` を正しく扱えないと**一般に言われている**(構文検査が古いバージョン相当で止まる)。この教材ではまだ実機(対話式の SEU セッション)で確認できていない点なので、断定はせず「06-02で VS Code に切り替える理由の1つ」として留めておきます。

### 構文・コマンド(6つ)

- `QRPGLE112`: このレッスンで新規に作る、`RCDLEN(112)` のソース物理ファイル。
- `CVTRPGSRC`: RPG III/RPG・400 のソースを RPG IV 形式に変換するコマンド。
- `CRTBNDRPG`: RPG IV 用の新しいコンパイル・コマンド(`CRTRPGPGM` の後継、束縛プログラムを作る)。
- D仕様書: 変数・データ構造を宣言する、RPG IV で新設された仕様書(このレッスンの変換結果には登場しません。理由は後述)。
- `EVAL`: 自由に式が書ける新しいオペコード(このレッスンの変換結果には登場しません。理由は後述)。
- `/FREE` ... `/END-FREE`: 固定形式の中に自由形式の計算部分を埋め込む書き方(このレッスンの変換結果には登場しません。06-01b で別のソース `V0601B` を使って扱います)。

## 説明

### RPG IV の3段階

RPG IV のソースは、書き方によって次の3段階に分けられます。

| 段階 | 見た目 | この教材での扱い |
|---|---|---|
| 1. 固定形式 | H/F/D/C/O仕様書すべてが桁位置ベース(RPG III とほぼ同じ見た目) | **06-01(このレッスン)。`V0601A` がこの段階。** |
| 2. 固定形式+`/FREE`混在 | H/F/D/O仕様書は桁位置ベースのまま、C仕様書の計算部分だけ `/FREE`...`/END-FREE` で自由形式に | 06-01b(`V0601B` を新規に作る) |
| 3. `**FREE`完全自由形式 | ソース全体が自由形式 | 06-03以降 |

`CVTRPGSRC` が今日作る `V0601A` は、**この3段階のうちの1段階目そのもの**です。2段階目(`/FREE` 混在)は `CVTRPGSRC` が作ってくれるものではなく、06-01b で別のソースを使って手で体験します。

### `CVTRPGSRC` を実行する

`CVTRPGSRC` の変換先(`TOFILE`)は、**コマンド自体の既定値は `QRPGLESRC`**です(`F4` プロンプトや IBM のコマンド解説で確認できます)。変換後のソースに必要なレコード長は、一次資料(`ILE RPG プログラマーの手引き`)によれば**最低92桁(12桁の順序番号+日付+80桁のコード)、推奨112桁(+20桁のコメント)**で、IBM が `QGPL/QRPGLESRC` として用意している既定のソース物理ファイルは、既にこの推奨どおり `RCDLEN(112)` です。つまり112桁という長さ自体は、既定の `QRPGLESRC` を使わない理由にはなりません。**このレッスンで専用のソース物理ファイル `QRPGLE112` を自分で作るのは、06-01b で読者自身が新たに作る `QRPGLESRC`(手書きの RPGLE ソースを入れる場所)と、この `CVTRPGSRC` の変換結果を混在させないためです。** なお `CRTSRCPF` 自体の既定レコード長は92桁(推奨の112桁ではありません)なので、`QRPGLE112` を作るときは `RCDLEN(112)` を明示します。

さらに、`CVTRPGSRC` は変換先のファイル自体は自動的に作ってくれません(`TOFILE` は事前に存在している必要があります)。順番を守らないと、オブジェクトが見つからない、という趣旨のエスケープ・メッセージで止まります(具体的なメッセージIDは、この教材では実機確認していません)。

```text
CRTSRCPF FILE(<USER>1/QRPGLE112) RCDLEN(112) TEXT('CVTRPGSRC の変換先')

CVTRPGSRC FROMFILE(<USER>1/QRPGSRC) FROMMBR(R0408A) +
          TOFILE(<USER>1/QRPGLE112) TOMBR(V0601A) +
          CVTRPT(*YES) LOGFILE(*NONE)
```

`CVTRPT(*YES)` は実は既定値と同じです(明示しなくても同じ結果になりますが、「レポートを出す設定である」と分かるように、あえて書いています)。`LOGFILE` の既定値 `QRNCVTLG` は、`TOFILE` と同じく「事前に存在している別のファイル」を要求するため、このレッスンでは `LOGFILE(*NONE)` を明示して、監査ログ用のファイルをもう1つ作る手間を省いています(監査ログとレポートは別物で、今日必要なのはレポートの方だけです)。

**やり直すときの注意**: 一度変換した `V0601A` が既に存在する状態でもう一度 `CVTRPGSRC` を実行すると、変換自体は行われずジョブ・ログにメッセージが出るだけで、それに気づかず次の `CRTBNDRPG` を実行すると**古い(変換し直していない)メンバーがそのままコンパイルされてしまいます**。やり直すときは、先に `RMVM FILE(<USER>1/QRPGLE112) MBR(V0601A)` でメンバーを消してから `CVTRPGSRC` を実行してください。

### 変換結果を読む

実際に `R0408A`(04-08 で実機確認済みの `JUCINQ3`)を変換すると、次のメンバー(`<USER>1/QRPGLE112(V0601A)`)ができます。次は**実際の `CVTRPGSRC` 実行結果をそのまま書き起こしたもの**です(`src/qrpglesrc/v0601s.rpgle`。桁位置の詰め方までそのまま)。

```text
      * R0408A - JUCINQ3: order inquiry report for one customer.
     H
     FTOKUIM    IF   E           K DISK
     FJUCHUM    IF   E             DISK
     FQSYSPRT   O    F  132        PRINTER
     C                   MOVEL     'C00001'      CUST              6
     C     CUST          CHAIN     TOKUIM                             99
     C   99              MOVEL     'NOTFOUND'    TOKNM
     C     LOOP          TAG
     C                   READ      JUCHUM                                 98
     C   98              GOTO      ENDLP
     C     JUTOK         IFEQ      CUST
     C                   EXCEPT
     C                   ENDIF
     C                   GOTO      LOOP
     C     ENDLP         TAG
     C                   SETON                                        LR
     OQSYSPRT   E
     O                       TOKNM               30
     O                                           32 '  '
     O                       JUNO                38
     O                                           40 '  '
     O                       JUDATE              48
```

04-08 の `r0408s.rpg` と見比べると、変わっているのは**桁位置の詰め方(命令コード欄が広がり、余裕を持って並んでいる)だけ**で、命令コード自体は `MOVEL`・`CHAIN`・`IFEQ`・`READ`・`GOTO`・`TAG`・`SETON` のどれも無変更です。唯一のオペコード自体の変化は、`EXCPT`(RPG III/OPM の綴り)が `EXCEPT`(RPG IV の正式名。同じ演算です)に置き換わった点だけでした。`DOW`/`EVAL` のような自由形式・現代的な書き方への書き換えは一切起きていません。**これは今回たまたま起きなかったのではなく、`CVTRPGSRC` の設計そのものが「コンパイルできる形に整えるだけ」で、コードを近代化する道具ではないためです。**

D仕様書・`EVAL`・`/FREE` がこの変換結果に1つも出てこないのは、`R0408A` 自体が D仕様書で宣言するような独立した変数・データ構造を持たず(すべてファイルの入出力項目か、C仕様書の結果欄で初めて長さが決まるフィールドだけ)、`CVTRPGSRC` は「無ければ足す」ことはしないためです。D仕様書・`EVAL`・`/FREE` は、06-01b・06-03 以降で、皆さん自身が新しく書くときに登場します(06-01bで新しく作る `V0601B` は、この2段階目(固定形式+`/FREE`混在)の実例で、既に実機コンパイル・実行(税込み計算 `1,738.00` の印字)まで確認済みです)。

### 変換レポートとコンパイル・リストは別物

**ここが今回いちばん誤解しやすい点です。** `CVTRPGSRC` を実行すると、変換そのものの結果を報告する**変換レポート**(スプール・ファイル名は `TOFILE` と同じ、つまり `QRPGLE112`)が出ます。この`R0408A`の変換では、レポートの最終集計はこうでした。

```text
   Message Totals:
     Information  (00) . . . . . . . :        0
     Warning      (10) . . . . . . . :        0
     Severe Error (30+)  . . . . . . :        0
     Total . . . . . . . . . . . . . :        0
   Source Totals:
     Original Records Read . . . . . . :       23
     Converted Records Written . . . . :       23
     Highest Severity Message Issued . :        0
```

**つまり `CVTRPGSRC` 自体はこの `R0408A` に対して何も指摘しませんでした(メッセージ0件)。** これは「`R0408A` が `/COPY` も他プログラムへの `CALL` も持たない、素直な1本のプログラムだったから」であり、**「`CVTRPGSRC` が何を変換できないか」は、今回の題材では実演できていません。** より込み入ったソース(`/COPY` を展開する `EXPCPY(*YES)` が必要になるケースなど)での確認は、このレッスンでは行っていない今後の課題です。

一方、変換後の `V0601A` を実際に `CRTBNDRPG` でコンパイルすると、**コンパイラー自身が**次の情報レベル(重大度00)のメッセージを10件出しました(合計。プログラムは問題なく作成されています)。

```text
   Message Totals:
     Information  (00) . . . . . . . :       10
     Warning      (10) . . . . . . . :        0
     Error        (20) . . . . . . . :        0
     Severe Error (30+)  . . . . . . :        0
     Total . . . . . . . . . . . . . :       10
```

その中に、次の2件が含まれていました。

- **`RNF2318`**(F仕様書の `QSYSPRT` の行に対して): 「Overflow indicator *INOA is assigned to PRINTER file QSYSPRT.」(オーバーフロー標識を明示しなかったので、コンパイラーが自動的に `*INOA` を割り当て、06行目への自動改ページを生成した、という意味)。
- **`RNF6011`**(O仕様書の先頭行に対して): 「The Space and Skip entries are blank and no PRTCTL keyword specified; Space-After defaults to 1.」(改行指定を1つも書かなかったので、1行改行が既定値として使われた、という意味)。

**この2件は `CVTRPGSRC`(変換ツール)ではなく `CRTBNDRPG`(コンパイラー)が出したものです。** `R0408A` を元の `CRTRPGPGM` でコンパイルしたとき(04-08)の実機メモには、メッセージの一覧までは記録されておらず(「Highest Severity 00」とだけ記録)、直接の比較はできません。ただし、[`docs/probes.md`](../probes.md)の RPG III 生成器の実機検証では、`R0408A` と同じ「`PRTCTL` なしの `QSYSPRT`」という形を持つ `R0401A`・`R0402A` を `CRTRPGPGM` でコンパイルした際に、同じ2つの省略(オーバーフロー標識未指定・PRTCTL/スペース・スキップ未指定)に対応する `QRG6103`・`QRG6011` という情報メッセージが実際に出ています。**RPG III の `CRTRPGPGM` も、メッセージIDの接頭辞(`QRG`→`RNF`)が変わっただけで、同種の情報メッセージを出していた可能性が高いと考えられます。** 「RPG IV になって初めて教えてくれるようになった」と言い切るのは言い過ぎで、正しくはおそらく「コンパイラーが変わってメッセージIDの体系が変わった」という違いです。どちらも重大度00(情報レベル)で、プログラムの動作そのものには影響しません。

## 実演

1. `<USER>1`(自分の開発用ライブラリー。04-08 で `R0408A` を作ったのと同じ場所です)に接続します。
2. `RCDLEN(112)` のソース物理ファイルを作ります。

   ```text
   CRTSRCPF FILE(<USER>1/QRPGLE112) RCDLEN(112) TEXT('CVTRPGSRC target')
   ```

3. `R0408A` を変換します(`LOGFILE(*NONE)` を忘れずに)。

   ```text
   CVTRPGSRC FROMFILE(<USER>1/QRPGSRC) FROMMBR(R0408A) +
             TOFILE(<USER>1/QRPGLE112) TOMBR(V0601A) +
             CVTRPT(*YES) LOGFILE(*NONE)
   ```

4. `DSPJOBLOG` で、ジョブ・ログに「Conversion complete. 1 converted, 0 converted with errors, 0 not converted.」というメッセージが出ていることを確認します。続けて `WRKSPLF` で、名前が `QRPGLE112` のスプール・ファイル(変換レポート)を開き、「説明」節で見た Message Totals・Source Totals の集計(すべて0、Original/Converted Records とも23)と一致していることを確かめてください。
5. `WRKMBRPDM FILE(<USER>1/QRPGLE112)` で `V0601A` を開き(オプション5=表示、または F4=SEU)、前節の内容と一致することを確認してください。
6. コンパイルします。

   ```text
   CRTBNDRPG PGM(<USER>1/V0601A) SRCFILE(<USER>1/QRPGLE112) SRCMBR(V0601A)
   ```

7. `WRKSPLF` でコンパイル・リストを開き、`RNF2318`・`RNF6011` を含む情報メッセージが出ていること、Highest Severity が `00` であることを確認します。
8. 実行し、04-08 と同じ出力になることを確認します。

   ```text
   CALL PGM(<USER>1/V0601A)
   ```

   ```text
   ACME TRADING CO                 J00001  20260901
   ACME TRADING CO                 J00003  20260905
   ```
