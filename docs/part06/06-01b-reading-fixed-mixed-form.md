# 06-01b 固定形式・混在形式の RPG IV を読む

> 所要時間: 45分 / 前提レッスン: 06-01 / 目標番号: 5 / 観測方法: `WRKSPLF` / 道具: 5250(SEU)/ 同時接続数: 5250×1 / 作る・変えるオブジェクト: `<USER>1/QRPGLESRC`(無ければ新規作成)・`<USER>1/V0601B` / DBVER: 1 / 依存するプローブ: P04, P10 / PTF 依存: なし / 容量の目安: わずか

## ゴール

- RPG IV の固定形式 C 仕様書・F 仕様書の桁位置が、RPG III と異なることを、具体的な桁番号で言える。
- 固定形式のソースの中に `/FREE`...`/END-FREE` が混ざった書き方を読める。
- IBM Docs で、ILE RPG言語リファレンスと RPG/400リファレンスを取り違えずに調べられる。

## ウォームアップ

<details><summary>前回の復習(06-01)</summary>

1. `CVTRPGSRC` は、命令コードを現代的な `%BIF` を使った書き方に書き換えてくれますか?
2. RPG IV のソースの「系譜」を、古い方から順に3段階で言うと?
3. `CVTRPGSRC` が `R0408A` を `V0601A` に変換したとき、書き換えられた命令コードが1つだけありました。どれが、何に変わりましたか?

答え: 1. 書き換えません。桁位置の詰まった書式を余裕のある書式に正規化し、一部の命令コードを RPG IV の正式名に置き換えるだけです(`EVAL` 化のような現代化は一切行いません)。 2. 固定形式 → 固定形式+`/FREE` 埋め込み → `**FREE` 完全自由形式。 3. `EXCPT`(RPG III/OPM の綴り)が `EXCEPT`(RPG IV の正式名)になりました。`MOVEL`・`CHAIN`・`IFEQ`・`READ`・`GOTO`・`TAG`・`SETON` は無変更です。

</details>

## なぜ学ぶか

現場の RPG IV ソースは、教科書どおりの `**FREE` だけとは限りません。**長年の資産は、固定形式のまま残っていたり、固定形式の中に `/FREE` ブロックだけが後から足された「混在形式」のまま残っていたりすることが珍しくありません。** 06-01 で `CVTRPGSRC` が作った `V0601A` は、まさに「固定形式のまま」の一例でした。ここでは一歩進めて、固定形式の中に `/FREE` ブロックが混ざる書き方(`V0601B`)を読みます。

あわせて、05-03 が積み残した問いにも答えます。05-03 は「サイクル自体・一致レコード処理には、FREE形式でも完全な代替がありません(第6部で確認します)」と予告していました。`V0601A` を見ると、この「代替がない」機能(制御レベル・一致レコード処理)を一切使わずに、サイクルの枠組み(`SETON LR` で終わる)だけを借りている、という**中間的な書き方**がすでに RPG III の時点で存在していたことが分かります。

最後に、これから先(06-03 以降)自分で IBM Docs の一次資料を引く場面が増えるため、ここで探し方の勘所も押さえておきます。

## 新出

- 中核概念(2つ)
  1. RPG III→RPG IV の BIF 転換: RPG III には `%` で始まる組み込み関数(BIF)が1つも無かった、という事実そのもの([付録F](../appendix/f-bif-reference.md)参照)。
  2. IBM Docs でのリファレンスの引き方(検索語の選び方、ILE RPG言語リファレンスと RPG/400リファレンスの取り違え防止)。
- 構文(2つ)
  1. `V0601A`(06-01)の桁位置の読み方の復習と、RPG III との桁のずれ。
  2. `/FREE`...`/END-FREE` 混在パターン(`V0601B` で新規に見ます)。
- 読解用(この上限には数えません): 固定形式 RPG IV の H/F/D/C/O 仕様書の桁の並び(RPG III の仕様書との異同)。

## 説明

### RPG III と RPG IV で、固定形式の桁位置が違う

**注意してください。RPG IV の固定形式は、RPG III の桁位置をそのまま受け継いでいません。** 同じ「Factor 1」「命令コード」という名前の欄でも、桁位置が変わっています。実際に `R0408A`(RPG III、04-08)と、その `CVTRPGSRC` 変換結果 `V0601A`(RPG IV、06-01)の同じ行を並べてみます。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+.
     C           CUST      CHAINTOKUIM               99
```

これが `R0408A`(RPG III)の `CHAIN` の行です。`CUST`(Factor 1)は18桁目から、`CHAIN`(命令コード)は28桁目から、`TOKUIM`(Factor 2)は33桁目から、結果標識の `99`(HI)は54〜55桁目です(04-02・04-07 で確認済みの桁割り当てどおり)。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8....+....9....+....0
     C     CUST          CHAIN     TOKUIM                             99
```

これが同じ行の `V0601A`(RPG IV、`CVTRPGSRC` の変換結果)です。`CUST` は12桁目、`CHAIN` は26桁目、`TOKUIM` は36桁目、結果標識の `99` は71〜72桁目に移っています。**命令コードそのもの(`CHAIN`)は変わっていませんが、桁位置は全体的に後ろへずれています。**

この2本のソース(`src/qrpgsrc/r0408s.rpg`・`src/qrpglesrc/v0601s.rpgle`)を実際に桁数で確認すると、対応は次のとおりです。

| 欄(C仕様書) | RPG III(桁) | RPG IV(桁) |
|---|---|---|
| Factor 1 | 18〜27 | 12〜25 |
| 命令コード | 28〜32 | 26〜35 |
| Factor 2 | 33〜42 | 36〜49 |
| 結果フィールド | 43〜48 | 50〜63 |
| フィールドの長さ | 49〜51 | 64〜68 |
| 小数桁数 | 52 | 69〜70 |
| 結果標識(HI/LO/EQ) | 54〜59 | 71〜76 |

F仕様書も同様にずれます。

```text
....+....1....+....2....+....3....+....4....+.
     FTOKUIM  IF  E           K        DISK
     FQSYSPRT O   F     132            PRINTER
```

上が `R0408A`(RPG III)、下が同じ2行の `V0601A`(RPG IV)です。

```text
....+....1....+....2....+....3....+....4....+.
     FTOKUIM    IF   E           K DISK
     FQSYSPRT   O    F  132        PRINTER
```

| 欄(F仕様書) | RPG III(桁) | RPG IV(桁) |
|---|---|---|
| ファイル種別(I/O/U/C) | 15 | 17 |
| ファイル指定(P/S/F など) | 16 | 18 |
| ファイル形式(F/E) | 19 | 22 |
| 装置(DISK/PRINTER) | 40〜46 | 36〜42 |

O仕様書も同様にずれます。同じ `TOKNM` の行(04-08 の `O TOKNM 30`)を比べると、フィールド名 `TOKNM` の開始位置が RPG III の32桁目から RPG IV の30桁目に、フィールドの終了桁位置を指定する数字(`30`)が RPG III の42〜43桁目から RPG IV の50〜51桁目に、それぞれ移っています。

この対応は、一次資料(ILE RPG言語リファレンス)の桁位置の節と、04-02・04-08 で実機確認済みの RPG III 側の桁表を、実際にこの教材のソース(`r0408s.rpg`・`v0601s.rpgle`)で数えて突き合わせたものです。**RPG III の桁位置をそのまま RPG IV の固定形式に持ち込むと、Factor 1 のつもりで書いた内容が命令コード欄にはみ出す、といった書き間違いが起きます。** SEU の `F4` プロンプトを使えば桁を自分で数えずに済むので、実際に入力するときは `F4` を活用してください。

### D仕様書という、RPG III には無い新しい仕様書

`V0601B` には、RPG III のどの仕様書にも対応しない、まったく新しい仕様書があります。

```text
     DPRICE            S              7P 2
     DRATE             S              3P 2
     DTOTAL            S              9P 2
     DOUTREC           DS
     DTOTALX                         15A
```

D仕様書(Definition Specification)は、変数・データ構造を、実行される計算より前にまとめて宣言する仕様書です。04-02 で見たとおり、RPG III には D仕様書が無く、フィールドは C仕様書の結果フィールドに初めて長さを書いた行で「その場宣言」されていました。**RPG IV は D仕様書を追加しましたが、固定形式の C仕様書では今でも同じ「その場宣言」が使えます。** 実際、`V0601A`(`CVTRPGSRC` は宣言方法を書き換えないので)は今も `CUST`(結果フィールド、上の表の64〜68桁目に長さ `6`)をその場宣言のまま使っています。**D仕様書が特に効いてくるのは `/FREE` ブロックの方です。** `/FREE`...`/END-FREE` の中の代入文(`price = 1580;` など)には、C仕様書のような「長さ欄」がありません。そのため、`/FREE` ブロックで使う変数は、あらかじめ D仕様書で宣言しておく必要があります(`V0601B` の `PRICE`・`RATE`・`TOTAL`・`OUTREC`/`TOTALX` がその例です)。

### RPG III のオペコード・桁位置には、RPG IV で `%BIF` という後継がある

[付録F](../appendix/f-bif-reference.md) で確認したとおり、RPG III には `%` で始まる組み込み関数(BIF)が1つもありません。RPG IV は、RPG III でオペコードや仕様書の桁位置が担っていた機能の一部に、BIF という関数呼び出しの形の後継を用意しました。対応の例をいくつか挙げます(いずれも[付録F](../appendix/f-bif-reference.md)参照)。

| RPG III | RPG IV の後継 BIF |
|---|---|
| `SUBST` 命令(オペコード) | `%SUBST` |
| `SCAN` 命令(オペコード) | `%SCAN` |
| `LOKUP` 命令(オペコード) | `%LOOKUP` |
| O仕様書(RPG IVでは44桁目)の編集コード欄 | `%EDITC` |

**大事な注意点があります。RPG IV は、これらの旧オペコード・O仕様書の編集コード欄を廃止したわけではありません。** 固定形式の C仕様書・O仕様書では、`SUBST`・`SCAN`・`LOOKUP` や編集コード欄は今でもそのまま書けます(RPG III での5文字略記`LOKUP`は、`EXCPT`→`EXCEPT`と同じパターンで、RPG IV では正式名`LOOKUP`に置き換わっています。一次資料(ILE RPG言語リファレンス)にも`LOKUP`という綴りは一度も登場しません)。**ただし、自由形式(`**FREE` はもちろん、`/FREE`...`/END-FREE` の中も含む)では、これらのオペコードは使えません。** 一次資料(ILE RPG言語リファレンス)は、`SUBST`・`SCAN`・`LOOKUP`・`XLATE` のそれぞれについて、自由形式の構文の欄に「not allowed」(使えない、対応する BIF を使うこと)という趣旨の注記を掲載しています。ただし文言はBIFごとに微妙に違い、例えば`SUBST`は「not allowed - use `%SUBST`」、`LOOKUP`は「not allowed - use the `%LOOKUP` or `%TLOOKUP` built-in function」(`%TLOOKUP`も選択肢として併記)です。**自由形式で同じ処理をしたいときに、対応する BIF を使う**、というのが RPG IV の設計です。`CHAIN`・`READ` のようなファイル操作の命令コードは、この制限を受けず、固定形式でも自由形式でも同じ名前のオペコードのまま使えます(`V0601A` 自身が固定形式での実例です。ただし自由形式での実例は、この教材ではまだ示せていません — `V0601B` にも自由形式の`CHAIN`/`READ`呼び出しはありません)。

### 混在形式: `V0601B` を読む

`V0601B` は、04-02 の `R0402A`(税込み金額の計算、`1580×1.10=1738.00`)のロジックを、固定形式の H/F/D 仕様書で挟み、計算部分だけ `/FREE`...`/END-FREE` で書いた小さなサンプルです(`src/qrpglesrc/v0601bs.rpgle`)。

```text
     H

     FQSYSPRT   O    F   15        PRINTER

     DPRICE            S              7P 2
     DRATE             S              3P 2
     DTOTAL            S              9P 2
     DOUTREC           DS
     DTOTALX                         15A

      /FREE
       price = 1580;
       rate = 1.10;
       total = price * rate;
       totalx = %editc(total : '1');
      /END-FREE
     C                   WRITE     QSYSPRT       OUTREC
     C                   SETON                                        LR
```

固定形式(H・F・D・そして末尾の `WRITE`/`SETON`)と、自由形式(`/FREE`...`/END-FREE` の中)が、同じソースの中に混ざっています。**`/FREE` から `/END-FREE` までの中は、Factor 1・命令コード・Factor 2 のような桁の区切りを気にせず書けます**(`price = 1580;` のような代入式は、RPG III の `Z-ADD` に相当します)。ただし、一次資料(ILE RPG言語リファレンス)によれば、`**FREE`(完全自由形式)以外のソースでは、自由形式の文は**8〜80桁目**に書く決まりで、6〜7桁目(仕様書種別欄とその次)は空白でなければなりません。`V0601B` の中でも、自由形式の文は実際に8桁目から始まっています。1桁目からどこにでも書ける完全自由形式(`**FREE`)とは、この点が違います。それ以外の行(`H`・`F`・`D`・末尾の `C` 2行)は、これまでどおり固定形式の桁位置に従います。

`totalx = %editc(total : '1')` は、04-08 の編集コード(O仕様書38桁目に書く1文字)と同じ働きを、関数呼び出しの形にしたものです。`%EDITC` の第2引数 `'1'` が編集コード1(桁区切りあり)に対応します。04-08 の編集コード早見表によれば、編集コード1は奇数側(ゼロ残高を表示する側)なので、値がゼロでも `.00` のように残ります(04-08参照。ただし `V0601B` の `TOTAL` は `1738.00` で非ゼロなので、この性質自体はここでも実演していません)。

### `V0601A`: サイクルはあるが、自動 `READ` が無い(05-03への回答)

05-03 は、`JU0300`(制御レベル `L1`/`L2`)・`ZA0500`(一致レコード処理 `M1`/`MR`)を読みながら、「サイクル自体・一致レコード処理には、FREE形式でも完全な代替がありません(第6部で確認します)」と予告していました。

`V0601A` の F仕様書を見ると、この問いへのヒントがあります。

```text
     FTOKUIM    IF   E           K DISK
     FJUCHUM    IF   E             DISK
```

05-03 で見た `ZA0500` の F仕様書(`src/legacy/qrpgsrc/za0500.rpg`、RPG III)は、`FJUCHUD IP F 27 DISK`(プライマリー・ファイル、16桁目 `P`)・`FJUCHUM IS F 26 DISK`(セカンダリー・ファイル、16桁目 `S`)のように、**RPG III の**16桁目(ファイル指定欄)に `P` か `S` を持っていました。**`V0601A`(RPG IV)の `TOKUIM`・`JUCHUM` は、どちらも(上の表のとおり RPG IV では18桁目にずれた)ファイル指定欄が `F`(Full procedural、全手続き)です。** `P`(プライマリー)でも `S`(セカンダリー)でもないので、**この2つのファイルは RPG サイクルの自動 `READ` に一切参加しません。** `CHAIN`・`READ` は、どちらも `C` 仕様書の中でプログラムが明示的に呼び出しています。

つまり `V0601A`(そして変換前の `R0408A` 自体)は、**「サイクルの枠組み(`SETON LR` で終わる、という仕組み)は使っているが、制御レベル(`L1`〜`L9`)も一致レコード処理(`M1`/`MR`)も、そもそも自動 `READ` すら使っていない」**という、いわば中間的な書き方です。05-03 が説明した「サイクルの便利な機能」を一切使っていないので、FREE形式へ書き直すときに困る部分(サイクル・一致レコード処理そのもの)が、そもそも `R0408A`/`V0601A` には存在しません。

**この教材は、`JU0300`(05-03で読んだ、制御レベル `L1`/`L2` を使うサイクル・プログラム)を、RPG IV へ移植する回を用意していません。** 05-03 が説明したとおり、サイクル自体・一致レコード処理には FREE形式でも完全な代替がなく、移植するとすれば「明示的な `READ` ループと比較ロジックへの全面書き換え」になります。それは固定形式からの橋渡しを目的とするこの第6部の範囲を超えるため、**`JU0300` は第6部以降で手を加えられることなく、引き続き第5部の RPG III 教材のまま残ります。**(`ZA0500` は05-13でチケット対応として RPG III のまま修正されますが、それも第5部の中の話であり、RPG IV への移植とは別です。)

### IBM Docs で調べる: どちらのリファレンスを見ているか

この教材が一次資料として参照している RPG のマニュアルは、少なくとも2つの別々のものがあります。

- **ILE RPG言語リファレンス** — 第6部以降がこれから使う一次資料。`%` で始まる BIF・D仕様書・`**FREE` を扱います。
- **RPG/400リファレンス** — 第4部・第5部がこれまで使ってきた一次資料。[付録F](../appendix/f-bif-reference.md) で確認したとおり、BIF はゼロ、D仕様書もありません。

**この2つは同じ見出し語(例:「Factor 1」)を使っているため、どちらのマニュアルを開いているか確認せずに読むと、桁位置を取り違えます。** 実際、今しがた見たとおり Factor 1 は RPG III で18〜27桁目、RPG IV で12〜25桁目です。「Factor 1」という同じ言葉が出てきても、開いているのがどちらのマニュアルかで、指している桁位置が変わります。

見分け方をいくつか挙げます。

- **コンパイル・コマンドで見分ける。** ページの例が `CRTRPGPGM` なら RPG/400リファレンス、`CRTBNDRPG`/`CRTRPGMOD` なら ILE RPG言語リファレンスです。
- **D仕様書・`%` で始まる BIF が出てくるかで見分ける。** RPG/400リファレンスには、どちらも存在しません([付録F](../appendix/f-bif-reference.md)参照)。
- **検索語に `ILE RPG` を含める。** 例えば `CHAIN` の RPG IV 側の説明を調べたいときは、単に `RPG CHAIN` ではなく `ILE RPG CHAIN` のように検索語を絞ると、RPG/400リファレンス側のヒットを減らせます。

## 実演

1. 06-01 の `V0601A` が `<USER>1` に存在することを確認します(`WRKOBJPDM LIB(<USER>1) OBJTYPE(*PGM)`)。まだの場合は、先に06-01を済ませてください。
2. `V0601B` を入れるソース・ファイルを作ります(`QRPGLE112` は06-01の `CVTRPGSRC` 専用の変換先なので、手書きのソースは別のソース・ファイル `QRPGLESRC` に入れます)。

   ```text
   CRTSRCPF FILE(<USER>1/QRPGLESRC) RCDLEN(112) TEXT('RPG IV source (hand-written)')
   ```

   すでに `QRPGLESRC` がある場合は `CPF5813`(ファイルは既に存在する、という診断メッセージ)が出た後、コマンド自体を失敗させるエスケープ・メッセージも続けて出ます。`CRTPF` で同種の「既に存在するファイルを作ろうとした」状況を実機確認した `part06-01-cvtrpgsrc` の接続記録では、`CPF5813` の直後に `CPF7302`(`File VFYSPL not created in library …`)というエスケープ・メッセージが続いていました。`CRTSRCPF` 自体でこの組み合わせを実機確認したわけではありませんが、`CRTPF` と同系統のコマンドなので同様のパターンになると考えられます。いずれにせよ、これは想定内の状況(目的のファイルは既に存在している)なので、気にせず次へ進んでください。

3. `WRKMBRPDM FILE(<USER>1/QRPGLESRC)` でメンバー `V0601B`(種別 `RPGLE`)を作り、`src/qrpglesrc/v0601bs.rpgle` と同じ内容を、桁位置に注意しながら入力します(上の「説明」節で示した内容と同じです。`/FREE`...`/END-FREE` の中は8〜80桁目であれば自由に書けます)。
4. コンパイルします。

   ```text
   CRTBNDRPG PGM(<USER>1/V0601B) SRCFILE(<USER>1/QRPGLESRC) SRCMBR(V0601B)
   ```

5. `CALL PGM(V0601B)` を実行し、`WRKSPLF` で `1,738.00`(`R0402A` の実機値と同じ)が印字されていることを確認します。
