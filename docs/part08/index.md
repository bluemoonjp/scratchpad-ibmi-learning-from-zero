# 第8部 モダン開発

## この部の目標

第7部で作った`JUCSRV`・`ZAISRV`(サービス・プログラム)を土台に、**現代的な開発の一通りの流れ**を身につけます。gitによるソース管理・`makei`(TOBi)によるビルド・リンター/CIによる自動検査・自作テストキットによる単体テスト・レガシーの近代化(特性検定→SQLへの書き換え)・DDSからSQL DDLへの移行・IBM iサービスと権限、そして最後に、ブランチ作成から本番昇格・`TXCHECK`・切り戻しまでを1つの流れとして実際に通します(08-08)。個々の技法はほとんどが第5〜7部の既習の応用であり、この部の主眼は新しい構文ではなく、**それらを実際の開発フローとして矛盾なく組み立てること**にあります。

## 前提となる状態

第7部の内容(07-05のチェックポイントまで)が済んでいること。02-04で取り込んだ教材のgitプロジェクト(`myproject`)を、この部から本格的に使い始めます。

## 道具

PC自身のgit/SSHクライアント(ソースの編集・push・pull)、SSH(`makei build`の実行、`CPYFRMSTMF`でのソース取り込み)、5250(コンパイル・実行・確認)、PC自身のnpm/npx(`rpglint`)、SQL(ACSの「実行SQLスクリプト」)。レッスンによって組み合わせが異なります(各レッスンの案内文の「道具」「同時接続数」欄を参照してください)。08-03・08-06・08-07はPUB400へのSSH/5250接続を必須としません。

## この部で自分たちが作る道具

`TESTKIT`(08-04、自作の単体テスト・フレームワーク)。IBM iにはRPGUnitはインストールされておらず、RPG言語自身の`ASSERT-T`命令もこのPUB400のPTFレベルでは未対応であることが実機確認済みのため(08-04参照)、コンパクトな自作品で代替します。

## 観測方法

レッスンごとに異なります。`git log`/`git diff`(pushの前後比較)、`makei build`の標準出力、`rpglint`の出力、`TESTRES`テーブル、`TXSNAP`+`CMPPFM`/SQLの`EXCEPT`(近代化前後の出力比較)、`DSPFD TYPE(*RCDFMT)`と生成されたDDL、SQLの結果セット、`DSPSRVPGM DETAIL(*SIGNATURE)`(シグネチャー数の変化)・`DSPLIBL`・`DSPPGM DETAIL(*SRVPGM)`(08-08)。

## この部で扱わないこと

- RPGUnit・RPG言語自身の`ASSERT-T`命令(このPUB400のPTFレベルでは未対応。08-04参照)。
- `ZAISRVBD`/`JUCSRVBD`という2つのバインディング・ディレクトリーの統合(意図的に別のままにしています。統合するかどうかは第9・10部に持ち越します)。
- `TESTKIT`一式の本番(`<自分のユーザー名>2`)への昇格(08-08が意図的に除外する設計決定。テスト用の道具一式は通常本番へは届けないため)。
- `RESTOBJ`の実際のパラメーター構文、`git push`によるタグのリモートへの送信・確認の往復(いずれも一般知識、要確認・V3のまま。各レッスンの実機メモ参照)。

## 同時接続数

レッスンによって大きく異なります。5250×1のみで完結するもの(08-04)、PC側のgit/SSHクライアントが張る別経路の接続を伴うもの(08-01・08-02・08-08)、PUB400へまったく接続しないもの(08-03の必須手順)、ACS×1のみのもの(08-06・08-07)まであります。各レッスンの案内文の「同時接続数」欄を必ず確認してください。

## 容量の予算

この部で作るオブジェクトはいずれも小さなプログラム・サービス・プログラム・テーブルで、容量を気にする場面はありません。

## 出力が違うとき

- **印刷結果が `WRKSPLF` に出てこない**: 第6・7部と同じ理由(検証ハーネスの非対話SSHジョブでは印刷装置ファイルが実スプール・ファイルにならない)で、学習者自身の5250対話セッションでは通常どおり `WRKSPLF` で確認できます。
- **`TXCHECK`が「確認不能」(`could not query the manifest`)を返す**: 08-08で実機確認された`TXCHECK`(v1)自身の不具合で、同一ジョブ内で2回目に`CALL`すると起こることがあります(原因は特定できていません)。サインオフしてサインオンし直してから打ち直してください。08-08の「説明」・実機メモを参照してください。
- **08-08を実施した場合の注意**: 08-08の実演は共有テーブル `ZAIKOM`(`<自分のユーザー名>1`・`<自分のユーザー名>2`の両方)の中身を書き換えます。演習後は両方に対して必ず `TXRESET` を実行してください。
