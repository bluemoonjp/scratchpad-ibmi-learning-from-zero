# 04-21 固定形式 RPG IV の骨格

> 所要時間: 90分(長め)/ 前提レッスン: 03-14 / 目標番号: 3・5・12 / 観測方法: `WRKSPLF`(帳票・コンパイル・リスト)・`DSPJOBLOG` / 道具: 5250(PDM/SEU)/ 同時接続数: 5250×1 / 作る・変えるオブジェクト: `<USER>1/QRPGLESRC`(無ければ新規作成)にメンバー、`<USER>1/V0421A`・`V0421B`・`V0421C`・`V0421D` / DBVER: 1 / 依存するプローブ: P04, P10 / PTF 依存: なし / 容量の目安: わずか

このレッスンは「第4部V」(固定形式 RPG IV で書く第4部の代替ルート)の最初の1本です。RPG III(第4部・第5部)を通らずに第6部へ進む読者のためのルートで、現場が**固定形式(または固定形式と自由形式の混在)の RPG IV を `CRTBNDRPG` でコンパイルしている**ことを前提にしています。`CRTRPGPGM`(RPG III のコンパイル・コマンド)を使う職場は、この教材の対象外です。

## ゴール

- 固定形式 RPG IV の H・F・D・C・O 仕様書の役割を言い、C 仕様書の主要な桁(12・26・36・50・64・69・71)を言える。`V0421A` を入力し、`CRTBNDRPG` でコンパイルして実行できる(`04-21-1`)。
- `Z-ADD`・`ADD`・`SUB`・`MULT`・`DIV`・`MVR` で計算し、結果フィールドの桁数を超えたときに何が起きるかを説明できる(`04-21-2`)。
- コンパイル・リストの主な節を指さして読み、帳票プログラム `V0421D`(RPG III 版 `R0408A` と同じ出力)を入力・実行できる(`04-21-3`)。

## ウォームアップ

第3部の総復習として始まるため、ウォームアップはありません(RPG III を前提にしないルートの最初のレッスンです)。

## なぜ学ぶか

現場の RPG IV は、教科書どおりの `**FREE` だけではありません。**長年の資産は、固定形式のまま残っているのが普通です。** そうしたソースを読み、直し、新しい処理を足すには、まず固定形式の「どの桁に何を書くか」を体で覚える必要があります。

この教材には、RPG III(第4部・第5部)を経由して第6部へ進むルートと、このレッスンから始まる第4部Vを経由するルートがあります。第4部Vは、**RPG III を一度も書かなくても第6部〜第10部を最後まで終えられる**ように作られています。そのため、RPG III のレッスンで学ぶ内容(仕様書の桁・算術命令・帳票の出力)を、このレッスンでは**RPG IV の桁位置で**学び直します。RPG III のレッスンを済ませているかどうかは、このレッスンの前提ではありません。

このレッスンで作る4本のうち、`V0421A`・`V0421B`・`V0421D` は、RPG III 側の `R0401A`・`R0402A`・`R0408A` と**同じ内容を印刷する**ように作ってあります。同じ出力になるように揃えてあるので、以後のレッスンで「`R0408A` と同じ出力になります」という説明がそのまま使えます。

## 新出

- 中核概念(3つ)
  1. 固定形式は「桁位置がすべて」。同じ1行でも、何桁目に書いたかで意味が決まる(RPG IV の桁位置は、RPG III とは異なる)。
  2. `CRTBNDRPG` と、`H` 仕様書の `DFTACTGRP`。コンパイラーのメッセージは `RNF`・`RNS`(コンパイル時)と `RNQ`・`RNX`(実行時)で始まる。
  3. 変数の宣言には2つの書き方がある。C 仕様書の結果フィールドに長さ・小数桁数を書く(その行が宣言を兼ねる)方法と、D 仕様書(`S` 定義)で先に宣言する方法。結果フィールドに収まらない桁は、既定では警告なく切り捨てられる。
- コマンド(2つ)
  - `CRTSRCPF`(`RCDLEN(112)` のソース物理ファイル `QRPGLESRC` を作る)
  - `CRTBNDRPG`(固定形式 RPG IV のソースをコンパイルして、プログラムを作る)
- 構文(2つ): 算術命令(`Z-ADD`・`ADD`・`SUB`・`MULT`・`DIV`・`MVR`)、D 仕様書の単独変数の定義(`S`)
- 読解用(この上限には数えません): 定型として写す `EXCEPT`(O 仕様書に書いた出力を印刷する)・`SETON`(`LR` 標識を立ててプログラムを終える)と、編集・コンパイルに使う `WRKMBRPDM`(第1部の 01-07 で学習済み)。`V0421D` に出てくる `MOVEL`・`CHAIN`・`READ`・`IFEQ`・`ENDIF`・`GOTO`・`TAG`(次の 04-22・04-23 で書き方を学びます。このレッスンでは桁位置を写して、出力が変わらないことを確かめるだけです)。F 仕様書の外部記述ファイル(`IF E K DISK`)の桁。

## 説明

### RPG の系譜と、固定形式がいまも現役の理由

RPG は、帳票(レポート)を作るために生まれた言語です。IBM i の世界では、大きく次の世代があります。

| 世代 | 呼び名 | コンパイル・コマンド | この教材での扱い |
|---|---|---|---|
| RPG II | RPG III の前の世代 | — | 扱いません |
| RPG III | RPG/400(1988年〜、OPM) | `CRTRPGPGM` | 第4部・第5部。**第4部Vのルートでは通りません** |
| RPG IV | ILE RPG(1994年〜) | `CRTBNDRPG`・`CRTRPGMOD` | **第4部V・第6部以降** |

RPG IV のソースには、書き方による3つの段階があります(段階2・3は第6部で扱います)。

| 段階 | 見た目 |
|---|---|
| 1. 固定形式 | H/F/D/C/O 仕様書すべてが桁位置ベース。**このレッスンはここです** |
| 2. 固定形式+`/FREE` 混在 | C 仕様書の計算部分だけ `/FREE`...`/END-FREE` で自由形式 |
| 3. `**FREE` 完全自由形式 | ソース全体が自由形式 |

固定形式が現場に残っているのは、次のような理由からだと考えられます(この教材が実機で確かめた事実ではなく、一般的な事情の説明です)。

- 長年動いていて業務を支えているプログラムを、書き換えるリスクと手間が大きい。
- 固定形式のソースも、いまの RPG IV コンパイラー(`CRTBNDRPG`)がそのままコンパイルできる。06-01 の `V0601A` は、まさに固定形式のまま実機でコンパイル・実行できたソースです。
- 既存の保守では、既存ソースの書き方に合わせて「1行だけ直す」ことが多く、まず読めなければ手を出せない。

### この教材の前提: RPG III を通っていない

**RPG III のレッスン(第4部・第5部)の知識は、このレッスンでは前提にしません。** 06-01b は、RPG III と RPG IV の桁位置のずれを表にして示していますが、第4部Vの読者にとって RPG III の桁位置は「知らなくてよいもの」です。このレッスンの表は RPG IV の桁位置だけを示します。

**RPG III 側のレッスンの知識と混ぜないでください。** 「Factor 1 は 18 桁目から」のような RPG III の記憶があると、RPG IV の固定形式を書くときに桁を間違えます(後の「出力が違うとき」で、実際に間違えたソースを見ます)。

### 仕様書の種類と並び順

固定形式の RPG IV は、1行が1つの仕様書で、**6桁目の文字がその行の種類**を表します。7桁目に `*` を書くと、その行はコメントです。ソースは次の順に並べる決まりです(一次資料: ILE RPG言語リファレンス、「RPG IV Source Records and Their Order」)。

| 仕様書(6桁目) | 役割 | このレッスンで書くか |
|---|---|---|
| `H` | 制御(プログラム全体の設定) | 書く(`DFTACTGRP`) |
| `F`・`D` | ファイル記述(F)・定義(D)。FとDは混在してよい | F は書く。D は `V0421C` で書く |
| `I` | 入力 | 書かない(外部記述ファイルでは通常不要) |
| `C` | 演算(実際の処理) | 書く |
| `O` | 出力(帳票への出力) | 書く |

RPG III にあった `E`(拡張)・`L`(行カウンター)仕様書は、RPG IV にはありません。D 仕様書は RPG IV で新設された、変数やデータ構造を先に宣言する仕様書です。このレッスンでは、単独の変数を定義する `S` だけを `V0421C` で書きます(データ構造 `DS` は 06-01b で読み方を扱います)。`V0421A`・`V0421B`・`V0421D` は、変数をすべて C 仕様書の結果フィールドで宣言しています(`V0601A` と同じ書き方です)。

### 桁位置の早見表

桁位置は、一次資料(ILE RPG言語リファレンス)の「Specifications」の章にある欄の割り当てと、実機で確認済みの `V0601A`(`src/qrpglesrc/v0601s.rpgle`)の文字位置を突き合わせたものです。

#### C 仕様書(演算)

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     CL0N01Factor1+++++++Opcode(E)+Factor2+++++++Result++++++++Len++D+HiLoEq
```

| 欄 | 桁 | 備考 |
|---|---|---|
| 制御レベル | 7〜8 | 空白、`L1`〜`L9`、`LR`、`SR`(04-25 で扱います) |
| 条件標識 | 9〜11 | 9桁目が `N`(NOT)、10〜11桁目が標識の番号(`99` など) |
| Factor 1 | 12〜25 | 「必ず12桁目から書く」 |
| 命令コード | 26〜35 | 「必ず26桁目から書く」。最後に `(H)` などの拡張を付けられる |
| Factor 2 | 36〜49 | 「必ず36桁目から書く」 |
| 結果フィールド | 50〜63 | |
| 長さ | 64〜68 | 右づめ。結果フィールドを新規に宣言するとき |
| 小数桁数 | 69〜70 | 右づめ。数値のとき |
| 結果標識(HI/LO/EQ) | 71〜76 | 71〜72が HI、73〜74が LO、75〜76が EQ |

「必ず…桁目から書く」は、一次資料の各欄の説明(`The entry must begin in position 12` など)の記述に沿っています。**1桁ずれても、同じ内容を書いたつもりでは通りません。**

#### F 仕様書(ファイル)

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     FFilename++IPEASFRlen+LKlen+AIDevice+.Keywords+++++++++++++++++++++++++++++
```

| 欄 | 桁 | `V0421D` の `TOKUIM` の例 |
|---|---|---|
| ファイル名 | 7〜16 | `TOKUIM` |
| ファイル種別 | 17 | `I`(入力) |
| ファイル指定 | 18 | `F`(全手続き) |
| ファイル形式 | 22 | `E`(外部記述) |
| レコード長 | 23〜27 | (外部記述なので空白。`QSYSPRT` は `132`) |
| レコード・アドレス型 | 34 | `K`(キーでアクセス) |
| 装置 | 36〜42 | `DISK`・`PRINTER` |

`QSYSPRT` の行は、種別 `O`(出力)・ファイル指定は空白・形式 `F`(プログラム記述)・レコード長 `132`・装置 `PRINTER` です。

#### H 仕様書(制御)

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     H DFTACTGRP(*YES)
```

6桁目が `H`、7〜80桁目がキーワードです。次の節で説明します。

#### D 仕様書(定義)

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     DName+++++++++++ETDsFrom+++To/L+++IDc.Keywords+++++++++++++++++++++++++++++
```

名前は7〜21桁目、定義の種類(`S`=単独の変数、`DS`=データ構造)は24〜25桁目、長さは33〜39桁目(右づめ)、内部データ型は40桁目(`P`=パック10進数)、小数桁数は41〜42桁目です。`V0421C` の次の行は、5桁・小数0桁のパック10進数 `NUMA` を宣言します。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     DNUMA             S              5P 0
```

#### O 仕様書(出力。プログラム記述ファイル)

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     OFilename++DF..N01N02N03Excnam++++B++A++Sb+Sa+...........................
     O..............N01N02N03Field+++++++++YB.End++PConstant/editword/DTformat++
```

| 行の種類 | 欄 | 桁 |
|---|---|---|
| レコード行 | ファイル名 | 7〜16 |
| レコード行 | 種別(`E`=例外出力) | 17 |
| 項目行 | フィールド名 | 30〜43 |
| 項目行 | 編集コード | 44 |
| 項目行 | 終了位置(出力行のどの桁で終わるか) | 47〜51(右づめ) |
| 項目行 | 定数(`'...'`) | 53〜 |

### コンパイル: CRTBNDRPG と DFTACTGRP

RPG IV のソースは、`CRTBNDRPG`(束縛プログラムを作る)でコンパイルします。`PDM`(`WRKMBRPDM`)のオプション `14` は、ソース・タイプ `RPGLE` のメンバーに対して、既定でこの `CRTBNDRPG` を実行するとされています(**未検証(2026-10-04時点、V3)**。対話操作の範囲で、非対話の検証バッチでは確認できません)。SEU のマニュアルには、`QRPGLESRC` に作るメンバーのソース・タイプの既定は `RPGLE` と書かれています。

```text
CRTBNDRPG PGM(<USER>1/V0421A) SRCFILE(<USER>1/QRPGLESRC) SRCMBR(V0421A)
```

H 仕様書の `DFTACTGRP(*YES)` は、「このプログラムは、OPM の時代から使われてきた**既定の活動化グループ**(default activation group)で動かす」という指定です。`CRTBNDRPG` の `DFTACTGRP` パラメーターの既定値が `*YES` なので、`H` 仕様書に書かなくても同じ動作になりますが(一次資料: ILE RPG プログラマーの手引き)、「このソースがどの活動化グループで動くか」がソースに残るよう、この教材では書いておきます。第7部では、`DFTACTGRP(*NO)` にして活動化グループ(`ACTGRP`)を選ぶ話に入ります。**`DFTACTGRP(*YES)` のままでは、プロシージャ(自分で定義する手続き)を定義できません**(この教材の実機検証で、`RNF1520` として確認されています。詳しくは `docs/probes.md`)。

`CRTBNDRPG` を実行すると、コンパイル・リストがスプール・ファイルとして出ます。重大度が `00` から `10` のメッセージだけならプログラムは作られ、重大度 `20` 以上のエラーがあると作られません(後者は既定の `GENLVL(10)` を超えたとき。`docs/probes.md`)。

### ソース・ファイル: QRPGLESRC と QRPGLE112

RPG IV のソースは、慣習として `QRPGLESRC` という名前のソース物理ファイルに入れます(01-06 で `QRPGLESRC` の `RCDLEN` を調べました)。ソース物理ファイルのレコードは、順序番号6桁・日付6桁・ソース行(80桁)で `RCDLEN` が 92 です。RPG IV のソース行は100桁目まで書け(81〜100桁目はコメント欄)、`CVTRPGSRC` の変換先は**112桁を推奨**とされているので(一次資料: ILE RPG プログラマーの手引き)、この教材では RPG IV 用のソース物理ファイルを `RCDLEN(112)` で作ります。

このリポジトリーには、`RCDLEN(112)` のソース物理ファイルが2つ登場します。

| ファイル | 使う場面 | 理由 |
|---|---|---|
| `QRPGLESRC` | **手書きの RPG IV ソース**(このレッスンの `V0421A`〜`V0421D`、第6部以降のほとんどのソース) | 通常の置き場所 |
| `QRPGLE112` | 06-01 の `CVTRPGSRC` の変換結果(`V0601A`)専用 | 06-01 が「変換結果」と「手書き」を混在させないために別のファイルにした |

**どちらも `RCDLEN(112)` です。** 名前が違うだけで、ファイルとしての違いはありません。第4部Vのルートでは、`CVTRPGSRC` で変換する元の RPG III プログラム(`R0408A`)がないので、06-01 が前提にする `V0601A` を `QRPGLE112` に用意する作業を 04-27 で行います(作り方はそこで説明します)。

### RPG IV のメッセージ ID の見方

RPG III のコンパイラーは `QRG` で始まるメッセージを、実行時は `RPG0xxx` を出していました(`docs/probes.md`・`verify/README.md` の記録)。RPG IV では、次のように変わります。

| 接頭辞 | いつ出るか | 例 |
|---|---|---|
| `RNF` | コンパイル時の診断メッセージ(ソースの各行・各欄の指摘) | `RNF2318`・`RNF6011`(06-01) |
| `RNS` | コンパイル・ステータスの通知(`RNS9304` は「Program ... placed in library」) | `RNS9304` |
| `RNQ` | 実行時の照会メッセージ(応答を待つ) | (04-24 で実機確認します) |
| `RNX` | 実行時のエスケープ・メッセージ(処理を打ち切る) | `RNX0103`(`TRUNCNBR(*NO)` のときの桁あふれ。ILE RPG プログラマーの手引き) |

[付録B](../appendix/b-message-ids.md)に、このレッスンの範囲を超えるメッセージも含めた一覧があります。`RNQ`・`RNX` を実際に起こす実習は、04-24(呼び出しとデバッグ)で行います。

### 算術命令: Z-ADD・ADD・SUB・MULT・DIV・MVR

固定形式の RPG IV は、`EVAL` のような式を書かず、桁位置に決まった要素を置く命令で計算します(`EVAL` は第6部で学びます)。

| 命令 | 意味 | 書き方 |
|---|---|---|
| `Z-ADD` | 結果フィールドをゼロにしてから Factor 2 を加える(実質は代入) | Factor 2 と結果フィールド |
| `ADD` | Factor 1 + Factor 2 を結果フィールドへ。Factor 1 を空白にすると、結果フィールド + Factor 2 を結果フィールドへ | |
| `SUB` | Factor 1 - Factor 2 を結果フィールドへ | |
| `MULT` | Factor 1 × Factor 2 を結果フィールドへ | |
| `DIV` | Factor 1 ÷ Factor 2 の商を結果フィールドへ | Factor 2 が 0 だとエラーになる |
| `MVR` | 直前の `DIV` の余りを結果フィールドへ | Factor 1・Factor 2 は空白。**直前の命令が `DIV` でなければならない** |

`DIV` は余りを捨てるので、余りがほしいときは `DIV` の**すぐ次の行**に `MVR` を書きます(一次資料: ILE RPG言語リファレンス、`DIV`・`MVR` の項)。

結果フィールドの長さ(64〜68桁目)と小数桁数(69〜70桁目)に値を書くと、その行がそのフィールドの宣言を兼ねます。`V0421B` の次の行は、`PRICE`・`RATE`・`TOTAL` を、このやり方で宣言しています(`V0421C` は、同じ型の変数を D 仕様書で宣言します)。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     C                   Z-ADD     1580          PRICE             7 2
     C                   Z-ADD     1.10          RATE              3 2
     C     PRICE         MULT      RATE          TOTAL             9 2
```

1行目は、命令コード `Z-ADD` が26桁目、Factor 2 の `1580` が36桁目、結果フィールドの `PRICE` が50桁目、長さ `7` が68桁目、小数桁数 `2` が70桁目です。

**結果フィールドに収まらない桁は、既定では警告なく切り捨てられます。** `CRTBNDRPG` の `TRUNCNBR`(桁あふれ時の動作)の既定値が `*YES` で、固定形式の演算では、あふれた上位の桁を落とした値が結果フィールドに入ります(一次資料: ILE RPG プログラマーの手引き、ILE RPG言語リファレンスの `Ensuring Accuracy`)。`TRUNCNBR(*NO)` にすると、桁あふれは実行時エラー(エラー・コード `RNX0103`)になります。なお、この `TRUNCNBR` の規則は固定形式の演算命令についてのもので、`EVAL` のような式の中の計算には当てはまりません(式の中での桁あふれは、実行時にメッセージが出ます)。

`MULT` の結果フィールドの長さは、Factor 1 の長さと Factor 2 の長さの和があれば足ります(一次資料の説明)。`V0421B` の `TOTAL` は、`PRICE`(7桁)と `RATE`(3桁)の積を入れるので `9`(小数2桁)としています。

### O 仕様書と編集コード

`V0421B` の最後の行は、`TOTAL` を印刷する O 仕様書です。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     OQSYSPRT   E
     O                       TOTAL         1     20
```

1行目はレコード行で、`QSYSPRT`(7桁目〜)と、種別 `E`(17桁目)です。`E` は、C 仕様書の `EXCEPT` 命令で印刷される出力を表します。2行目が項目行で、フィールド名 `TOTAL` が30桁目、編集コード `1` が44桁目、終了位置 `20` が50〜51桁目です。**「終了位置」は、印刷行のどの桁で項目が終わるかを表します。** 編集コード `1` で編集した `1738.00` は `1,738.00`(8文字)になるので、13〜20桁目に印刷されます。

編集コード `1` は、桁区切りのコンマを付け、小数点を付け、値がゼロのときも表示を残す側です。編集コードは RPG IV の O 仕様書でも44桁目に書きます(一次資料: ILE RPG言語リファレンス、`Position 44 (Edit Codes)`)。編集コード `3` は、桁区切りがなく、ゼロのときの表示は残す側です(コード `2`・`4` は、ゼロのとき空白にします)。

文字の定数(`'HELLO, RPG III!'` のようなもの)は、53桁目から引用符で囲んで書き、終了位置を50〜51桁目に書きます。`V0421A` の定数は、終了位置 `20` で、**6桁目から**始まって20桁目で終わります。

### コンパイル・リストの読み方

コンパイル・リストには、次の節が(この順で)出ます(一次資料: ILE RPG プログラマーの手引き、付録D「コンパイラー・リスト」)。

| 節 | 内容 |
|---|---|
| Prologue(プロローグ) | コマンドのオプションの一覧(`CRTBNDRPG` の各パラメーターの値) |
| Source Listing(ソース・リスト) | ソースの各行に行番号を付けたもの。その行に対するエラー・メッセージも行の直後に出る |
| Additional Diagnostic Messages | 複数行にまたがるエラー(ある場合だけ) |
| Cross-Reference Table(相互参照表) | ファイル・フィールド・標識が、どの行で使われているかの一覧 |
| Message Summary(メッセージ要約) | 出たメッセージの ID と回数の一覧 |
| Final Summary(最終要約) | メッセージの重大度ごとの件数と、最終メッセージ(プログラムが作られたかどうか) |

`V0601A`(`CVTRPGSRC` の変換結果で、`V0421D` とほぼ同じ内容の固定形式ソース)を実機でコンパイルしたときの Message Summary には、06-01 のとおり、次のメッセージが出ていました(すべて重大度 `00`、情報レベル)。

- **`RNF2318`**(F 仕様書の `QSYSPRT` の行): 「Overflow indicator *INOA is assigned to PRINTER file QSYSPRT.」。オーバーフロー標識を書かなかったので、コンパイラーが自動的に `*INOA` を割り当てた、という意味です。
- **`RNF6011`**(O 仕様書の先頭行): 「The Space and Skip entries are blank and no PRTCTL keyword specified; Space-After defaults to 1.」。改行指定を書かなかったので、1行改行が既定になった、という意味です。
- そのほか `RNF7031`(5件)・`RNF7066`(2件)・`RNF7086`(1件)が出ていました。

この2つ(`RNF2318`・`RNF6011`)は、プログラムの動作に影響しない情報メッセージです。印刷ファイル `QSYSPRT` を `PRTCTL` なしで使う限り、このレッスンの `V0421A`〜`V0421D` でも同じメッセージが出ます(**実機で確認(part04v-21cmp、2026-10-04)**。4本とも Message Summary に `RNF2318`(1件)と `RNF6011`(1件)が重大度 `00` で出ました。`V0421D` には、さらに `RNF7031`(5件)・`RNF7066`(2件)・`RNF7086`(1件)も出ました。「実機メモ」にも記録します)。リストを読むときは、まず Final Summary の最終メッセージで「プログラムが作られたか」を確認し、エラーがあれば Source Listing のその行を見ます。

### SEU についての注意(`**FREE` と、PDM/SEU の基本操作)

**SEU(第1〜5部で使ってきたソース編集ツール)は、`**FREE`(完全自由形式)を正しく扱えないと一般に言われています。** SEU の構文検査が古い世代の RPG IV 相当で止まるため、とされますが、この教材ではまだ実機の対話式 SEU セッションで確認できていません(**未検証**)。固定形式のソース(このレッスンの4本)は SEU で書けます。`**FREE` を書く第6部からは、VS Code(Code for i。06-02)に切り替えます。

固定形式の RPG IV を SEU で編集するときの基本操作は、次のとおりです(PDM と SEU の基本操作は 01-07 で学習済みです)。

- `WRKMBRPDM FILE(<USER>1/QRPGLESRC)` で一覧を開き、`F6` で新規メンバーを作る。ソース・タイプは `RPGLE`。**ソース・タイプを `RPG` にすると RPG III のつもりで扱われるので、必ず `RPGLE` にします。**
- 既存のメンバーはオプション `2`(編集)。保存は `F3`、コンパイルは一覧でオプション `14`。
- SEU の**桁表示**: 行番号の領域に `COLS` と入力して Enter を押すと、その行の上に桁を示す目盛りの行が出ます(一次資料: SEU のマニュアル「Displaying a Columns Line」)。左右にスクロールしても桁番号が追従します。
- SEU の**プロンプト**: 編集したい行にカーソルを合わせて `F4` を押すと、その行を仕様書の欄ごとに分けたプロンプトで編集できます(`P` や `IP` の行コマンドでも同じです)。桁を自分で数えなくても、欄に値を入れれば正しい桁に入ります。固定形式の桁を数え間違えそうなときは、`F4` を使ってください。

SEU の `F4` プロンプトの画面の細かい表示は、このレッスンでは実機確認していません(**未検証(2026-10-04時点、V3)**。一次資料の SEU のマニュアルは1990年代の版で、RPG IV のプロンプトの内容までは書かれていません)。

## 実演

### 準備: ソース物理ファイルを作る

1. `<USER>1` に、手書きの RPG IV ソースを入れるソース物理ファイルを作ります。

   ```text
   CRTSRCPF FILE(<USER>1/QRPGLESRC) RCDLEN(112) TEXT('RPG IV source (hand-written)')
   ```

   すでに `QRPGLESRC` がある場合は、`CPF5813`(ファイルは既に存在する、という診断メッセージ)のあとにコマンド自体を失敗させるメッセージが続きます。想定内なので、気にせず次へ進んでください(06-01b と同じ状況です)。既存のファイルの `RCDLEN` が `92` の場合も、このレッスンのソース(80桁以内)は入力できます。`DSPFD FILE(<USER>1/QRPGLESRC) TYPE(*ATR)` で確認できます。

### V0421A: 最初の1本(R0401A と同じ出力)

1. `WRKMBRPDM FILE(<USER>1/QRPGLESRC)` を開き、`F6` でメンバー `V0421A`(ソース・タイプ `RPGLE`)を作ります。
2. 次を、桁位置に注意しながら入力します(`src/qrpglesrc/v0421s.rpgle` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * V0421A - minimal fixed-form RPG IV: print one line via EXCEPT.
         * Same printed line as R0401A (RPG III, lesson 04-01).
         * Part 4V lesson 04-21. Compile: CRTBNDRPG (see the lesson).
        H DFTACTGRP(*YES)
        FQSYSPRT   O    F  132        PRINTER
        C                   EXCEPT
        C                   SETON                                        LR
        OQSYSPRT   E
        O                                           20 'HELLO, RPG III!'
   ```

   上の目盛り(`....+....1`)の1桁目が、ソースの1桁目です。`H`・`F`・`C`・`O` は6桁目、コメントの `*` は7桁目に来ます。

   - 1〜3行目はコメント(7桁目が `*`)。
   - `H` 行は H 仕様書(制御)。
   - `FQSYSPRT` の行は F 仕様書。`QSYSPRT`(印刷装置ファイル)を、出力(17桁目の `O`)・プログラム記述(22桁目の `F`)・レコード長 `132`・装置 `PRINTER` で宣言します。
   - `C ... EXCEPT` は、出力の命令。`SETON ... LR`(結果標識の欄71〜72桁目に `LR`)は、プログラムを終わらせる命令です。
   - `OQSYSPRT   E` と、次の行が O 仕様書。例外出力(`E`)のレコードと、その中の項目(定数 `'HELLO, RPG III!'`、終了位置20)です。

   **`SETON LR` を忘れると、プログラムが終わらず暴走します**(RPG のサイクルは第4部Vの 04-25 で扱います。印刷を伴うプログラムでは、スプール・ファイルが大量に作られ続けます)。もし止まらなくなったら、`System Request`(または `Attn` キー)から `2`(ジョブの表示)を選び、コマンド行から `ENDJOB` してください。作られすぎたスプールは `WRKSPLF` から `4`(削除)で片付けます。

   RPG III 版の `R0401A` と同じ文言(`HELLO, RPG III!`)を印刷するようにしてあるのは、「同じ出力になる」ことを確かめられるようにするためです。演習 1 で自由に変えます。

3. `F3` で保存し、`WRKMBRPDM` の一覧でオプション `14`(コンパイル)を実行します。または次のコマンドを実行します。

   ```text
   CRTBNDRPG PGM(<USER>1/V0421A) SRCFILE(<USER>1/QRPGLESRC) SRCMBR(V0421A)
   ```

4. `WRKSPLF` でコンパイル・リストを開き、「説明」節で示したプロローグ・ソース・リスト・メッセージ要約・最終要約を探します。Highest Severity が `00` であることを確認します(**実機で確認(part04v-21cmp、2026-10-04)**。最終メッセージは `RNS9304: Program V0421A placed in library ... 00 highest severity.` でした。`H DFTACTGRP(*YES)` の行もそのまま受け付けられました)。
5. `CALL PGM(<USER>1/V0421A)` を実行し、`WRKSPLF` で `HELLO, RPG III!` が印刷されたことを確認します。

### V0421B: 算術と編集コード(R0402A と同じ出力)

1. メンバー `V0421B`(`RPGLE`)を作り、`src/qrpglesrc/v0421bs.rpgle` と同じ内容を入力します。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * V0421B - C-spec columns and arithmetic (tax-inclusive price).
         * Same printed line as R0402A (RPG III, lesson 04-02): 1,738.00
         * Fields are defined on the C spec itself (length cols 64-68,
         * decimals cols 69-70), the same idea as RPG III but other columns.
        H DFTACTGRP(*YES)
        FQSYSPRT   O    F  132        PRINTER
        C                   Z-ADD     1580          PRICE             7 2
        C                   Z-ADD     1.10          RATE              3 2
        C     PRICE         MULT      RATE          TOTAL             9 2
        C                   EXCEPT
        C                   SETON                                        LR
        OQSYSPRT   E
        O                       TOTAL         1     20
   ```

   `PRICE`(単価 `1580`)に `RATE`(税率 `1.10`)を掛けて `TOTAL`(9桁、小数2桁)に入れ、編集コード `1` で印刷します。

2. コンパイルし(`CRTBNDRPG PGM(<USER>1/V0421B) SRCFILE(<USER>1/QRPGLESRC) SRCMBR(V0421B)`)、`CALL PGM(<USER>1/V0421B)` を実行します。`WRKSPLF` で、`1,738.00` が13〜20桁目に印刷されていることを確認します(**実機で確認(part04v-21cmp、2026-10-04)**。コンパイルは Highest Severity `00`、印刷は `1,738.00` で、右端が20桁目に揃いました)。

### V0421C: 算術命令を一通り

1. メンバー `V0421C`(`RPGLE`)を作り、`src/qrpglesrc/v0421cs.rpgle` と同じ内容を入力します。10個の変数を D 仕様書で宣言し(C 仕様書の結果フィールドに長さは書きません)、`NUMA`=10・`NUMB`=3 に対して、`ADD`・`SUB`・`MULT`・`DIV`+`MVR`、Factor 1 を空白にした `ADD`、桁あふれ(`99999` × 10 を5桁の結果フィールドへ)を実行し、1行にまとめて印刷します。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
        DNUMA             S              5P 0
        DNUMB             S              5P 0
        DSUMV             S              5P 0
        (DIFV・MULV・QUOV・REMV・CNTV・BIGV・OVFV も同じ形)
        C                   Z-ADD     10            NUMA
        C                   Z-ADD     3             NUMB
        C     NUMA          ADD       NUMB          SUMV
        C     NUMA          SUB       NUMB          DIFV
        C     NUMA          MULT      NUMB          MULV
        C     NUMA          DIV       NUMB          QUOV
        C                   MVR                     REMV
        C                   Z-ADD     41            CNTV
        C                   ADD       1             CNTV
        C                   Z-ADD     99999         BIGV
        C     BIGV          MULT      10            OVFV
   ```

   上は D・C 仕様書の中核部分の抜粋です(`(...)` の行はソースの行ではありません)。H・F・O 仕様書とコメントを含む全文は `src/qrpglesrc/v0421cs.rpgle` にあります。

2. コンパイルして実行します。印刷される行は次のとおりです(**実機で確認(part04v-21cmp、2026-10-04)**。コンパイルは Highest Severity `00` で、D 仕様書の `5P 0` の宣言と `MVR` の組み合わせも問題なく動きました)。

   ```text
   SUM=   13 DIF=    7 MUL=   30 QUO=    3 REM=    1 CNT=   42 OVF=99990
   ```

   `OVF=99990` は、`99999 × 10 = 999990` の上位の桁(先頭の `9`)が、結果フィールド `OVFV`(5桁)に入りきらずに落ちた結果です。メッセージは何も出ていません(`TRUNCNBR` の既定値が `*YES` のため)。

### V0421D: 帳票(R0408A と同じ出力)

1. 前提として、第2部で作ったサンプル・データベース(`TOKUIM`・`JUCHUM`)が、ライブラリー・リスト(`*LIBL`)から見える状態にしておきます。
2. メンバー `V0421D`(`RPGLE`)を作り、`src/qrpglesrc/v0421ds.rpgle` と同じ内容を入力します。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
         * V0421D - JUCINQ3 as fixed-form RPG IV: order list for one customer.
         * Same printed lines as R0408A (RPG III, lesson 04-08).
         * Hand-written equivalent of CVTRPGSRC output (V0601A, lesson 06-01).
        H DFTACTGRP(*YES)
        FTOKUIM    IF   E           K DISK
        FJUCHUM    IF   E             DISK
        FQSYSPRT   O    F  132        PRINTER
        C                   MOVEL     'C00001'      CUST              6
        C     CUST          CHAIN     TOKUIM                             99
        C   99              MOVEL     'NOTFOUND'    TOKNM
        C     LOOP          TAG
        C                   READ      JUCHUM                                 98
        C   98              GOTO      ENDLP
        C     JUTOK         IFEQ      CUST
        C                   EXCEPT
        C                   ENDIF
        C                   GOTO      LOOP
        C     ENDLP         TAG
        C                   SETON                                        LR
        OQSYSPRT   E
        O                       TOKNM               30
        O                                           32 '  '
        O                       JUNO                38
        O                                           40 '  '
        O                       JUDATE              48
   ```

   `CUST`(得意先コード、ここでは `'C00001'` に固定)を `TOKUIM` から `CHAIN` で探して得意先名を取得し、`JUCHUM` を先頭から順に `READ` して、**得意先コードが一致する注文だけ**を印刷します。**F・C・O 仕様書の行は、06-01 で `CVTRPGSRC` が作った `V0601A` と、桁位置まで同じです。** 違いは、`H` 仕様書の `DFTACTGRP(*YES)` を足していることと、コメントだけです。`CHAIN`・`READ`・`IFEQ`・`GOTO`・`TAG`・`MOVEL` の意味は 04-22・04-23 で学びます。ここでは桁を写して、出力が `R0408A` と同じになることを確かめます。

3. コンパイルして実行し、次のように印刷されることを確認します。

   ```text
   ACME TRADING CO                 J00001  20260901
   ACME TRADING CO                 J00003  20260905
   ```

   この2行は、`R0408A`(04-08)と `V0601A`(06-01)の出力と同じです。**`V0421D` 自体のコンパイル(Highest Severity `00`)と実行結果は、実機で確認しました(part04v-21cmp、2026-10-04)。** `H DFTACTGRP(*YES)` を足しても、`V0601A` と同じ2行が印刷されました。

## 出力が違うとき

`V0421W` の C 仕様書(RPG III の桁位置のつもりで書いた行):

## 演習

答えは `solutions/04-21/` にあります(ソースは見る前に自分で書いてみてください)。

1. (例題を変える)`V0421A` の文字列を、自分の好きな文言に変えて、再コンパイル・実行してください。次に、終了位置の `20` を `40` に変えて、文字列が印刷される位置がどう変わるか確認してください。ヒント: 終了位置は「項目が終わる桁」です。文字列の長さと終了位置から、開始位置が決まります。
2. (予想してから試す)`V0421B` の `TOTAL` の長さを `9` から `4`(小数2桁のまま。整数部は2桁)に縮めると、`1738.00` はどう印刷されるか予想してから、試してください。ヒント: `TRUNCNBR` の既定値は `*YES` です。落ちるのは上位の桁です。答え: [`solutions/04-21/v0421b-overflow.rpgle`](../../solutions/04-21/v0421b-overflow.rpgle)(`38.00` になります。**実機で確認(part04v-21cmp、2026-10-04)**。コンパイルは Highest Severity `00` で、桁あふれのメッセージは出ず、上位の桁が黙って落ちました)。
3. (別の得意先)`V0421D` の `'C00001'` を `'C00003'` に変えて、再コンパイル・実行してください。ヒント: 変える行は最初の C 仕様書の `MOVEL` の1行だけです。答え: [`solutions/04-21/v0421d-c00003.rpgle`](../../solutions/04-21/v0421d-c00003.rpgle)(得意先 `C00003` の注文の行が印刷されます。サンプル・データでは `J00004`・`J00008` の2行です。**実機で確認(part04v-21cmp、2026-10-04)**。印刷は `BLUE OCEAN INC` の `J00004`(20260906)・`J00008`(20260912)でした)。
4. (間違い探し)「出力が違うとき」の `V0421W`〜`V0421Z` をそれぞれ入力してコンパイルし、メッセージが付いた行を指さして、原因を1行で説明してください。直した版は `V0421B` です。ヒント: C 仕様書は、Factor 1 が12桁目、命令コードが26桁目、Factor 2 が36桁目、結果フィールドが50桁目です。
5. (発展)`V0421C` の `DIV` の Factor 2 を、`NUMB` ではなく `0` にしたとき何が起きると考えますか。ゼロ除算は実行時エラーになると考えられますが、ILE RPG でのメッセージ ID と挙動(応答待ちになるか)はこのレッスンでは**未検証(2026-10-04時点)**です(`part04v-21cmp` は非対話のバッチで、ゼロ除算の実行は含んでいません)。**応答待ちのメッセージが出る可能性があるので、5250 の対話ジョブでだけ試してください。** この実習の続きは 04-24 で扱います。

## 実機メモ

- **実機で確認(part04v-21cmp、2026-10-04、V2)。** このレッスンのソース(`V0421A`・`V0421B`・`V0421C`・`V0421D`、演習の答え `V0421S`・`V0421T`)は、すべて `CRTBNDRPG`(`H DFTACTGRP(*YES)` つき)で Highest Severity `00` でコンパイルでき、`CALL` の印刷は次のとおりでした: `V0421A`=`HELLO, RPG III!`、`V0421B`=`1,738.00`、`V0421C`=`SUM=   13 DIF=    7 MUL=   30 QUO=    3 REM=    1 CNT=   42 OVF=99990`、`V0421D`=`ACME TRADING CO` の `J00001`・`J00003`、`V0421S`=`38.00`、`V0421T`=`BLUE OCEAN INC` の `J00004`・`J00008`。
