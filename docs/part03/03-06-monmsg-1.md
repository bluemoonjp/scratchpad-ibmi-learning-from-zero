## なぜ学ぶか

01-03 で、失敗するとメッセージが出ることを学びました。CL プログラムの中では、そのメッセージを**エラーとしてプログラムを止める代わりに、捕まえて対処する**ことができます。これが `MONMSG` です。他の言語の `try`/`except`(`try`/`catch`)に近い働きですが、**捕まえる対象がメッセージID**という点が特徴です。

## 新出

- `MONMSG`(コマンド・レベル。直前の1つのコマンドだけを監視する)
- `EXEC(DO)` での対処の書き方
- `CPF9800` のような範囲指定(下2桁を `00` にすると、その範囲すべてを捕まえる)

## 説明

`MONMSG MSGID(メッセージID) EXEC(実行する内容)` を、あるコマンドの直後に書くと、そのコマンドがそのメッセージIDで失敗したときに、指定した内容を実行します。これを**コマンド・レベルの MONMSG**と呼びます(直前の1つのコマンドだけが対象です。プログラム全体を監視する**プログラム・レベル**は、次のレッスン 03-07 で学びます)。

`CPF9800` のように、末尾を `00` にすると、`CPF9801` から `CPF9899` までの**範囲**をまとめて捕まえられます。**`CPF0000` は、あらゆる `CPF` メッセージを捕まえる、最も広い指定です。** 自分で書くプログラムでは使う場面がありますが、既存コードで見かけたときに「あらゆるエラーを飲み込んでいる」と読めれば十分です(過度に広い範囲の使用は、本当のエラーまで隠してしまう危険があるため、第5部で問題点として扱います)。

### なければ作る、というパターン

`CHKOBJ` でオブジェクトの存在を確認し、見つからなかった(`CPF9801`)ことを `MONMSG` で捕まえて、その中で `CRTDTAARA` のような作成コマンドを実行する、というのはよく使うパターンです。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QCLSRC)` で `C0306A`(`CLP`)を作る。
2. 次を入力する(`src/qclsrc/c0306s.clp` と同じです)。

   ```clp
   PGM
   DCL        VAR(&LIB) TYPE(*CHAR) LEN(10) VALUE('*CURLIB')
   DCL        VAR(&FOUND) TYPE(*LGL) VALUE('1')

   CHKOBJ     OBJ(&LIB/JUNODA) OBJTYPE(*DTAARA)
   MONMSG     MSGID(CPF9801) EXEC(CHGVAR VAR(&FOUND) VALUE('0'))

   IF         COND(&FOUND) THEN(SNDPGMMSG MSG('JUNODA already +
                exists. Nothing to do.'))
   ELSE       CMD(DO)
      SNDPGMMSG  MSG('JUNODA not found. Creating it.')
      CRTDTAARA  DTAARA(&LIB/JUNODA) TYPE(*DEC) LEN(6 0) VALUE(0) +
                   TEXT('Next order number')
   ENDDO

   ENDPGM
   ```

3. コンパイルして1回目の `CALL PGM(C0306A)` を実行する。「見つからない → 作成」のメッセージが出るはずです。
4. もう一度 `CALL PGM(C0306A)` を実行する。今度は「既にある」のメッセージが出るはずです(`JUNODA` は既に作られているため)。

## 演習

1. `MONMSG` を一時的に外して(コメントアウトして)再コンパイルし、`JUNODA` が既に存在する状態で `CALL` すると、`CHKOBJ` の失敗ではなく **成功**扱いになる(=何も起きない)ことを確認してください。今度は `JUNODA` を `DLTOBJ OBJ(<自分のユーザー名>1/JUNODA) OBJTYPE(*DTAARA)` で消してから同じプログラムを呼び、未処理のエラー(`CPF9801`)でプログラムが異常終了する様子を観察してください。その後、`MONMSG` を元に戻してください。
2. `CPF9801` の代わりに `CPF9800`(範囲指定)にしても同じように動くか確認してください。
