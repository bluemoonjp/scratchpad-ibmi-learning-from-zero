## 説明(Windows / Linux との比較)

Windows のバッチ・ファイル(`.bat`)や Linux のシェル・スクリプト(`.sh`)は、**そのまま実行(インタープリット)されます。** 書いたテキストが、実行時にそのまま解釈されます。CL は違います。**書いたソースを一度コンパイルして、プログラム・オブジェクト(`*PGM`)にしてから実行します。** これは、01-06 で学んだ「ソースとオブジェクトの分離」という IBM i の基本的な設計です。

### コンパイル・リストの重大度

コンパイル時に問題が見つかると、コンパイル・リストに、重大度(severity)付きのメッセージが表示されます。

| 重大度 | 意味 |
|---|---|
| 0〜9 | 情報(問題ではない) |
| 10〜19 | 警告(動くが注意が必要) |
| 20〜29 | エラー(その部分は無視される、または既定値で処理される) |
| 30以上 | 重大なエラー(プログラムは作成されない) |

**「コンパイルできた」は、重大度が閾値(既定では30未満)に収まったという意味であり、ロジックが正しいことの証明ではありません。** 実際に実行して確かめる習慣が大切です。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QCLSRC)` を開き、`F6` で `C0301A`(ソース・タイプ `CLP`)を作る。
2. 次の内容を入力する(`src/qclsrc/c0301s.clp` と同じ内容です。**わざと1か所、間違いが入っています**)。

   ```clp
   PGM
   DCL        VAR(&VAL) TYPE(*CHAR) LEN(10)
   RTVSYSVL   SYSVAL(QDATFMT) RTNVAR(&VAL)
   SNDPGMMSG  MSG('Date format: ' *CAT &VAL)
   ENDPGM
   ```

3. `F3` で保存し、オプション `14` でコンパイルする。**コンパイル・リストにエラーが出ます。**
4. コンパイル・リストを読み、重大度と、どの行が問題かを確認する。
5. 原因(コマンド名の綴り間違い: `RTVSYSVL` → 正しくは `RTVSYSVAL`)を見つけ、SEU で修正する。SEU の `F14`(検索・置換オプション画面を開く)で `RTVSYSVL` を検索すると、素早く見つけられます。
6. 修正後、再コンパイルし、重大度が下がって(エラーがなくなって)プログラムが作成されることを確認する。
7. `CALL PGM(C0301A)` を実行し、`DSPJOBLOG` で `SNDPGMMSG` のメッセージが記録されていることを確認する。

## 演習
