## なぜ学ぶか

**ここから、00-01 で紹介した「受注照会」の通し例(2段階目)を実装します。** 02-06 で SQL 版を作りました。ここでは、同じ用件を CL の `DCLF`/`RCVF` で実装し、SQL 版と結果を照合します。同時に、**CL には「キーで直接1件を探す」機能(RPG の `CHAIN` に相当するもの)がない**ことを体験し、これが第4部で RPG III を学ぶ動機の1つになります。

## 新出

- `DCLF`(データベース・ファイルを宣言する。1プログラムにつき最大5つ)
- `RCVF`(1レコードを読む)
- `CPF0864`(ファイルの終わりを表すメッセージ)

## 説明

`DCLF FILE(ファイル名)` を書くと、そのファイルのフィールドが、**フィールド名と同じ名前の CL 変数として自動的に宣言されます**(例えば `JUTOK` というフィールドがあれば、`&JUTOK` という変数が自動的に使えるようになります)。`RCVF` を実行するたびに、次の1レコードが読まれ、それらの変数に値が入ります。

**ファイルの終わりまで読むと、`CPF0864`(のようなメッセージ)が返ります。** これを `MONMSG` で捕まえて、ループを終える合図にします。

### CL には CHAIN がない

RPG(第4部で学びます)には、キーを指定して**1件だけ**をピンポイントで読む `CHAIN` という命令があります。**CL にはこれに相当するものがありません。** `DCLF`/`RCVF` は、順番に読んでいくことしかできません。キー付き論理ファイル(02-08)を通せばキー順に読めますし、`OVRDBF` の `POSITION` で読み始める位置を指定することもできますが、**「この得意先番号のレコードだけを直接取り出す」ことはできません。** 欲しいレコードにたどり着くまで、順に読み飛ばす必要があります。これが、この先 RPG(第4部)を学ぶ大きな動機の1つです。

## 実演

1. `WRKMBRPDM FILE(<自分のユーザー名>1/QCLSRC)` で `JUCINQC`(`CLP`)を作る。

   ```clp
   PGM        PARM(&TOKCD)

   DCLF       FILE(JUCHUM)
   DCL        VAR(&TOKCD) TYPE(*CHAR) LEN(6)
   DCL        VAR(&JUDATEC) TYPE(*CHAR) LEN(8)

   LOOP:      RCVF
   MONMSG     MSGID(CPF0864) EXEC(GOTO CMDLBL(END))

   IF         COND(&JUTOK *NE &TOKCD) THEN(GOTO CMDLBL(LOOP))

   CHGVAR     VAR(&JUDATEC) VALUE(&JUDATE)
   SNDPGMMSG  MSG(&JUNO *BCAT %TRIM(&JUDATEC))
   GOTO       CMDLBL(LOOP)

   END:       ENDPGM
   ```

2. コンパイルする。
3. コマンド行から直接ではなく、次のような小さな CL(または SEU の別メンバー)経由で呼び出す(03-08 で学んだ安全な `CALL` の仕方です)。あるいは、`CALL PGM(JUCINQC) PARM('C00001')` のように文字リテラルを直接渡して試し、正しく動くか確認してください(文字リテラルは今回問題になりにくいですが、確認する習慣をつけましょう)。
4. `DSPJOBLOG` で、得意先 `C00001` の受注番号と日付が表示されることを確認する。02-06 の SQL 版の結果(`J00001` と `J00003`)と一致するはずです。
