## この部の目標

第0部から第9部まで、あなたは7つの目標を1つずつ積み上げてきました。第10部は、それを**1つの題材で通しで使う**仕上げです。新しい概念は、ほとんど出てきません。代わりに、各レッスンの演習が厚く、ヒントが段階的に置いてあります。試されるのは、次の4つの場面で、これまでの技法を正しい順序で、途切れずに使えるかどうかです。

- 10-01(課題A 運用): 本番役の旧システムで、あるバッチ・ジョブが帳票を出さなくなった。原因を突き止め、安全に復旧し、障害報告書を書く。
- 10-02(課題B 保守): 得意先ファイル`TOKUIM`に項目`TOKYSN`(与信限度額)を足し、影響を調べ、変更し、`JU0300`に与信超過の印を付け、移送と切り戻しの手順を書く。
- 10-03(課題C 近代化・課題D 開発基盤): 旧式の`ZA0500`を、`**FREE`・埋め込みSQL・`ZAISRV`に置き換える。旧版と同じ結果になることを示し、git・makei・リント・テストで「誰でも作り直せる」形に整える。
- 10-04(課題E API): 受注の照会・受注の登録・郵便番号の検証(既定はモック)の3つの操作を、1つのAPIとして公開する設計書を書き、低在庫アラート(手で実行する問い合わせ)とIFSへの書き出しの部品をつなぐ。

**必須の点検項目(3つ。どの目標にも共通)**:

1. **ソースにライブラリー名で修飾した記述がない。** 自分が書いたソース(`ZA0500`・テスト・SQLの`.sql`ファイル)に、自分のライブラリー名を書き込まない(`*LIBL`で解決する)。レッスン本文でコマンドを入力するときの修飾は、この点検の対象外です。SQLのビューが別の自作ルーチンを呼ぶ場合、`RUNSQLSTM`では未修飾の名前が`SQL0204`になりました(2026-09-30、V2、`part10-04-checkpoint`)。そのときはビューに問い合わせを直接書く形にして、修飾を避けてください。
2. **ソースがASCIIだけで書かれている。** コメントも英語で、CCSID 273で位置が変わる文字(`@ # $ [ ] { } | ! \ ^ ~`)に頼らない([スタイル・ガイド](../style-guide.md)の「配布ソースの文字・書式」)。
3. **片付けを終えている。** 下の「片付け」の表のとおり、作ったものを消し、データを元に戻した。

### 確認の範囲に関する注意

- 検証は非対話のSSHだけです。5250の画面でスプール・ファイルを読む操作(`WRKSPLF`・`DSPSPLF`)は、V3です。「12行が一致する」の確認は、実際のスプール・ファイルどうしではなく、検証の仕組みが取り込んだ印刷テキストの比較です。`TXSNAP`は、非対話のSSHの検証で`CPF3303`(`QSYSPRT`が見つからない)になり、動きませんでした(2026-09-30、V2、`part10-02-tokuim`)。5250の対話ジョブでの動作は未検証(V3)です。`CMPPFM`は未確認(V3)です。10-02の前後の比較は、`TXSNAP`に頼らず`SELECT`で件数と列を確かめる形にしてください。
- 他のジョブのスプール・ファイルを`SPOOLED_FILE_DATA`で読む方法は、名前付きの引数が使えず失敗しました(`part10-01-incident`)。ジョブの中で自分のログ・印刷を写す方法だけが動きました。
- 10-01の実行は、検証用の道具でアップロードしたメンバーからビルドしたものです。クローンからメンバーへ`CPYFRMSTMF`で取り込む手順は、学習者の手順そのままでは実行していません。
- 検証は1つの環境の結果で、ほかのユーザーのPUB400での再現は保証しません。
- 「ジャーナルがない」の行(環境による代替)の、受注登録のルーチンが途中で失敗しても取り消せないという説明は、`COMMIT(*NONE)`の設計上の前提です。実機で取り消しを試した結果ではありません。
