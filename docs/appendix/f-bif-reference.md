# 付録F BIF早見表

この付録は生きた文書です。第6部(RPG IV 完全自由形式)が書き上がると、内容が大きく増える見込みです。現時点では、第4部・第5部(RPG III)でこの教材が実機確認してきた事実と、一次資料(*RPG/400 Reference*, IBM, 1994年6月 初版、ILE RPG/400 プログラム番号5763-RG1、Version 3 Release 0 Modification 5 向け)の確認結果、そして第6部でまだ実機検証していない一般知識とを、はっきり区別して記載します。

## BIF とは

BIF(Built-In Function、組み込み関数)は、`%TRIM`・`%SUBST`のように`%`で始まる名前を持つ、RPG言語があらかじめ用意している関数です。呼び出す側は `%関数名(引数)` の形で式の中に直接書けます。

**この教材のCLプログラム(第3部03-03など、`tools/qclsrc/`以下のツール類)にすでに出てきた `%TRIM`・`%SST`・`%CHAR` は、CL(Control Language)自身が持つ別の組み込み関数です。** RPGのBIFとは名前が似ている(どちらも`%`で始まる)だけで、まったく別の仕組みです。本付録が扱うのはRPGのBIFだけです。

RPGには大きく分けて2つの世代があります。

- **RPG III**(この教材の第4部・第5部が扱う言語。固定形式、命令コード中心。コンパイルには`CRTRPGPGM`を使う)
- **RPG IV**(完全自由形式。この教材の第6部以降で扱う予定。現時点では未執筆)

この2つでBIFの扱いが大きく違います。次の節でそれぞれを分けて説明します。

## RPG III で使える主な BIF

**結論を先に書きます。** この教材が一次資料として使っている*RPG/400 Reference*(前掲、`CRTRPGPGM`が対象とするOPM RPG/400コンパイラーの言語仕様書)の全文(約26,600行のテキスト版)を検索した限り、`%`で始まる組み込み関数の記載は1件も見つかりませんでした。唯一ヒットした`%`は、EBCDIC文字コード表の中で「`%`(パーセント記号)という文字そのもの」を説明している1行だけで、BIFとは無関係です。

この一次資料は、RPG III(固定形式)の言語仕様そのものを扱っており、文字列操作・配列検索・数値編集は、すべて**命令コード(オペコード)**または**仕様書の桁位置**で行うようになっています。実際、この教材の第4部・第5部のRPGソース(`*.rpg`)を`git grep`で検索しても、`%`で始まる記述は1件もありません。文字列操作・配列検索は、`CAT`・`SUBST`・`SCAN`・`MOVE`/`MOVEL`・`LOKUP`(配列検索。綴りは"LOOKUP"ではなく、命令コード欄が5文字までのため短縮された"LOKUP")といった命令コードのみで書かれています。

**つまり、「RPG IIIで使える主なBIF」という問いへの正しい答えは「実質的にゼロ」です。** 以下の表は、RPG IVで馴染みがあるかもしれないBIF名を手がかりに、「RPG IIIではそれぞれ何を使うか」を対応させたものです。表の見出しは他のBIF表と揃えていますが、「意味」欄の中身は実質的にすべて「RPG IIIには存在しない」から始まる点に注意してください。

| BIF | 意味 | 例 | 備考 |
|---|---|---|---|
| `%SUBST` | RPG IIIには存在しない。文字列の一部を取り出すには**`SUBST`命令(オペコード)**を使う(C仕様書28〜32桁目に命令コードを書く)。 | `SUBST`(桁位置は04-03のとおり、SEUの`F4`プロンプトで確認するのが確実) | 一次資料「SUBST (Substring)」の章で、"The SUBST operation extracts a specified character string from a base character string" と説明されている。本教材内での実機コンパイルは04-03の演習止まり(未確認、次回確認予定)。 |
| `%TRIM`/`%TRIML`/`%TRIMR` | RPG IIIには存在しない。決まった1つの代替命令もない。近い機能として、**`CHECK`/`CHEKR`命令**(Factor 2の各文字がFactor 1の文字集合に含まれるかを、それぞれ左から/右から検証し、含まれない文字の位置を返す)を使い、空白以外の文字の境界を探す、という組み方が考えられるが、これが「決まったイディオム」として一次資料に明記されているわけではない(**要確認**)。また、`MOVE`/`MOVEL`・`CAT`・`SUBST`・`XLATE`には、**オペレーション拡張子`P`(C仕様書53桁目)**を付けると「書き換えなかった残りの桁を自動的に空白で埋める」機能があり(05-02で実機の桁位置を確認済み)、「前の値が残る罠を避ける」という目的の一部はこちらで代替される。 | ― | RPG IIIは固定長フィールドが前提のため、「前後の空白を詰めて長さを縮める」という操作自体があまり必要にならない、という側面もある。CLの`%TRIM`(03-03)と混同しないこと。 |
| `%LEN` | RPG IIIには存在しない。フィールドの長さは、結果フィールドに初めて長さを指定した行(C仕様書49〜51桁目)でコンパイル時に固定される(04-02で実機確認済み)。D仕様書(変数を先に宣言する仕組み)自体がRPG IIIには無いため、実行時に長さを問い合わせる関数も無い。 | ― | ― |
| `%EDITC`/`%EDITW` | RPG IIIには存在しない。数値の編集(桁区切り・符号など)は、O仕様書の**編集コード欄(38桁目、単一文字)**または**編集語欄(45〜70桁目、定数として直接書く)**という、桁位置ベースの機能で行う。関数呼び出しではない。 | 編集コード`1`(カンマ区切り)は04-02で実機確認済み(`1580×1.10`が`1,738.00`と正しく印字された。小数点以下2桁の表示自体は、編集コードではなく`TOTAL`フィールド側の宣言(小数桁数2)による)。 | 一次資料 第10章の目次に "Position 38 (Edit Codes)" と明記されており、本教材の`src/qrpgsrc/r0402s.rpg`(実機確認済み)のO仕様書でも、編集コード`1`は実際に38桁目に置かれている。なお、DDS(表示・印刷装置ファイル)側にも`EDTCDE`/`EDTWRD`というキーワードがあるが、これはDDSレベルの別機能であり、RPG IIIのO仕様書の編集コード欄とは別物(要確認: 本教材では04-11でこの2キーワードをまだ使っていない)。 |
| `%LOOKUP`/`%LOOKUPxx` | RPG IIIには存在しない。配列検索は**`LOKUP`命令(オペコード)**を使う。 | `ZKSHO LOKUP TABPCD TABPRI 80`(検索値`ZKSHO`をFactor 1、検索対象の配列/テーブル`TABPCD`をFactor 2、関連する別テーブル`TABPRI`を結果欄、`80`を結果標識に置く。05-04の`ZA0510`の設計より)。 | 一次資料「LOKUP (Look Up)」の章の説明と、05-04で示された設計に基づく。**ただし05-04自身が「`ZA0510`はこのセッションでは実機コンパイル未確認」と明記しており、この行の内容全体が実機未検証(要確認)。** 検索に失敗したとき結果標識は自動ではOFFにならない(`LOKUP`の前に毎回`SETOF`しておく必要がある)という点は一次資料の記述に基づく。`LOKUP`失敗時に`*PSSR`へ処理を渡す経路・`QCMDEXC`呼び出し・失敗時のエラー標識の桁位置も、05-04自身が実機未確認と明記している。 |
| `%SCAN` | RPG IIIには存在しない。文字列検索は**`SCAN`命令(オペコード)**を使う。 | `SCAN`(04-03で導入) | 実機コンパイルは04-03の演習止まり(未確認)。 |
| `%REPLACE` | RPG IIIには存在しない。近い操作は`SUBST`と`CAT`の組み合わせで代替することになると考えられるが、決まったイディオムは一次資料からは確認できていない(**要確認**)。 | ― | ― |
| `%XLATE` | RPG IIIには存在しない。文字の変換(大文字/小文字変換など)は**`XLATE`命令(オペコード)**を使う。 | `XLATE` | 一次資料の文字列操作(String Operations)の節に、CAT・CHECK・CHEKR・SCAN・SUBSTと並んで挙げられている。本教材ではまだ実際に使った例が無い(**要確認**)。 |
| `%CHAR`/`%DEC`(数値⇔文字の変換) | RPG IIIには専用のBIFは無い。フィールド間の型変換は`MOVE`/`MOVEL`(転記)や`Z-ADD`(数値の代入)、印字時の編集コードの組み合わせで行う。 | 04-02・04-03で実機確認済みの技法の組み合わせ | CLの`%CHAR`(03-13で使用)と混同しないこと。 |
| `%ELEM`/`%SIZE` | RPG IIIには存在しない。配列の要素数は、E仕様書(拡張仕様書)の**36〜39桁目**にコンパイル時の固定値として書く。実行時に問い合わせる関数はない。 | ― | 一次資料の制限一覧(Appendix A)に「Elements in an array/table (positions 36 through 39 of extension specifications)」と明記。 |
| `%ERROR`/`%STATUS` | RPG IIIには存在しない。実行時の状態把握は、複数の別々の仕組みの組み合わせで行う: (1) 演算ごとの**結果標識(C仕様書54〜59桁目のHI/LO/EQ)**。例: `CHAIN`の「見つからない」はHI(04-07で実機確認済み)、`READ`のEOFはEQ(04-06で実機確認済み)。(2) 予約済みの2文字標識`H1`〜`H9`(ホールト標識。ONのまま`LR`を迎えるとプログラムが異常終了する、05-02で確認)。(3) 未監視の実行時エラーが起きたとき、RPGが自動的に制御を渡す**`*PSSR`(プログラム全体用)・`INFSR`(ファイル単位用)エラー・サブルーチン**と、そこから参照できるPSDS(プログラム状態データ構造)・INFDS(ファイル情報データ構造)のステータス・コード欄。 | ― | 04-06(暗黙オープン失敗`RPG1216`は`*PSSR`で捕まえられない)・04-12(ゼロ除算`RPG0102`)は実機確認済み。05-04(`LOKUP`失敗時に明示的に`EXSR *PSSR`)は、実機コンパイル未確認のまま一次資料に基づいて設計された内容であり、実機検証はまだ済んでいない(要確認)。 |

**この節でまとめて残す要確認事項**: (1) `%TRIM`・`%REPLACE`に相当する「決まったイディオム」が一次資料に明記されているかは未確認。(2) `%XLATE`相当の`XLATE`命令は、本教材ではまだ実際に使った実例が無い。(3) `LOKUP`失敗時の結果標識の桁位置は、05-04自身が「このセッションでは実機未確認」と明記している。

## RPG IV の主な BIF(第6部以降で扱う予定)

**この節の内容は、この教材の第6部以降でまだ実機検証していない一般知識です。** RPG IV(完全自由形式)は、このリポジトリーの外で広く文書化されている言語であり、以下の内容はそうした一般的な情報源に基づきます。第6部が実際に書かれ、PUB400での実機検証が済み次第、この節を検証済みの内容に置き換えていきます。

| BIF | 意味 | 例 | 備考 |
|---|---|---|---|
| `%TRIM` | 文字列の前後の空白を取り除く。`%TRIML`/`%TRIMR`はそれぞれ左側/右側だけ。 | `%TRIM(NAME)` | 最も基本的なBIFの1つ。 |
| `%SUBST` | 文字列の一部を取り出す(部分文字列)。代入先に使うと、その部分だけを書き換えられる。 | `%SUBST(NAME:1:3)` | RPG IIIの`SUBST`命令に相当。 |
| `%LEN` | フィールド・式の(現在の)長さを返す。可変長フィールドの実際の長さを取るのにも使う。 | `%LEN(NAME)` | ― |
| `%DEC` | 文字列や数値を、指定した桁数・小数点位置の10進数に変換する。 | `%DEC(CHARFLD:7:2)` | 逆(数値→文字)は`%CHAR`。 |
| `%CHAR` | 数値・日付などを文字列に変換する。 | `%CHAR(AMOUNT)` | CLにも同名のBIFがあるが別物。 |
| `%EDITC` | 数値を、指定した編集コード(RPG IIIのO仕様書編集コード欄に相当するもの)で編集した文字列にする。 | `%EDITC(AMOUNT:'1')` | RPG IIIでは桁位置指定だった編集コードが、RPG IVでは関数呼び出しになる。 |
| `%EDITW` | 数値を、指定した編集語で編集した文字列にする。 | `%EDITW(AMOUNT:編集語)` | 同上、編集語版。編集語の書式は桁数に応じて変わるため、例は省略(`AMOUNT`の桁数に合わせて別途組み立てる)。 |
| `%LOOKUP` | 配列やテーブルの中から指定した値を探し、見つかった要素番号を返す(見つからなければ0)。`%LOOKUPxx`(GT/GE/LT/LE等)で条件付き検索もできる。 | `%LOOKUP(KEY:ARR)` | RPG IIIの`LOKUP`命令に相当。**[実機確認]** 06-07(`F0607A`)で実機確認済み(`BONUS: LOOKUP P00002 -> INDEX  2`という出力が実際に得られた)。 |
| `%SCAN` | ある文字列が別の文字列の中に含まれるかを検索し、見つかった位置を返す(見つからなければ0)。 | `%SCAN('AB':NAME)` | RPG IIIの`SCAN`命令に相当。 |
| `%REPLACE` | 文字列の指定した位置を、別の文字列で置き換える。 | `%REPLACE('XX':NAME:1)` | ― |
| `%XLATE` | 文字列中の文字を、対応表に従って変換する(大文字/小文字変換など)。 | `%XLATE(LOWER:UPPER:NAME)` | RPG IIIの`XLATE`命令に相当。 |
| `%INT` | 文字列や数値を整数に変換する。 | `%INT(CHARFLD)` | ― |
| `%ELEM` | 配列の要素数を返す。 | `%ELEM(ARR)` | RPG IIIでは仕様書に固定で書いていた値を、RPG IVでは関数で取得できる。 |
| `%SIZE` | フィールド・データ構造の(バイト単位の)サイズを返す。 | `%SIZE(FLD)` | ― |
| `%STATUS` | 直前のファイル操作や演算のステータス・コードを返す。引数にファイル名を指定すると、そのファイルのステータスを返す。 | `%STATUS`、または`%STATUS(ファイル名)` | RPG IIIのPSDS/INFDSのステータス・フィールドに相当する情報を、関数として取得できる。 |
| `%ERROR` | 直前の演算でエラーが起きたかどうかを返す(オペレーション拡張子`(E)`と組み合わせて使う)。 | `IF %ERROR;` | RPG IIIの`*PSSR`・結果標識によるエラー検知に相当。 |
