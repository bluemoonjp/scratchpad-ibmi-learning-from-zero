# 付録J 日本語・DBCS

この付録は生きた文書です。第9部(特に09-02b、ACS経由で日本語・DBCSを実機で体験するレッスン。現時点では未執筆)が書き上がると、内容が実機検証済みのものに置き換わっていく見込みです。

## このカリキュラムですでに確認済みのこと

- PUB400のシステム全体の文字コード(システム値`QCCSID`)は**273**(ドイツ語圏向けEBCDIC)です。ホスト・コード・ページを273に合わせる必要があることは、一次資料(PUB400のFAQ)と著者自身の実測の両方に基づく確認済みの事実として、00-03に記録されています(**個々のジョブのCCSID属性**は、システム値QCCSIDとは別物で、こちらは01-08時点ではまだ実機未確認だと明記されています。混同しないでください)。
- IFS(統合ファイル・システム)上のテキスト・ファイルはASCII系、特に**CCSID 1208(UTF-8)**で置かれることが多く、ソース物理ファイルのメンバー(EBCDIC系)へ複写するときに変換が必要です。02-03で確認済みです。
- この教材のツール類(`tools/qclsrc/txsetup.clp`の`CPYFRMSTMF`、02-09の`CPYTOIMPF`/`CPYFRMIMPF`、03-10の`CPYTOSTMF`、03-13の`CPYTOIMPF`)は、いずれも同じ**`STMFCCSID(1208)`**を明示的に指定しています。この値そのものが実機で正しく動く(IFS→ソース物理ファイル・メンバーの方向)ことは、`docs/probes.md`の「TXSETUP・TXRESETの続報」で、`txsetup.clp`の`CPYFRMSTMF`について実機のコンパイル・実行を通して確認済みです。02-09・03-10・03-13の各コマンドは同じ値を踏襲していますが、それぞれのレッスン自体の実機検証状況(V1/V2/V3等)は、各レッスンの実機メモを参照してください。**1208はUTF-8であり、Shift-JIS(932)とは別の値です。** この教材の配布ソース(CLP/RPG/DDS)・CSVデータはASCII文字のみで書かれているため、「ASCIIの内容を1208(UTF-8)として複写しても壊れない」ことは`txsetup.clp`の実機検証で確認済みですが、**日本語(全角)の文字そのものを含むソースやデータをCCSID変換して送るところまでは、本教材ではまだ実機検証していません。**

## 一般知識(このカリキュラムではまだ実機未検証)

以下は、IBM iのCCSID・DBCSに関する一般的な知識です。第9部 09-02b(予定)で、PUB400とACS(IBM i Access Client Solutions)を使った実機検証を行い、確認できた内容に置き換えていきます。

### CCSIDの基礎

CCSID(Coded Character Set Identifier、符号化文字集合識別子)は、IBM iのオブジェクト・フィールド・ジョブなどに付く、「どの文字コードで書かれているか」を表す番号です。代表的な値として、次のものが知られています。

- **1208 = UTF-8。** 上記のとおり、この教材でも実機確認済みです。
- **932。** 一般にShift-JIS系の日本語文字コードとして知られていますが、**IBM iのCCSID 932と、Windowsのコードページ932(cp932)が完全に同一のコードポイント配置かどうかは要確認です。** Windows環境との厳密な互換を語るときは、しばしば**CCSID 943**の方がcp932互換として挙げられることもあり、932/943のどちらを使うべきかは本教材では未検証・未確認です。
- **930・5035など、日本語のIBM iショップで歴史的に使われてきたとされるEBCDIC系のCCSID群。** カタカナのみのSBCS用途か、漢字を含むDBCS混在用途かといった正確な使い分け、およびどの値が現在推奨されるかは**要確認**です(本教材では未検証。一次資料や実機での裏付けがまだありません)。

**なぜソース・メンバーのCCSIDが転送で重要か**: IFS上のファイル(クライアントで書いたUTF-8のテキストなど)をソース物理ファイルのメンバーへ複写するとき、複写元と複写先で文字コードの解釈が食い違うと文字化けします。`CPYFRMSTMF`の`STMFCCSID()`パラメーターは、「複写元(IFS側)のファイルは何というCCSIDで書かれているか」を明示することで、システムに正しい変換をさせるためのものです。この教材では、ASCII専用ソースに対して1208を指定する使い方までは実機確認済みですが、日本語コメントや日本語データを含むソースを正しく転送するには、送り側・受け側双方のCCSIDをより注意深く合わせる必要があると考えられます(**要確認**、09-02bで扱う予定)。

### DDSのDBCSフィールドの基礎

- DDS(データ記述仕様)には、DBCS(2バイト文字集合。日本語の全角文字など)を扱うための、いくつかのフィールド・データ・タイプがあります。一般に、**`G`(グラフィック型)は、シフトアウト/シフトインの制御バイトを伴わない、純粋なDBCSデータ**を表し、これに対して**`J`(DBCS-Only)・`O`(DBCS-Open)・`E`(DBCS-Either)**といった別のタイプは、**シフトアウト(SO)・シフトイン(SI)の制御バイトを伴う**、という違いがあるとされています。このタイプごとの区別は一般知識であり、**本教材ではまだ実機で確認していません(要確認)**。
- **シフトアウト(SO、X'0E')・シフトイン(SI、X'0F')**は、DBCS文字列の前後に置かれる制御バイトで、周囲のSBCS(1バイト文字)とDBCS部分を区別するために使われます。
- RPG III(この教材の第4部・第5部が扱う言語)については、著者が参照した一次資料(*RPG/400 Reference*, IBM, 1994年、第16章「Using Double-Byte Character Set (DBCS) Data in RPG/400 Programs」)に、DBCSを扱う専用の章があります。そこで確認できる内容は次のとおりです。
  - RPG/400は、外部記述ファイルのDBCSフィールドを**文字フィールドとして扱います**(DBCSデータをSBCSデータと同じように扱う、という説明が明記されています)。
  - DBCSの定数・リテラルは、「透過(transparent)」形式(アポストロフィ+SOで始まり、SI+アポストロフィで終わる)で書くと、内部にアポストロフィに似た文字が含まれていても正しく認識されます。
  - 相互参照リスト(コンパイル・リスト)上では、DBCSを含むフィールドが**フィールド欄では`G`、キー・フィールド欄では`IGC`**という表示で示されます。**これはRPG/400のコンパイラーが相互参照リストに付ける表示であり、上記のDDSのフィールド・タイプ`G`(グラフィック型)そのものとは、直接同じものではない**ことに注意してください(両者の関係は本教材ではまだ確認していません、要確認)。
  - INFDS(ファイル情報データ構造)の`OUT`フィールドが**10**のとき、その装置がDBCS出力に対応していることを示す、という説明があります。
  - これらはあくまで一次資料に基づく仕様の説明であり、**本教材ではまだRPG III上でDBCSデータを実際に扱うプログラムを書いていません(実機未検証)。**
