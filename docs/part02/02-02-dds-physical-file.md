## なぜ学ぶか

02-01 で概念を学んだので、ここでは実際に手を動かして DDS を書きます。**桁位置がそのまま意味を持つ**という固定形式の世界を、体で覚える最初の一歩です。ここで作る `TOKUIM`(得意先マスタ)は、この教科書全体を通して使う、最初の実データベースです。

## 新出

- DDS の桁の規則(名前種別・名前・長さ・型・小数桁・キーワード)
- `UNIQUE`
- `TEXT`・`COLHDG`
- `CRTPF`

## 説明

DDS(データ記述仕様)は、物理ファイルや論理ファイルの構造を定義する、RPG III と同じく固定形式のソースです。1行の桁の意味は、次のとおりです。

| 桁 | 内容 |
|---|---|
| 6 | 常に `A`(固定) |
| 7 | コメントなら `*` |
| 17 | 名前種別: 様式名の行なら `R`、キー・フィールドの行なら `K`、通常のフィールドの行なら空欄 |
| 19〜28 | 名前(様式名またはフィールド名。10文字まで) |
| 30〜34 | 長さ(数字。右詰め) |
| 35 | データ型(`A`=文字、`S`=ゾーン10進など) |
| 36〜37 | 小数桁数(数値型のみ) |
| 45〜 | キーワード(`TEXT`、`COLHDG` など) |

`TEXT('...')` は、オブジェクトやフィールドの説明文です。`COLHDG('...')` は、SQL などで表示するときの列見出しです(指定しなければ、フィールド名がそのまま使われます)。`UNIQUE` は、様式の行(`R`)に付けると、キーの値が重複しないことを保証します(今回は使いません。同じ商品コードを在庫マスタで一意にする、といった場面で第2部の後半に出てきます)。

## 実演

1. コマンド行に `WRKMBRPDM FILE(<自分のユーザー名>1/QDDSSRC)` と打ち、Enter を押す。
2. `F6` で新しいメンバー `TOKUIM`(ソース・タイプ `PF`)を作る。
3. SEU が開く。次の内容を、桁位置に注意しながら入力する(`db/v1/tokuim.pf` と同じ内容です)。

   ```text
   ....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
        A          R TOKUIR                    TEXT('Customer master')
        A            TOKCD          6A         TEXT('Customer code')
        A            TOKNM         30A         TEXT('Customer name')
        A            TOKZIP         7A         TEXT('Zip code')
        A            TOKTAN         6A         TEXT('Sales rep code')
        A            TOKUPD         8S 0       TEXT('Updated date YYYYMMDD')
        A          K TOKCD
   ```

   一番上のルーラー行(`....+....1....`)は桁を数えるための目安で、実際には入力しません。

4. `F3` で保存する。
5. `WRKMBRPDM` の一覧で `TOKUIM` の行にオプション `14`(コンパイル)を入力し、Enter を押す。`CRTPF` が実行される。
6. コンパイルが成功したら、コマンド行に `DSPFFD FILE(<自分のユーザー名>1/TOKUIM)` と打ち、Enter を押す。5つのフィールド(`TOKCD`・`TOKNM`・`TOKZIP`・`TOKTAN`・`TOKUPD`)が、それぞれ指定した型・長さで定義されていることを確認する。

## 同じ手順を別の対象で

同じ手順で、`SHOHIM`(商品マスタ)を作成してください。

```text
....+....1....+....2....+....3....+....4....+....5....+....6....+....7....+....8
     A          R SHOHIR                    TEXT('Product master')
     A            SHOCD          6A         TEXT('Product code')
     A            SHONM         30A         TEXT('Product name')
     A            SHOTNK         7S 2       TEXT('Unit price')
     A            SHOHAT         5S 0       TEXT('Reorder point')
     A          K SHOCD
```

`DSPFFD FILE(<自分のユーザー名>1/SHOHIM)` で、`SHOTNK` が7桁2小数のパック10進として定義されていることを確認してください(02-01 で計算した5バイトと一致するか、`DSPFFD` の詳細表示で確認できます)。

## 出力が違うとき

- コンパイルでエラーが出た場合、桁がずれている可能性が最も高いです。SEU の `F19`/`F20`(横スクロール)でルーラーを表示し、自分の入力と見比べてください。
- `A` の位置(6桁目)がずれていると、DDS の行として認識されず、多くの場合そのままエラーになります。

## 演習

1. わざと `TOKUPD` の桁を1つずらして(例えば型 `S` の位置を1桁右にずらして)コンパイルし、コンパイル・リストに出るエラーの内容を読んでください。その後、正しい桁に戻して再コンパイルしてください。
2. `DSPFFD FILE(<自分のユーザー名>1/TOKUIM) OUTPUT(*PRINT)` を実行し、スプールで詳しい情報(バッファー上の位置など)を確認してください。
