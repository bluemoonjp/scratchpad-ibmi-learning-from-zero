## なぜ学ぶか

ここでは、**在庫引当**(受注した分だけ在庫を減らす)という、この教科書を通して繰り返すもう1つの用件(00-01 で触れた「通し課題」)の、最初の SQL 版を実装します。**更新は、事前に同じ条件で `SELECT` して確認してから行う**という安全な手順も、ここで身につけます。

## 新出

- `GROUP BY`/`HAVING`
- 更新前の確認(同じ `WHERE` で `SELECT` する)
- `INSERT` で列名を明記する

## 説明

### 更新の安全な手順

`UPDATE` や `DELETE` は、一度実行すると元に戻せません(この教材では `TXRESET` で戻せますが、実務では簡単には戻せないことが普通です)。そのため、**更新の直前に、同じ `WHERE` 条件で `SELECT` して対象を確認する**習慣を付けます。

1. `SELECT` で、更新される予定の行を確認する。
2. `UPDATE`/`DELETE` を実行する。
3. もう一度 `SELECT` して、結果が正しいことを確認する。

### ジャーナルと SQL7008(先の学びの予告)

テーブルが「ジャーナル」という変更記録の仕組みでカバーされていないと、`UPDATE`/`INSERT`/`DELETE` が `SQL7008` というエラーで拒否されることがあります。この教材のサンプル・データベースでジャーナルが必要かどうかは、実機で確認してから追記します(06-13 で本格的に扱います)。今は「そういうことがある」と知っておくだけで十分です。

## 実演

1. `STRSQL` を開く。
2. `src/sql/02-07-hikiate.sql` の内容を、1文ずつ実行する。

   ```sql
   -- 1. 更新前の確認
   SELECT ZASHO, ZASU FROM ZAIKOM WHERE ZASHO IN ('P00001', 'P00003');
   ```

   `P00001` の在庫数量(`ZASU`)が `45`、`P00003` が `250` であることを確認する。

3. 受注 `J00001`(得意先 `C00001`。02-06 で確認済み)の分だけ、在庫を引き当てる(減らす)。

   ```sql
   UPDATE ZAIKOM SET ZASU = ZASU - 2 WHERE ZASHO = 'P00001';
   UPDATE ZAIKOM SET ZASU = ZASU - 5 WHERE ZASHO = 'P00003';
   ```

4. 更新後を確認する。

   ```sql
   SELECT ZASHO, ZASU FROM ZAIKOM WHERE ZASHO IN ('P00001', 'P00003');
   ```

   `P00001` が `43`、`P00003` が `245` になっていれば成功です。

## 同じ手順を別の対象で

`GROUP BY`/`HAVING` の練習として、次を実行してください。

```sql
SELECT SHOHIM.SHOCD, SUM(JUCHUD.JUSU) AS QTY
  FROM JUCHUD
  JOIN SHOHIM ON SHOHIM.SHOCD = JUCHUD.JUSHO
 GROUP BY SHOHIM.SHOCD
HAVING SUM(JUCHUD.JUSU) >= 5
 ORDER BY QTY DESC;
```

商品ごとの受注数量の合計のうち、5個以上のものだけが表示されることを確認してください。

## 演習

1. **集計1**: 得意先ごとの受注件数を、`GROUP BY` で求めてください。
2. **集計2**: 商品ごとの売上金額(数量×単価の合計)を、金額の大きい順に並べてください。
3. **集計3**: 在庫数量が発注点(`SHOHAT`)を下回っている商品を、`SHOHIM` と `ZAIKOM` を `JOIN` して探してください。
