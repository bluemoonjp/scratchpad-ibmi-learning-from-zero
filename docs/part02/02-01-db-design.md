## 説明

### IBM i の用語と、一般的な RDB 用語の対応

| IBM i の用語 | 一般的な RDB の用語 |
|---|---|
| 物理ファイル(PF) | テーブル |
| レコード | 行 |
| フィールド | 列 |
| 様式(レコード・フォーマット) | (テーブルの行の型。IBM i 特有の概念) |
| 論理ファイル(LF) | インデックス・ビュー |
| キー | 主キー・インデックス・キー |

00-01 で触れたとおり、IBM i では Db2 が OS に統合されているため、**特別なインストールなしに、最初からテーブル(物理ファイル)を作って使えます。**

### 様式名とファイル名は別

物理ファイルには「様式(レコード・フォーマット)」という、そのファイルの1行の構造を定義したものが必ず1つあります。**様式の名前は、ファイルの名前と別に付けます。** 例えば、得意先マスタというファイルの名前を `TOKUIM` にしたら、様式の名前は `TOKUIR` のように、末尾の文字を変えて区別するのが一般的な習慣です(この理由は、論理ファイルを作るときに関わってきます。02-08 で扱います)。

### 数値の格納形式

IBM i の数値フィールドには、主に2つの格納形式があります。

- **ゾーン10進**: 1バイトに1桁を格納する形式。人間が読みやすい形に近い。
- **パック10進**: 1バイトに2桁を詰め込む形式(最後の1バイトだけ符号と1桁を共有)。ゾーンより省スペース。

パック10進のバイト数は、`桁数 ÷ 2` を切り上げてから `+1` した値になります。例えば7桁のパック10進フィールドなら、`7 ÷ 2 = 3.5` を切り上げて `4`、`+1` で **5バイト**です。

### 数値日付

この教材のサンプル・データベースでは、日付を「8桁の数値」(`YYYYMMDD` の形。例: `20260901`)で格納しています。専用の日付型を使わず、数値として扱う古い流儀です。RPG III(第4部)には日付専用の型がないため、この形式が広く使われてきました。

## サンプル・データベースの全体像

この教材で一貫して使うのは、次の6つのファイルです。

```mermaid
erDiagram

    TANTOM ||--o{ JUCHUM : "担当"
    TOKUIM ||--o{ JUCHUM : "発注"
    JUCHUM ||--o{ JUCHUD : "明細"
    SHOHIM ||--o{ JUCHUD : "商品"
    SHOHIM ||--|| ZAIKOM : "在庫"

    TANTOM {
        char TANTOCODE PK
        char TANTONAME
    }
    TOKUIM {
        char TOKCD PK
        char TOKNM
        char TOKZIP
        char TOKTAN FK
        num TOKUPD
    }
    SHOHIM {
        char SHOCD PK
        char SHONM
        packed SHOTNK
        num SHOHAT
    }
    JUCHUM {
        char JUNO PK
        char JUTOK FK
        num JUDATE
        char JUTAN FK
    }
    JUCHUD {
        char JUNO PK_FK
        num JULINE PK
        char JUSHO FK
        num JUSU
        packed JUTNK
    }
    ZAIKOM {
        char ZASHO PK_FK
        num ZASU
        num ZAUPD
    }
```

| ファイル | 内容 | 主なフィールド |
|---|---|---|
| `TANTOM` | 担当者マスタ | `TANTOCODE`(コード)、`TANTONAME`(氏名) |
| `TOKUIM` | 得意先マスタ | `TOKCD`(コード)、`TOKNM`(名前)、`TOKTAN`(担当者コード) |
| `SHOHIM` | 商品マスタ | `SHOCD`(コード)、`SHONM`(名前)、`SHOTNK`(単価)、`SHOHAT`(発注点) |
| `JUCHUM` | 受注マスタ | `JUNO`(受注番号)、`JUTOK`(得意先コード)、`JUDATE`(受注日) |
| `JUCHUD` | 受注明細 | `JUNO`+`JULINE`(受注番号+行番号)、`JUSHO`(商品コード)、`JUSU`(数量) |
| `ZAIKOM` | 在庫マスタ | `ZASHO`(商品コード)、`ZASU`(在庫数量) |

フィールド名がすべて6文字以内なのは、第4部で学ぶ RPG III の制約(フィールド名は6文字まで)に合わせているためです。`TANTOM` だけは「他システム由来」という設定で、あえて6文字を超える名前(`TANTOCODE` など)にしてあります(第5部の保守レッスンで、この名前を RPG III から扱う練習をします)。

## 実演

1. コマンド行に `DSPFFD FILE(<自分のユーザー名>1/QCLSRC)` と打ち、Enter を押す。`QCLSRC` というソース物理ファイル自体のフィールド定義(順序番号・日付・本文の3フィールド)が表示される。これは 01-06 で学んだ「ソース物理ファイルの1行の内訳」が、実際にはこの3つのフィールドとして定義されている、ということです。

## 演習

1. `SHOTNK`(単価、パック10進7桁2小数)のバイト数を計算してください。
2. `JUSU`(数量、ゾーン10進5桁)のバイト数を計算してください(ゾーン10進は1バイト1桁なので、単純に桁数と同じバイト数になります)。
3. 上のER図を見ながら、「ある受注(`JUCHUM` の1行)の合計金額を求めるには、どのファイルとどのファイルを、どのフィールドで結び付ければよいか」を、自分の言葉で説明してください。

<details><summary>解答例</summary>

1. `7 ÷ 2 = 3.5` を切り上げて `4`、`+1` で **5バイト**
2. **5バイト**(ゾーン10進はそのまま桁数)
3. `JUCHUM` の `JUNO` と `JUCHUD` の `JUNO` を結び付け、`JUCHUD` の `JUSU`(数量)× `JUTNK`(単価)を明細行ごとに求めて合計する。
