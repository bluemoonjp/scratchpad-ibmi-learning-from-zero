## なぜ学ぶか

## 新出

- IFS(統合ファイル・システム)
- `/QSYS.LIB/ライブラリー名.LIB/ファイル名.FILE/メンバー名.MBR` という経路
- `WRKLNK`・`MKDIR`
- `EDTF`(IFS 上のテキスト・ファイルを編集する)

## 説明(Windows / Linux との比較)

Linux にはディレクトリー階層を持つファイル・システムがあります。IBM i にも同じような**IFS(Integrated File System、統合ファイル・システム)**があり、`/home/<自分のユーザー名>` のようなパスで、ディレクトリーとファイルを扱えます。

**重要なのは、01-04 で学んだ「ライブラリー・オブジェクトの世界」と、この IFS が、同じ1つのシステムを2つの窓から見ているという点です。** 実は、ライブラリーもファイルもメンバーも、IFS のパスとして表現できます。

```text
/QSYS.LIB/<自分のユーザー名>1.LIB/QCLSRC.FILE/C0107A.MBR
```

これは、`<USER>1` ライブラリーの `QCLSRC` ファイルの `C0107A` メンバーを、IFS のパスとして表した例です。`ライブラリー名.LIB`・`ファイル名.FILE`・`メンバー名.MBR` という拡張子が付くのが特徴です。

### CCSID と改行

IFS 上のテキスト・ファイルには、**CCSID(文字コードの設定)**があります。00-01 で触れたとおり、IBM i の内部は EBCDIC 系(PUB400 では 273)ですが、IFS のファイルは ASCII 系(1208 = UTF-8)で置かれることも多く、変換が必要になります。

**改行コードにも注意が必要です。** Windows は `CR+LF`、Linux/Mac は `LF` だけを使います。IBM i のライブラリー・オブジェクトの世界(固定形式ソース)には、そもそも改行コードという概念がなく、**桁位置がそのまま意味を持ちます。** IFS からライブラリーのメンバーに取り込むとき、`CR` が1バイトでも残っていると、桁がずれて DDS や RPG III のコンパイルが壊れます。**この教材の配布ソースはすべて LF のみで統一しています。**

## 実演

1. コマンド行に `MKDIR DIR('/home/<自分のユーザー名>/work')` と打ち、Enter を押す。作業用のディレクトリーを作る。
2. コマンド行に `WRKLNK OBJLNK('/home/<自分のユーザー名>')` と打ち、Enter を押す。IFS のオブジェクト(ディレクトリーやファイル)が一覧表示される。今作った `work` ディレクトリーがあることを確認する。
3. コマンド行に `WRKLNK OBJLNK('/QSYS.LIB/<自分のユーザー名>1.LIB/QCLSRC.FILE')` と打ち、Enter を押す。01-07 で作ったメンバー(`C0107A.MBR` など)が、IFS のファイルのように一覧表示されることを確認する。

## 同じ手順を別の対象で

`WRKLNK` で次の3か所を見て、それぞれ何が表示されるかを比較してください。

1. `/home/<自分のユーザー名>`(自分のホーム・ディレクトリー)
2. `/QSYS.LIB/<自分のユーザー名>1.LIB`(自分の `<USER>1` ライブラリーの中身)
3. `/QSYS.LIB/<自分のユーザー名>1.LIB/QDDSSRC.FILE`(02-02 で作ったメンバーが見えるはず)

## 演習
