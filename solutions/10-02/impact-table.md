# 影響調査表(模範解答): `TOKUIM` に `TOKYSN` を追加する

[docs/templates/impact-table.md](../../docs/templates/impact-table.md) の骨組みに沿った、課題Bの模範解答です。**自分の表を書き終えてから見比べてください。**

**この表の確からしさ: 静的に読んだ結果(ソースの `grep` と、`db/v1/`・`src/legacy/` の読解)を土台に、実機の結果(バッチ `part10-02-tokuim` の3回目の接続、2026-09-30、V2)で確かめた行に「V2」と書いてあります。** 「V2」と書いていない「実機」の記述は、その接続で確かめていない項目です(未検証(2026-09-30時点))。実機の行数(`DSPPGMREF` の27行など)は、著者の検証用ライブラリーの内容で、あなたの環境とは違います。

実在のユーザー名は書かず、`<自分のユーザー名>2` のプレースホルダーを使います。

## 1. 変更の内容

- 変更対象: 物理ファイル `TOKUIM`(得意先マスター)。`db/v1/tokuim.pf` に項目 `TOKYSN`(与信限度額、`7S 0`)を1つ足す。定義は [`solutions/10-02/tokuim-v3.pf`](tokuim-v3.pf)。
- 変更の理由: 与信限度額を超える受注を、受注一覧(`JU0300`)で見分けられるようにする。
- 変更の種類: 項目の追加。レコード様式名 `TOKUIR` とキー `TOKCD` は変えない。
- 既存のレコードにどう見えるか: `CHGPF` はデータを残したまま形だけ変える。**追加した項目の既存行の値は 0 になる**(`DFT` を書いていない数値項目。実機で、既存の6行がすべて0になることを確認した。V2、2026-09-30)。**限度額 0 を「未設定」と読むか「限度額なし」と読むかは業務の決めごと**で、模範解答の `JU0300` は「0 なら全件が限度超過になる」実装(`ju0300-credit.rpg` の冒頭コメントを参照)。

## 3. 影響調査表

「レベル・チェック」は、外部記述ファイルを F仕様書/`dcl-f`/`DCLF` で使う側がコンパイル時に様式レベル ID を焼き込む仕組みです。項目が増えると ID が変わり、再コンパイル前のプログラムは開いた時点で `CPF4131` になります。

## 4. 影響を受けないと判断したものの根拠

- **`JU0300`(変更前)**: F仕様書に `TOKUIM` が無い(`JUCHUL1` と印刷ファイルだけ)。`DSPPGMREF` の `WHFNAM = 'TOKUIM'` に出ないことを実機で確認した(`TK0100` は出た。V2、2026-09-30)。
- **SQL を使う `Q0613S`/`Q0614S`**: 列名を並べた `SELECT`/`UPDATE` で、`SELECT *` を使っていない(ソース確認)。SQL には様式レベル ID の照合が無い。
- **`TESTKIT` ほか**: コメントの中の言及。名前が同じだけで、ファイルを開いていない。

## 5. 順番とリスク

1. **先に退避する**: `CRTDUPOBJ OBJ(TOKUIM) FROMLIB(<自分のユーザー名>2) OBJTYPE(*FILE) TOLIB(<自分のユーザー名>B) NEWOBJ(TKUIMBK) DATA(*YES)`。`TOKUIL1` は DDS から作れるので退避しない。
2. `CHGPF`(`TOKUIM`)→ `TOKUIL1` の確認・再作成 → レベル・チェックの影響を受けるプログラムの再コンパイル(3-1 の順)→ `JU0300` の改修。**この順序の理由: 物理ファイルが新しくならないと、論理ファイルもプログラムも新しい様式レベル ID を取り込めないため**(05-09)。
3. 途中で止まったとき安全な状態: 退避(`TKUIMBK`)が残っていれば、いつでも 6 の手順で戻せる。**`CHGPF` の直後から再コンパイルが終わるまでは、旧プログラムが `CPF4131` になる時間帯がある**。共有の環境では、その間に利用者がいない時間を選ぶ。
4. 元に戻す方法: 論理ファイル `TOKUIL1` を `DLTF` → `TOKUIM` を `DLTF`(論理ファイルが残っていると消せない)→ 退避から `CRTDUPOBJ`(`REPLACE` が無いので先に消す)→ `TOKUIL1` を `CRTLF` → 影響を受けるプログラムを再コンパイル。**旧版のソースから再コンパイルするまで、`TOKYSN` を取り込んだプログラムは `CPF4131` になる**([移送手順書](../../docs/templates/transfer-procedure.md)の切り戻しと合わせる)。

## 6. この表で分かること・分からないこと

- 分かること: レベル・チェックが効く依存物と効かない依存物を分けたこと。`*SRVPGM` は `TXMIGR` の再コンパイルの対象外で、`DSPPGMREF` は、`OBJTYPE` を付けない実行では出さず、`OBJTYPE(*SRVPGM)` を付けた実行でだけ出すこと(V2、2026-09-30)。`JU0300` は今は関係が無いが、改修すると `TOKUIM` に依存すること。
- 分からないこと: 実行時に組み立てるコマンド文字列の参照。他のユーザーの環境にある、自分では見えないプログラム。`TOKUIL1` の再作成が本当に要るか(実機で確認する)。旧プログラムを再コンパイルせずに `LVLCHK(*NO)` で動かすと、**新しい項目の位置が読まれて、実行できても値がずれる危険がある**ので、その方法は取らない。
