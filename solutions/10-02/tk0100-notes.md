# `TK0100` に `TOKYSN` を出す(任意の読解演習の模範解答メモ)

**未検証(2026-09-30時点、5250 が必要なので実機バッチでは確認できません。V3)。** `docs/style-guide.md` の V レベルでは、コンパイルだけを確認できる部分(V1)と、画面を実際に見る部分(V3)を分けて読んでください。この演習は採点対象ではありません(採点対象は `JU0300` と `TOKUIM` だけです)。

## 何が変わるか

`TK0100`(RPG III)は `TOKUIM` を外部記述で開き、`TK0100D`(画面ファイル)の `INQFMT` に `TOKCD`/`TOKNM`/`TOKZIP`/`TOKTAN` を出しています。`TK0100D` の項目は DDS に**手書き**で、`REFFLD` で `TOKUIM` を参照していません。したがって:

- `TK0100`(プログラム)は、`TOKUIM` が変わると**再コンパイルが必須**です(様式レベル ID)。画面ファイル `TK0100D` は、`TOKUIM` が変わっただけでは再作成は要りません。
- `TOKYSN` を画面に出したいときだけ、`TK0100D` の DDS を編集して再作成し、その**後で** `TK0100` を再コンパイルします(画面ファイルの様式も、プログラムに焼き込まれるため)。順序は 画面ファイル、プログラムの順です(05-09)。

## 編集の大きさ

`src/legacy/qddssrc/tk0100d.dspf` の `INQFMT` に、`TOKTAN` の行(7行目)の次へ、次の2行を足します(桁位置は、既存の `Sales rep:` / `TOKTAN` の行に合わせてあります)。

```text
     A                                  8  2'Credit limit:'
     A            TOKYSN         7S 0O  8 16
```

1行目は見出しの文字、2行目が出力専用(`O`)の項目です。`TOKYSN` の項目定義は、**`TOKUIM` の `TOKYSN` と名前・長さ・型が同じ**でなければなりません(長さが違うと `QRG6033` になることが 04-11 で分かっています。ここでは `7S 0`)。

`TK0100`(`src/legacy/qrpgsrc/tk0100.rpg`)側は、次の1行だけを足します。**該当なしのとき(標識 50 が ON)、`CHAIN` は前回読んだ行の値を残す**ため、`TOKUPD` を 0 にしている行(`C   50                Z-ADD0         TOKUPD`)の隣に、同じ理由で `TOKYSN` も 0 に戻す行が要ります。

```text
     C   50                Z-ADD0         TOKYSN
```

(桁位置の作り方は `ju0300-credit.rpg` の追加行と同じです。ソースをコピーしてから、**必ず桁をそろえて**ください。)

## 確かめ方(V3)

1. `CRTDSPF` で `TK0100D` を作り直す。
2. `CRTRPGPGM` で `TK0100` を再コンパイルする(`CHGPF` の後で、`TOKUIM` に `TOKYSN` があること)。
3. 5250 のセッションから `TK0100` を呼び、`C00005`(与信限度額を設定した得意先)を入れる。**限度額と、該当なしのときは 0 が出ること**を目で確認する。

`TK0100` は、バッチのジョブでは表示装置を開いて応答待ちになるおそれがあるため、この教材の検証用バッチ(`verify/part10-02-tokuim`)では呼びません。
